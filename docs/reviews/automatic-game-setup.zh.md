# 地图选择后自动配置房间

现在点击地图直接进入默认单人配置，取消独立创建表单和提交步骤。玩家仍需点击开始游戏；切换模式、刷新和邀请加入都不会自动开局。

服务端部署中，单人配置由浏览器本地房间承担，地址保存地图、种子、房名和席位配置；刷新后按地址重新创建本地配置，保留种族、队伍和电脑设置，不复制用户身份或准备状态。这里恢复的是开局配置，不是运行中的比赛进度。多人模式使用真正的服务端房间及其 `?room=` 地址，邀请和刷新都进入同一个房间。

现有部署适配器按本地房间 ID 选择后端，没有就地迁移模式的接口。模式切换因此先创建目标后端房间，成功后关闭旧配置房间，再更新地址。多人配置保留至少一个可加入空位；切回单人将其他真人和空位改为电脑。静态部署只支持单人，对多人选项明确禁用并说明需要服务端版本。

`RoomSetupSession` 串行处理模式和席位修改，仅发布最新意图。已过期的创建结果会关闭；创建响应丢失也按已分配 ID 尝试清理；关闭旧房失败时关闭新房并保留旧配置。界面另外用操作令牌防止旧失败覆盖新成功。关闭期间禁止再次编辑、切换或开始。返回地图保留旧房，成功选择新地图后再关闭；浏览器前进、后退到同一配置复用原本地房间。被关闭的多人房间通过真实房间事件让访客返回列表。

定向测试共 34 项通过：房间会话 12、地址路由 6、双语文案 6、悬停光标 10。会话测试使用实际部署适配器和共享房间生命周期，覆盖首次创建中切模式、快速切换、关闭中再次切换、迟到失败、路由取消、迁移回退和模式两侧的种族修改。`tsc --noEmit` 与 `git diff --check` 通过。

完整房间验收还发现显式地图种子绕过了命名双岸地图的物理座位处理，改变联盟后预览生成抛出异常，旧控件因此一直禁用。共享创建逻辑已修正：同命名布局的种子设置继续使用固定物理座位，外交按玩家配置处理，预览与正式开局一致。客户端地图预览 7 项回归通过，覆盖不均衡联盟、自由混战、种子变化、自定义地图约束及安全缓存复用。命名地图不再要求联盟恰好均分两岸；修改联盟会复用物理预览，不重新生成同一张地形，详见 [地图预览缓存](map-preview-cache.zh.md)。

真实浏览器功能验收共 14 项通过，服务端部署 11 项、静态部署 3 项，页面错误为 0。使用原地图按钮、模式控件、席位控件和开始按钮；服务端使用实际 HTTP 和房间事件，邀请另一个浏览器用户加入并准备。验证了单人刷新、多人数值和地址切换、多人刷新同 ID、访客接收关闭事件、新地图关闭旧房、延迟服务端创建后的快速切换，以及旧创建失败不会污染新地图。验收使用 2D 回退并限制动画频率，不能据此作 FPS 或冷启动时延结论。已有完整房间与玩法验收脚本的兼容调整见 [自动房间流程与浏览验收兼容](automatic-room-ui-compatibility.zh.md)。
