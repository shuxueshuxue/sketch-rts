# 海军导航、火控、集结出口与采矿跟进

本轮针对长途航行中的绕行和停顿、同航船队与交叉船流、后排舰船不能及时参战，以及单位选择、生产出口和近矿经济继续修正。出生出口和炮位选择遵守实际身体、地形、炮弧、射程与同盟关系，不以扩大武器范围、穿越障碍或放宽既有场景断言换取通过。

## 航线与船流

长距离沿岸搜索增加可复用的水域距离启发场。距离按实际风向下的各方向推进成本计算；不同目标可以共享邻近目标区域的场，并以最终连接区域的势能修正保持保守估计。该场只决定搜索展开顺序，不批准任何移动：完整船体的格点占地、转向包络、连续扫掠和当前船流仍逐段检查。开阔水域使用积分占地场快速证明整块包络为空；搜索堆改用可增长的数值数组，减少逐节点对象分配，同分仍按状态编号决定顺序。

这些缓存只保存可重新推导的地形与几何结果，以弱引用绑定地图，并限制目标区域数量；当前航线和必要操纵状态仍随船保存。地形变化、风向变化以及 JSON 存档恢复均有冷缓存和热缓存一致性检查。

复杂船舶规划分为直接连接、参考搜索、航线细化与待采用四个阶段；每 tick 共八个确定性工作单位，直接连接与参考搜索各消耗两个，细化消耗四个，同步完整搜索消耗全部八个。多个船体可以推进小阶段，但新航线安装仍遵守原有单船体授予规则。已经获得炮位搜索资格的同一船体可以继续消耗航线的 `2 + 2 + 4` 阶段，共用原授予与八单位上限；炮位授予清除旧等待字段后，不会被其他船的等待请求阻断。下一 tick 仍按保存的首次等待 tick、再按单位编号的 UTF-16 顺序服务。取消命令、死亡和不再需要规划的请求会释放等待资格，idle 防守、返航和岸上接客仍是有效的操纵来源。独立导航调用保留同步返回契约；仿真中的炮火检查、实际舵角与推进、船体扫掠继续每 tick 执行。确定性工作单位不代表固定 CPU 用时，逐场测量见末节。

被冻结的规划输入、阶段与已经执行的逻辑搜索步数保存为 `sailing.planningJob` 字符串，等待请求与该字符串进入校验和版本 17；派生搜索图只保留在弱引用缓存中，不编码进存档。冷恢复通过原始输入重做此前逻辑步，恢复相同的搜索和候选顺序。没有船流的参考搜索每小阶段展开至多 4,096 个状态，有船流时至多 128 个；原有有船流搜索的 1,024 节点总预算保持不变，无船流的完整地形搜索仍可继续展开。冷恢复重建搜索的成本单独测量，最终采用前仍检查实时地形与船流。

首次阶段获准前，未绑定现有航段的船可以进行原允许的有限预转；实际开始时同时冻结此刻位置、航向和航速，不沿用排队前的位置。目的地在半个船长以内或要求指定朝向时，继续使用原精确参考规划，不额外引入巡航转弯圆和航线细化；这保留近距炮位和精确抵达的原选择规则。

正在航行时，只有旧航线的首段仍通过实时地形与船流检查，才在该段上选择未来规划起点。新结果若含无法接入连续航段的精确操纵或固定支点转向，会清空旧航点并删除旧航线，从当前实际位置重新建立任务；同一授予只刷新任务的最后请求 tick，不再消耗阶段额度。这样保留等待的公平性，也避免反复给不兼容航线追加未来起点，使路线持续膨胀。运输船未抵达卸载岸边且仍有规划任务或等待资格时，即使当前没有乘员，也保留卸载命令直到原完成条件成立。

浏览器从检查点恢复时，每次实际绘制更新至多重建一个此前搜索阶段，派生图重建期间保持世界 tick、JSON 状态和校验和不变，权威命令帧继续按原顺序缓冲。客户端随后每次更新最多应用四帧，并在已用 8 ms 后让出执行机会；单次搜索阶段或仿真步仍可能超过 8 ms，不能把这个检查当成硬时间上限。服务器继续存档和房间网络推进也先准备派生图，准备完成前不消费命令队列或帧序号。同步独立 API 仍按原契约一次性完成恢复，不把同步调用的重建开销藏在初始化计时外。

恢复准备只重建下一 tick 仍会使用的任务：请求已过期、已失去有效操纵来源，或下一 tick 的确定性风变会使任务失效时，跳过无用重建；世界状态的实际取消仍由原仿真步骤执行。这个准备判断不提前删除存档字段，也不改变下一步的风变、任务清理和单位状态。

[独立深岛冷恢复诊断](../../assets/naval-runtime/planning-payload-deep-island.json)使用已保存 19 个逻辑搜索阶段的检查点，参考图此前已展开 53,248 个状态；编码的参考任务仅 738 字节，不包含派生图。`869245c`、Node 20 的三次同步首个续演步为 162.477–194.528 ms；每次分 19 次准备，单次最大为 11.073–23.137 ms，准备总 CPU 为 95.297–160.627 ms，之后首个续演步为 19.435–31.593 ms。每次准备均保持权威 JSON 和校验和不变，三个冷恢复的完整结果与热运行相同，校验和均为 `97c8fe84`。原热世界的下一步测得 27.678 ms；该诊断还进行载荷解析与观测，可能触发 GC，因此这项热步数字与准备数字均不作为正式导航 CPU 基准。这个 8 秒／160 tick 诊断最多只有一个活动任务，观测到的最大细化任务为 4,320 字节，与上述 738 字节参考检查点不同，不能作为整支舰队载荷的上界。记录保留 111 项运行时与场景依赖摘要；Node 事件循环分次准备也不代替浏览器验收。

[真实 Chromium 冷恢复检查](../../assets/naval-runtime/cold-planning-restore.json)使用生产客户端、实际 `requestAnimationFrame` 与测试 Canvas 组成的恢复夹具，实际重建 53,248 个状态。18 次等待绘制均保持完整状态和校验和不变，仍绘制画面；同步首帧为 162.7 ms，分阶段客户端更新最大为 21.3 ms，包含校验断言和实际 Canvas 绘制的回调测量最大为 21.8 ms，未出现超过 50 ms 的客户端更新。客户端更新计时不含场景构造、校验断言与 Canvas 绘制，两个后续帧的完整结果与同步参考精确相等。检查还覆盖等待期间的新帧及重复帧、中途关闭和关闭后检查点，五次关闭相关更新均保持原状态；客户端与服务器回归另检查同步世代与命令帧顺序。九个直接受测运行时文件及两个脚本的摘要均未变化，无页面错误。它是 `869245c` 的恢复调度验收，不是游戏 FPS 测量；[实际绘制截图](../../assets/naval-runtime/cold-planning-restore.png)及复现浏览器脚本已纳入仓库。

32 与 64 像素地形格使用预生成的完整船体扫掠模板，其他格距仍按真实轮廓生成。搜索保留八个航向和原展开预算，复用数值堆与带世代的数组，避免逐节点对象分配；自定义船流回调嵌套调用导航时使用独立搜索空间，异常退出也能恢复外层状态。

同属方、执行普通前进命令并继续驶离的前舰不再固定成整段战略航线上的岛屿，也不把其暂时占据的终点替换成永久接触泊位。接近出发时仍保留实际操纵空间；损毁帆装、明确泊位、停止与接舷相关命令分别处理。局部舵手按前舰速度、两船长度、间距和制动能力控制跟航，不靠反复超越前舰来维持前进。

正在安全执行短距离倒车或精确操纵的船不再被每秒恢复搜索反复打断。倒车和原地转向的采用检查包含全部实时船体，不能因为后舰被普通向前战略走廊暂时过滤，就批准倒退穿过它。前进恢复遇到“前方通道可走，但附近船体不允许驶出完整转弯圆”的情况时，只有原地有限转向与后续向前航段均通过实际地形和全部船体检查，才把单个完整向前精确航段拆成有限转向与连续巡航；普通新航线、部分路线、倒车或多段精确操纵不使用此转换。每一步仍受真实转向速率和连续扫掠限制，转完立即恢复向前航行。

交叉船流中，让路舰依据两船实际外形、交叉点和对方船尾通过时间限制速度；避让状态保持承诺的世界航向，直到恢复原航向的预测走廊也已清晰。前舰正在让路时仍能被后舰识别为队列的一部分。最近接近距离（CPA）判断要求减速时，舵手使用船体实际减速度，避免将主动制动当成缓慢失去帆力而冲出转弯走廊；没有交通制动命令、仅风力下降时仍使用减速度的 0.2 倍，保留入弯惯性。两类输入各有真实船体与风场回归，检查路线对象、有限移动和实际速度变化。最终身体扫掠和物理碰撞继续检查所有活船，战略过滤不等于允许穿船。

避让中的风力判断改用舵手实际选择的通过航向。旧航线的参考点仍在逆风方向时，不再因此把已经驶上有效绕行方向的船继续压在辅助操纵速度。普通无指定朝向、无接客任务的前进命令遇到低速 idle 或 hold 船时，只有完整转向与向前走廊都通过地形和不截断距离的全船体检查，并且两段只读物理扫掠均未发现当前碰撞帧中的码头地基、岩石障碍或岸上单位，才取消额外的固定供能折扣；向前距离至少为本船长度，并覆盖当前速度与实际减速度推导的制动距离。没有提供地图的独立避让调用保留原比例，运动中的交叉舰船、迎头相遇和战斗追击保留各自避让规则。这个检查每次按当前地图和船体重做，不将“可以供能通过”的裁决保存到存档或下一 tick，也不记录碰撞、改变坐标或造成伤害。绕行边界与操舵共 49 项针对性检查通过；另在通过绕行期间进行 60 tick JSON 续演，逐 tick 校验和一致。

排队航线转角遇到风变时，能继续使用的圆角保留原走廊；已进入的有限转弯用低速辅助操纵完成，再从真实出口对新逆风航段安排抢航。转角前遇到不利风变则交回普通抢航规划。已经略过的顶点不因风变而要求倒回，命令队列依次推进，并检查存档续演与中途新命令。

只有风场变化、既有连续通道的首段仍通过实时船体与地形检查时，取消旧风下尚未完成的搜索，保留不含精确操纵、原地转向或抢航点的已验证通道，并立即按实际新风向重评推进与抢航。开阔水域的近处领舰仍计入出发扫掠，沿岸船队继续保留对驶离同航伙伴的战略过滤；实际操舵与物理扫掠仍检查全部活船。避免等待新搜索时仍朝旧航向加速，随后用更长的制动距离错过抢航出口；地形或交通阻塞仍按原实时规则处理。

## 后排炮位与真实开火条件

炮位的“可用”同时包含真实炮弧、当前装炮和老兵射程、最小射程、提前量以及炮线。低平炮弹和火焰不能穿过己方或另一玩家的同盟船体；迫击炮的高弹道按既有规则越过船体。检查使用实际旋转船体和炮口，发射前还会用炮管实际完成瞄准后的炮口再验一次，不仅判断船中心与目标距离。

后排舰选择接敌位置时检查该位置能否实际开火，避免进入被友舰遮蔽的炮位后永远等待。正在前往的友方炮位仍占用预留空间；可用炮位的延续和局部调整须同时满足船体与武器约束，不能用多次横移目标掩盖未参战的问题。

已有炮位先按当前船体、转向空间、射程、炮线和友舰预留重新验证。仍可用时继续该炮位，不消耗或重置正在等待的导航请求；需要重新遍历炮位候选时才申请本 tick 的规划资格。未获准且已有同一目标的航线时，保留其目的地、到达半径、速度上限、射击航向与倒车状态，实际前进和炮火继续使用实时安全检查。没有同一目标航线时等待首个合法炮位，只允许仍可移动的船在当 tick 剩余舵角内做连续扫掠的有限预转，定身状态禁止等待中的预转，不朝临时编出的炮位推进；运动目标的拦截不经过静止炮位搜索的调度入口。

独立审查还复现了“炮弧两个边界均被友舰遮住，但区间内部有合法炮线”的情况。火控补充有限区间内部候选，只有没有既有合法射角时才启用，保持已能开火的炮优先；接受的每个候选仍重新检查炮弧、射程和炮线。它不是每帧无界扫描整个航向圆周。

历史双纵队场景保留既有史料机制判据，并另加引擎质量要求：110 秒观察窗内，每艘进攻舰必须在最后 15 秒以前至少开火一次，即首炮不晚于 95 秒。这个时间限期是本项目的参战验收条件，没有史料给出该游戏时标，不能把一艘领舰的成功代替全部后舰支援。

追击正在航行的目标时，普通航段末端的预测拦截点是随目标更新的操纵参考，而非必须刹停的泊位。船经过这个临时点时继续保持当前航线的切向推进，并对实际这一步做完整扫掠，避免先因“到达”收掉速度、下一 tick 又重新追赶。部分航线、抢航、精确抵达和靠泊仍按各自结束条件处理；目标实际停止后也允许刹到静止炮位。目标是否正在航行由实际船舶运动状态决定，步行的岸上单位不会成为航行目标，甲板人员则先解析为承载它的船体。

[火焰舰横向拦截记录](../../assets/naval-runtime/fire-ship-interception.json)保留原 HP、武器、冷却、损伤和停船定义：90 秒场景中，停船段从 7 段降为 6 段，炮击从 15 次增至 22 次，实际伤害从 105 增至 154，所有发射均在真实射程和炮弧内。它仍有一段 8.35 秒的停止推进，期间实际造成六次命中，属于维持合法炮位的交战行为；这一段继续计入原停船指标，没有从数据中排除。25 项战斗质量、24 项追击和 29 项操舵针对性检查通过，包含临时点距离为零、目标停止、特殊航段结束和 JSON 恢复边界。该记录只支持此回归修复，不是船队整体性能或所有停船行为合理的证明。

## 选择与生产出口

Shift 加左键点击已选单位时只取消该单位，保留其余选择并修正焦点；点击未选单位仍加入选择。该规则也覆盖检查中的敌方单位、建筑与可见甲板船员。普通点击仍替换选择，Shift 框选仍添加框内单位，不把一次取消扩展成取消所有同类。

真实 `main.ts` 应用入口下，通过原生鼠标与 Shift 键分别执行 3D WebGL 和 2D Canvas 回退各 12 项检查，共 24 项通过且无错误。覆盖普通选择、加入和取消、连续 Shift 点击、敌方检查、普通与 Shift 框选，以及取消甲板船员后保留船和其他单位。3D 验证采用 SwiftShader，画面节流仅用于输入验收，不能作为设备帧率或性能测量。

选择与悬停标记改为实际地面或甲板上的标记。2D 先绘制全部地面标记，再绘制地面实体；每艘船的甲板标记位于甲板之上、桅杆和全部船员之下，避免只排在各单位自身之前仍覆盖另一单位。3D 使用同一场景内有深度测试的平面带状几何，接舷桥上的标记跟随实际桥面坡度；只有 GPU 成功绘制时才停止相应 Canvas 标记。实例、几何和材质复用，退出场景时释放。

悬浮自己的单位、盟军、敌军分别显示绿色盾形、青色连环、红色菱形光标，中立对象使用金色圆形。关系由当前玩家和队伍判断，检查敌舰不等于当前选择能攻击它。瞄准、施法、建造等操作模式优先保留各自光标；死亡、入舱和已消失的悬浮目标恢复普通光标。原生光标与锁定指针共用同一 32×32 SVG 资源和箭头尖端热点 `(4, 3)`。[悬停光标验收](unit-hover-cursor.zh.md)包含真实 2D／3D 各 12 项输入检查和锁定指针截图：原生路径核对实际样式、资源和热点，截图检查的是应用绘制的锁定指针，没有声称捕获操作系统指针像素。

悬停目标只在本次绘制中进行一次真实 3D 模型命中，命中到单位、建筑、中立营地或商店后，以这个可见对象为准；只有没有模型命中时，才调用原地面对象检查。修复了光标落在营地或商店屋顶时，却显示其后被遮挡己方单位颜色的问题，也避免同一次悬停连续做最多三次模型命中。死亡、入舱或已失效的可见 ID 不向后穿透选择别的对象。[中立对象遮挡验收](../../assets/cursors/unit-hover-neutral-occlusion.json)分别构造真实可见营地／商店和其后被遮挡的己方单位：四项浏览器检查通过且无页面错误，两个连续绘制帧各只命中一次，原生和锁定指针均保持中立图像；另有 7 项目标解析、10 项光标和 18 项关系定向检查。该记录保留修复后的源码摘要，与此前 24 项光标输入记录分开，截图只用于检查实际屋顶遮挡，没有捕获操作系统光标像素。

## 矿距与五人饱和

主基地与金矿的最小中心距从 280 降为 210，初始主矿到真实网格吸附后的基地中心距从 288 降为精确 216，均缩短 25%。搬运每趟 10 金与入矿间隔 1.5 秒保持不变；工作时间调整为 3.2 秒，使常速短矿道的循环推导仍需五名工人达到 400 金/分。五人是达到吞吐上限的最少工人数，不是硬性装入五人的矿场名额；较长矿道仍能从更多工人获益。

完整模拟完成 707 场实测，覆盖所有 54 个正式出生席位、129 处分矿、基础图、不同方向的最近合法矿道和长途矿道。全部紧凑正式矿道五人与六人均为 400 金/分，四人低于上限；每步检查矿量、工人携带和入库金钱守恒。实测找出的芦苇泽两处分矿泥地反例通过保持矿点原有经济清场干燥修复，未修改全局泥地速度或单独加速工人。推导、逐图收益、测量窗及反例修复见[缩短矿距与五人饱和采矿](mining-distance-and-saturation.zh.md)。

## AI 持续作战与 CPU 工作量

预设与 V5 混合脚本栈补入已有的绝境工人反击脚本。主基地遭多方近距进攻且既有防御不足时，工人攻击可以按原有紧急规则接管此前的建塔命令，避免建造脚本先占用工人、后续防守攻击被命令冲突过滤。已有完整主塔能覆盖战斗时仍保留正常建造，不把所有近距入侵都变成工人离岗。检查直接执行同一帧建造与攻击命令，并核对工人的最终任务，主基地无需先掉血才触发原有绝境判断。

骑射手袭矿任务不再因为矿工恰好全部处于塔下的返程阶段而立即释放。只有矿工仍执行采矿、矿中仍有金、实际入矿点与矿工同属可走陆地，并且骑射手能在该点找到塔外合法射击位置时，才保留等待下一趟暴露的任务。当前位置不安全时仍撤退或保持安全位置；整条矿道都受保护、矿耗尽或工人停止采矿时结束任务。这修复了袭矿任务短暂消失后被普通进攻脚本改成冲向主基地、吃塔伤害的问题，没有给予塔外射程或免伤。

V2 经济在所有已完成采矿基地失去有效近矿后，可以为正在工作的安全远矿存钱建设替代基地。该矿必须已有实际采矿工人、仍足以和当前库存共同支付基地，且不受附近敌军、敌方建筑或野怪控制；还必须有未被其他任务占用的工人、合法地基和可达路径。矿心周围 720 的敌建筑排除范围只是初筛：实际基地地基还要按基地半径与 `strikeGap` 检查所有有效敌建筑的射程，工人当前位置及实际地形路径的每段也必须避开其火力范围，避免矿安全却把基地或施工工人送入塔下。库存不足时保留建造预算，达到现有造价后发出真实建造命令，不直接增加金钱、生成基地或指定胜负。只缓存同一只读快照的地基与路径几何，工人任务占用、矿量和可用预算每次重新判断；返回坐标独立复制，避免调用者改坏缓存。17 项扩张与 12 项训练检查通过，包括用真实模拟证明旧地基遭塔击、安全地基完整建成，以及工人当前位置和接近路径受塔覆盖时释放预算；这些针对性结果不替代最终完整回归。

通常的施工优先选择空手且实际可达的 idle 工人，再选择超过五人饱和数量的空手矿工，减少从已饱和矿道抽走工人和中断现有载荷。仍无法施工时依次使用其他空手工人和原有工人选择，保留受限经济的推进机会。已经有超过一座完整主基地、但只有一处有效采矿基地时，施工先按原可达性与距离选择附近空手工人，仍保留原全部工人兜底；第二处收入恢复后重新按 idle 与多余矿工优先，避免远处 idle 工人在替代矿与主基地科技建筑之间反复往返，耽误替代基地完工。两种族各检查 idle 与多余矿工两种情况，实际建成重型生产建筑、保留两处各五名矿工，并检查其他施工不会重复占用同一工人及完整金钱守恒。替代矿收入按每名工人从该矿空手采集、取得新载荷再实际交付的过程观察，避免将改派前携带的旧矿黄金误算为新矿收入；营地替代矿场景的原 6,000 tick、矿塔掩护场景的原 4,000 tick 交付时限及完整金钱守恒要求均保持。

训练规划先检查能证明结果为空的实际条件：库存低于全部可训练单位的最低造价、没有已完成且生产队列空闲的建筑能够训练可支付单位，或当前单位与队列预占人口已不足最低训练人口。不能用 UI 中可能尚未更新的已用人口代替真实投影。满足购买条件时继续原有兵种、预留金钱和生产优先级计算，不改变单位费用、人口或队列规则。两种族的边界检查覆盖 74/75 金、预留后的负预算、占满及释放人口、忙碌及取消生产队列、只有更昂贵生产线，以及显示人口落后于队列预占的情况。

脚本间预算没有数值变化时复用同一经济快照，已有空间查询可继续使用；实际支出或预留改变预算时仍创建原有独立预算视图。没有离岸登陆部队时不查询全军接敌关系，没有船舶时不建立船舶防守查找表。船舶运动预算和碰撞帧容器在同一单位集合上重置后复用，清空碰撞、速度与命中记录并更新实际地图；这两项按当前数组实际检查船体，避免同长度替换、船只出生或死亡后沿用错误的“无船”结论。没有正在下令接舷的甲板人员时仍清理失去发起者的隐式接近命令，再跳过后续集合建立。

死亡与临时单位过期清理先扫描是否真的需要移除，空帧不再构造死亡数组、沉船集合和过期数组；障碍物的死亡清理继续执行。真正出现死亡时仍运行原有物品掉落、沉船乘员处理和数组移除逻辑。这些工作量优化不降低 AI 思考频率、跳过物理步进或放宽原 CPU 限期。

[五个船舶辅助模块的等价性记录](../../assets/naval-runtime/land-helper-equivalence.json)比较 600 tick 的完整可观察 JSON，包含运动预算、碰撞帧、船舶防守、规划等待请求和接舷会合。该对照中有一次实际物理接触、20 个全部船只已死亡且碰撞计数和排出结果均为零的空帧，还覆盖原数组中新船加入、JSON 恢复及甲板与船舱人员；600 步结果精确相等。码头输入在两侧同时变更，但此对照没有产生地面裁剪，也没有单独证明码头碰撞。地面／岸线、码头与障碍接触、同长度替换、隐式接近清理和实际登船转移分别由记录列出的独立回归覆盖。冻结的五个旧模块逐字节匹配 `f33904e`，其余依赖在该对照中相同；受测优化模块来自 `be1b062`，共同运行时捕获于 `02ca890`。记录提供完整输入、源码摘要和可重建驱动，只证明受测辅助模块的可观察行为等价，不扩展成最终整套源码或 AI 胜负等价、也不用于宣称 CPU 改善幅度。

移动更新中还移除了无接触时的整单位自身复制，只在碰撞约束产生新坐标时写入坐标。原 CPU 限期保持；单独替换此项优化的 48,000 tick 陆地决斗中，逐阶段状态与统计一致，均在 tick 42,144 结束，最终校验和均为 `b06d0f23`。这一独立对照避免用更早结束战斗掩盖 CPU 成本；它不是最终整套源码的性能对照。

射击评估复用同一次同步选择中的提前量、几何资格和炮线结果，不将判定留到单位已经移动的下一帧；不可变局部船体对应的炮座和边几何按弱引用复用。命中点仍按原计算顺序取最近船体表面，减少逐边临时对象和重复边长、三角函数计算。单独替换命中点计算的 600 步交战校验和、舰船状态、首炮和炮数完全一致；七种船体分别改变尺度和航向后，实际弹道仍命中表面且提前结束的弹道不误判命中。

火控继续删去能证明无法进入最终评分窗口的边界候选，并推迟其炮数评分；移动目标的边界修正、最多 48 个被遮蔽区间内部样本与 12 次内部细化保持不变。炮弧三角函数在单次调用内复用，边界输出缓存每个炮座最多 32 项，调用结束即释放；目标姿态、提前量或炮线裁决不会保存到下一 tick。静止目标与速度恰好处于 `1e-7` 分界处分别验证，避免把原本仍需预测的目标错判为静止。

[火控等价性记录](../../assets/naval-runtime/fire-heading-equivalence.json)给出冻结输入与源码摘要：763 个冷缓存、热缓存、JSON 恢复、船体尺度及不同目标速度用例的射击航向均以 `Object.is` 精确相等；原始 6 对 6 交战的 600 tick 逐步校验和、位置、航向、HP、首炮与炮数也相等。炮线查询从 27,464 次减少到 6,082 次，保留的查询是原合法查询集合的子集。查询回调是同步、只读且相同参数返回相同裁决的策略；查询顺序和次数不属于契约。这项记录验证单独替换火控计算的行为等价性，其中的诊断计时不是本轮最终发布性能对照。

同一次航向选择固定目标身体与速度后，各炮座仍完成原有离散飞行时长搜索，但相同飞行 tick 共用同一个平移后的完整目标身体；最多保留 128 个结果，调用结束即释放。不缓存下一帧的目标姿态或炮线裁决，不改变二分探测次数、48 个被遮挡区间内部样本或 12 次内部细化。[提前量身体复用等价性记录](../../assets/naval-runtime/fire-prediction-equivalence.json)单独冻结复用前后源码与相同依赖：763 项原航向用例及 1,440 项侧舷用例精确相同，600 tick 完整可观察 JSON、校验和与全部船体航向逐步精确相等，构造的预测身体从 98,944 个减到 38,063 个。该独立冻结战局的 3,000 tick 原始模拟质量字段及最终校验和 `26f89868` 也相同，平均 CPU 从 7.366 ms 降至 6.913 ms，p99 从 28.913 ms 降至 25.741 ms；它仍有两步超过 50 ms，不能代替最终导航组合的性能结果。

凸多边形扫掠几何按需计算实际访问到的支撑平面。只需要最小投影的避让和偏移调用不先计算最大投影；公开完整平面接口仍补齐原最大值，并保持缓存数组身份、运算顺序与所有边界容差。凸包以逆向索引构造上半部、复用下半部数组，保留原点顺序。[几何等价性记录](../../assets/naval-runtime/geometry-equivalence.json)对 2,976 个多边形、763,248 个平面分量、108,276 次裁剪及 763,248 个凸包坐标逐项用 `Object.is` 检查，包含先提前裁剪、再读取最小平面、偏移后才请求完整平面的顺序。八个航向、1,024 节点上限、船体采样与连续扫掠精度保持原值。

该几何记录中的交叉船流对照包含最终最小投影调用迁移，移动交战对照只包含此前的共享几何核心版本，两者源码摘要分别列出。场景质量与校验和分别一致，但其峰值仍超过 50 ms；这些独立优化计时用于定位减少的计算工作，不能代替最终组合的逐场性能测量或证明全部长帧已经消除。

船流转向扫掠复用最多 2,048 个临时顶点，超过此数量仍独立分配，不截断采样。实际进入后续裁剪的负船体另行复制，因此已保存的扫掠几何不会随下一次临时顶点复用变化；原凸包、扩张、支点转向与碰撞裁决规则保持。[独立暂存复用对照](../../assets/naval-runtime/traffic-sweep-pool-equivalence.json)将改动前模块逐字节冻结于 `594f2de`，其余依赖相同：3,024 个普通、支点及保留几何查询的裁决精确相同，包含 1,176 个通行与 1,848 个阻塞裁决，其中 336 个专门复用此前保留的零转向及有限转向几何；两侧各保留的 840 个负船体逐点以 `Object.is` 核对，后续查询后坐标仍精确不变。600 tick 完整 JSON 逐步相同，包含 tick 300 的 JSON 恢复，最终校验和均为 `79a6b8b1`。加入分配计数和保留坐标观测的同一对照仍处理 2,203,110 个顶点样本，临时顶点分配从 2,203,110 次降至 97,792 次。该记录证明受测模块和冻结场景的行为相同、临时分配减少，不是 CPU 性能测量，也不扩展成全部输入或完整运行时普遍等价。
