# 潮汐王座：战役与菜单重写

开始游戏直接进入原有地图选择窗口；上方标签切换遭遇战与战役。战役沿用地图浏览结构，显示真实地形预览、任务章节、检查点以及单人/合作入口。

## 关卡与世界

地图从 8192×8192 扩大到 24576×18432，面积 6.75 倍，八座岛屿、三个独立战区。开场超过 5000 个实际模拟单位。前线、后方基地与海上补给分开。海岸、林带、堡垒高地和港口装饰由同一地图数据驱动预览与游戏。

五个任务阶段：清除岸上袭击队并修复灯塔；护送实际粮船并登陆北岬；维持两处港口并可选营救法师；摧毁供能枢纽、解除堡垒结界并协同攻城；守住港口并护送最后一艘撤离船回家。失败条件包括统帅、基地、灯塔或关键船队失守。

六种船只包含容量 30 的远洋运兵舰；五种攻城角色和六种工事保留。敌我 AI 根据港口兵力与归属选择跨岛增援，部队使用原生登船、寻路和卸载。预备队调度消耗补给并有冷却；建设与修理持续发生。角色能力和防御建筑尚未经过全面竞技平衡，因此不能称为已证明帕累托最优。

## 本轮迭代记录

这是混合模拟演算与浏览器操作记录，不是十次人工全程通关。

|轮次|发现|修正或结果|
|---|---|---|
|1|96 像素地形格使工程兵到不了维修距离|地形改为 64 像素格|
|2|工程兵挤在同一个维修位置|六个维修站位，移动后排队修理|
|3|登陆时统帅仍在船上，被视为死亡|生命与选中逻辑识别船上人员|
|4|运输舰同点卸载导致拥堵|按船错开登陆点，按人口分配乘员|
|5|转岛选择近岸点使运输舰绕过敌方海岸|各岛使用安全登船海滩|
|6|直接攻城败于巨龙与工事|增加清晰的法师营救线索并验证支线路线|
|7|法师未随转岛队伍上船|登船优先级包含营救法师|
|8|撤退被下一条攻击指令立即打断|控制器留出休整窗口，25分58秒完整演算胜利|
|9|联军其他岛屿的胜军无法有效支援中线|跨岛 AI 增援与容量30运输舰，11分35秒完整演算胜利|
|10|浏览器中选择远征军没有立即刷新暂停时的指令栏|选择操作显式刷新 HUD；真实点击完成开场和护送登陆|
|11|主界面按钮样式漏接、地面过空、旧日志页面 CSS 残留|共用菜单按钮样式、海岸草地细笔触与林带，清理旧页面样式|
|12|4倍速按模拟 tick 推送使渲染与网络压力成倍增加|Worker按墙钟10Hz发送、合作网络5Hz发送|

完整模拟日志见 tidebound-v2-first-victory.json 和 tidebound-v2-strategic-victory.json。运行 node --import tsx scripts/tidebound-mission-playtest.ts /tmp/tide-playtest 可复现后一条路线；控制器只发普通游戏指令，没有改坐标、无敌或自动判胜。

## 合作边界

房主 Worker 是唯一权威模拟；最多八人共享远征军、经济与遗物。服务端中继完整首帧及增量帧，后来者获得完整状态；暂停时心跳保持连接。访客可发指令、招募、撤销队列和暂停；速度与存档由房主管理。房主离开会结束房间，目前不支持主机迁移，也不支持从单人检查点新建合作存档。旧版存档不会放进新版地形。
