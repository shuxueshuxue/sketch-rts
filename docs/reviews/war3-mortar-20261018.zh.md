# war3 迫击炮单发素材与发布

只替换站点默认 `war3` 包的 `mortarShot.file`。舰炮 `cannonShot` 保持 A（`08767be75a63ac43.ogg`，volume 0.8），
葡萄弹 `grapeshotShot` 保持同一个 A 文件及原来的 volume 0.7。其他音效包、运行时代码均不变。
本次提交提供处理脚本、署名及仓库外素材指针；合并不会自动激活这段声音。

[试听与舰炮 A 对比](https://lexicalmathical.com/sketch-rts/audio-packs/mortar-review-20261018/index.html)
的两个播放器初始音量均为 0.8，便于比较包内的实际相对音量；不模拟游戏里的距离、混音组或随机变化。
[单发 Ogg](https://lexicalmathical.com/sketch-rts/audio-packs/mortar-review-20261018/dbc177efbe4f569b.ogg)
也可直接播放，但浏览器直接打开文件时不会自动乘包内的 0.8。

## 来源与剪辑

- 录音：[Mortar Shots.flac](https://freesound.org/people/qubodup/sounds/184382/)，qubodup，2013-04-10，
  [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/)。作者称其摘自美国政府机构视频。
- 原始 FLAC 下载端点返回登录页，本次采用公开的
  [高质量 MP3 preview](https://cdn.freesound.org/previews/184/184382_71257-hq.mp3)，
  48 kHz、双声道、251232 字节，解码音频 12 秒（MP3 容器含编码延迟，共 12.024 秒）。
- 输入 SHA-256：`9ca9880572c1479b1ae627872dbfd3a5149b1f2d11f2e81269027fd65638c6e5`。
- 取第一发，解码时间 **0.960–3.100 秒**，成品 **2.140 秒**。发射在约 1.002 秒；
  2.8–3.0 秒尾音继续衰减，3.0–3.1 秒已回到约 −93 dBFS RMS 的底噪。
  下一发在约 4.0 秒，未包含在切片内。保留完整尾音，不加截尾淡出。
- 与 `prepare-war3.py` 一致：`loudnorm=I=-20:TP=-2:LRA=7`，32 kHz、单声道、Vorbis quality 3。
  在 A100 使用 FFmpeg 6.1.1 / libvorbis 编码。
- 文件名沿用原脚本的「源路径字符串 SHA-256 前 16 位」规则，源标识为
  `https://cdn.freesound.org/previews/184/184382_71257-hq.mp3#t=0.960,3.100`，得到 `dbc177efbe4f569b.ogg`。
  这不是文件内容哈希；`sources.json` 记录该映射。

| 成品 | 综合响度 | true peak | 包内 volume | 乘 0.8 后综合响度 |
| --- | --- | --- | --- | --- |
| 舰炮 A | −20.05 LUFS | −6.30 dBTP | 0.8 | −21.99 LUFS |
| 迫击炮单发 | −20.13 LUFS | −7.53 dBTP | 0.8 | −22.07 LUFS |

两段成品相差 0.08 LUFS。迫击炮沿用 pitch 0.025；游戏原有距离衰减与并发混音照常生效。
成品 Ogg 为 17883 字节，SHA-256：`71cff5f4c148ce80b163c243d2c640251901658d8ec0cc233cd5eb0eddc5f93e`。
试听页的 MP3 仅供浏览器兼容，游戏使用 Ogg。

## 合并并收到发布通知之后执行

以下步骤尚未发布默认包。需在有本仓库依赖、Node、Python 3、rsync 和 SSH 配置的机器执行；
复制已批准素材无需 FFmpeg。只有重新编码时才需在 mac1 或 A100 上运行 FFmpeg。

1. 取回批准素材，下载线上完整包的只读快照。使用新的工作目录；保留 `before` 供比较及回退。

   ```sh
   set -eu
   export SKETCH_MACHINES=~/.config/sketch/machines-sound.json
   bin/sketch evidence get docs/reviews/war3-mortar-20261018.evidence.json \
     --out work/war3-mortar-20261018 --on a100
   mortar_release=work/war3-mortar-release-20261019
   test ! -e "$mortar_release"
   mkdir -p "$mortar_release/before/war3"
   rsync -a -e "ssh -F $HOME/YellowPage/ssh_config" \
     alibaba-public:/opt/sketch-rts/shared/audio-packs/war3/ "$mortar_release/before/war3/"
   ```

2. 只修改 mortar 文件引用，沿用其 volume 0.8、pitch 0.025；将补丁覆盖到快照的副本上。
   `--reviewed-clip` 拒绝任何不等于已批准字节的 Ogg。**只拿三个补丁文件不够，发布校验要求完整包。**

   ```sh
   python3 tools/audio/prepare-war3-mortar.py \
     work/war3-mortar-20261018/input/184382_71257-hq.mp3 \
     "$mortar_release/before/war3" "$mortar_release/patch" \
     --reviewed-clip work/war3-mortar-20261018/stage-war3/dbc177efbe4f569b.ogg
   cp -a "$mortar_release/before/war3" "$mortar_release/war3"
   cp "$mortar_release/patch/"* "$mortar_release/war3/"
   node --import tsx tools/audio/validate-pack.ts "$mortar_release/war3"
   diff -u "$mortar_release/before/war3/extras.json" "$mortar_release/war3/extras.json" || test "$?" = 1
   ```

   应看到 23 个事件通过，以及清单仅 `mortarShot.file` 从 `08767be75a63ac43.ogg` 改为
   `dbc177efbe4f569b.ogg`。`sources.json` 增加源标识到该文件名的映射；已有映射会保留。
   如从原私有档案重建包，先跑 `prepare-war3.py`，再运行此补丁步骤。

3. 再次只读比较线上完整包，避免覆盖准备期间发生的变化。下面的 `-n` 只作比较，**不删除或写入**；
   输出非空则停止并用新快照重做。随后备份线上清单，再调用 #518 的受校验保护的发布脚本。

   ```sh
   mortar_drift=$(rsync -rcni --delete -e "ssh -F $HOME/YellowPage/ssh_config" \
     alibaba-public:/opt/sketch-rts/shared/audio-packs/war3/ "$mortar_release/before/war3/")
   test -z "$mortar_drift"
   ssh -F ~/YellowPage/ssh_config alibaba-public \
     'mkdir -p /root/sketch-sound-mortar-20261019 && cp -p /opt/sketch-rts/shared/audio-packs/war3/pack.json /opt/sketch-rts/shared/audio-packs/war3/extras.json /root/sketch-sound-mortar-20261019/'
   RSYNC_RSH="ssh -F $HOME/YellowPage/ssh_config" \
     bash tools/audio/publish-pack.sh "$mortar_release/war3" \
     alibaba-public:/opt/sketch-rts/shared/audio-packs/war3/
   ```

   发布脚本在任何上传前再用 `readSoundPack` 校验合并的 core 和 extras，失败立即退出。
   通过后先传录音，再更新清单；无须重启 Nginx 或 Node。原 A 文件保留。

4. 读取公开 `war3/extras.json` 及新 Ogg，核对文件引用和成品 SHA-256。重新加载 mac1 真实浏览器，
   运行已准备的 `/Users/mac1/work/sketch-sound-production-check-20261018/verify-production.mjs`，
   使用新的输出目录，保存 `home-fleet.png` 与 `requests-and-state.json`。
   检查 `noRejectedExtras`、`activeWar3HasRequiredEvents` 均为 true，
   `observed.activePack.sounds.mortarShot.file` 为 `dbc177efbe4f569b.ogg`，
   cannon/grapeshot 仍为 A，volume 分别为 0.8 / 0.7。主页不播放战斗音效，不把首页静音当成发布失败。
5. 需要回退时，用同一个受校验保护的脚本发布 `$mortar_release/before/war3`。
   迫击炮恢复 A；新增 Ogg 和来源映射可保留供复查。
