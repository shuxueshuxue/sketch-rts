# 模拟 CPU 预算修复审查

合并 PR #259 后，生产部署检查在 `7c8649c` 的原三地图快局测试中失败：bareDuel 进程 CPU **15,875.243 ms > 12,000 ms**，ladder **17,318.627 ms > 16,000 ms**。本轮优化保留林地弓手 83 HP、火花弓手 85 HP、指挥光环 +35% 攻速，以及原胜负、tick、CPU 预算断言；没有调整玩法参数或放宽预算。

最终源码 `1b6442f` 已通过独立 [Simulation CPU Check](https://github.com/shuxueshuxue/sketch-rts/actions/runs/38033881284)：Node 20 冷启动、单 worker、原三地图测试全部通过。中间版本 `129bc73` 和 `fa4744f` 的 CI 仍失败，这些失败记录保留。生产部署需要合并后另行确认，本页不将预合并 CI 成功写成已上线。

## 优化与行为约束

- 两坐标距离函数按 [Node 20 对应 V8 11.3 的运算顺序](https://github.com/v8/v8/blob/11.3.244/src/builtins/math.tq)计算，保留缩放和无穷大优先处理。`Object.is` 原生函数对照覆盖 NaN、±0、次正规数、极大数及 200,000 组固定种子的 binary64 输入；没有用近似距离改变范围边界。
- 地面碰撞复用分桶存储和成员关系。复用条件同时检查单位对象、源数组顺序、当前碰撞资格、各轴网格坐标；新生、移除、换对象、舱内状态或网格改变会重建。原桶和配对遍历顺序保持，每次实际碰撞仍读取当前位置、半径；缓存不保存过时的碰撞结果。工作桶引用用后清空，移除及恢复路径清理成员引用，缓存以游戏对象的弱引用管理。
- 空间和阵营索引同样检查对象、顺序及单独的网格坐标；owner 或 team 映射改变会使阵营索引失效。AI 的建筑查询返回新的数组，评分缓存限定于一次排序，压力计算限定于一次规划；重复纯查询、无需使用的候选过滤和分配被减少，比较器、稳定平局及命令顺序保持。

## 实际对照

诊断在导入源码前锁定提交、干净工作区、源码清单和驱动摘要；两次均为 Node `v20.20.2`、bareDuel、V2、36,000 tick。基线 `7c8649c` 清单含 449 文件；最终 `1b6442f` 含 450 文件，新增 `src/shared/hypot.ts` 已计入。清单包含 `src` 内 git 跟踪的 `.ts`／`.json` 非测试文件，是保守输入记录，不表示全部文件都执行过。

这组单次诊断 CPU 下降 **11.10%**，包含采样与摘要计算，不能视为重复统计或 CI 的 CPU 实测值。最后一批与 `fa4744f` 的 9,915.895 ms 相比没有显示可归因的增益，不能单独宣称显著加速。

61 个检查点是初始状态及每 600 tick 的状态，游戏和 AI 状态保留精确 JSON 数值、数组顺序，命令链汇总实际发出的命令。所有检查点、命令链及最终联合状态 SHA-256 均相同，最终联合摘要为 `89e2869c30426db96b6e421a357a4fc49b48554257a5f1a7a9c9d4851ef721f1`。这是本次 bareDuel 对照的精确一致性证据，不能推广为所有地图、所有对局逐 tick 均已证明相同；该诊断到 36,000 tick 尚无胜者，未人为缩短对局。
