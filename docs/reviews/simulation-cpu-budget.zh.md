## 优化与行为约束

- 两坐标距离按 [Node 20 对应 V8 11.3 的运算顺序](https://github.com/v8/v8/blob/11.3.244/src/builtins/math.tq)计算，保留缩放、无穷大优先、NaN 与有符号零处理。原生 `Object.is` 对照覆盖 200,000 组固定种子的 binary64 输入，没有用近似距离修改范围边界。
- 地面碰撞复用分桶及成员关系，严格检查对象、源序、碰撞资格和两轴格号。私有查找表按桶数预留空位，桶数组保留首遇顺序；保留原数值键别名与 SameValueZero，移除和重建清除旧单位引用。实际碰撞读取实时坐标与半径，桶和配对顺序不变；移除和恢复路径清理缓存引用，缓存由游戏对象弱引用管理。工作桶持有当前成员，成员变动时重新建立。
- 空间索引检查对象、源序和网格；阵营索引额外检查 owner/team。重建只转移私有元数据数组，旧公开桶保持独立，旧索引重新使用时必须重建。静止瞄准、空光环帧和相同目标自动攻击减少无效工作。
- 严格无海军状态的帧跳过船舶处理链。旧 cargo、甲板、船舱、栈桥、航行及上下船指令走完整路径；出生和 ferry 会重新开启尾部处理，碰撞帧重置始终执行。自定义出生函数和观察者保留完整处理，公开船舱 helper 的隐藏移动额度也继续生效。
- SDK 查询保留源序与公开结果的独立性；AI 延后未使用的候选查询，空指令跳过记账但仍运行脚本及其记忆修改。网络只读 tick 不再复制全世界，实际帧、检查点、延迟指令、恢复和终局处理保持。
