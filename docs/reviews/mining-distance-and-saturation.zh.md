# 缩短矿距与五人饱和采矿

普通主基地对金矿的最小中心距从 280 改为 210；初始矿点从真实、吸附网格后的主基地中心起算，距离从 288 改为精确 216，两者均缩短 25%。矿体、建筑地基和工人通道的其它碰撞规则继续生效。15 张正式地图的 54 个主矿，以及 129 处分矿，仍通过完整基地地基、四周工人通道和实际矿道审计；小岛基地空间没有缩小。

每次带回 10 金、入矿间隔 1.5 秒保持不变，每矿收入上限仍是 `10 / 1.5 * 60 = 400 金/分`。缩短矿道减少了往返时间，因此工作时间从 0.8 秒增加到 3.2 秒。以工人速度 60、入矿距离 44、交付距离 74 推算，216 的常速短矿道无排队循环为：

```text
C = gather + 2 * (distance - entryRange - dropRange) / workerSpeed
  = 3.2 + 2 * (216 - 44 - 74) / 60 ≈ 6.47 秒
N = ceil(C / entryInterval) = ceil(6.47 / 1.5) = 5
```

旧 288 矿道的理论循环同样为约 6.47 秒，所以没有顺便抬高总体经济速度。实际引擎还包含 20 Hz 离散计时、建筑占地、道路形状和矿口排队；以下结果使用完整模拟和实际交付金钱验证，并不把五写成矿场的工人准入上限。现有 `workstations` 仅供 AI 默认工人预算使用，第六至第八名工人仍能入矿、携带和交付。

“五人最优”在这里指**达到矿场吞吐上限所需的最少工人数**，不是每名工人的收益最高，也不是任意距离或地形都必须只派五人。

## 实测

统一预热 60 秒，再观察 180 秒。没有 AI 或战斗干扰；视为已经清除守矿部队，但保留正式地图的地形、矿点、建筑和障碍物。分矿基地使用 `miningHallSite` 搜出的普通合法位置，完成建造后才计稳态收入，建造成本与时间不包含在吞吐率中。

- 16 张图（基础决斗加 15 张正式地图）各 1–8 人，128 场；五人均为 400 金/分。
- 所有 54 个正式出生席位加基础图两席，各 4/5/6 人，168 场；五人与六人均为 400，四人 323.33–363.33 金/分。
- 所有 129 处分矿最近合法基地各 4/5/6 人，387 场；基地中心距 210.02–213.69，五人与六人均为 400，四人 336.67–366.67 金/分。
- 最近合法 210 矿道的轴向、45°方向，以及 600 长途矿道各 1–8 人，24 场。210 的四人 376.67，五至八人均为 400；600 的五人 160、八人 250，额外工人仍能改善真实长途运输。
- 全部 707 场的每个观察步，都满足 `剩余矿量 + 工人携带 + 已入库金钱 = 初始矿量`。180 秒观察窗的单次交付分辨率为 3.33 金/分。

## 修复实测反例

芦苇泽最初有两处分矿：最近基地虽然只有 210.12 距离，矿道却几乎全在速度系数 0.6 的泥地上。五人只有 326.67，六人 393.33 金/分，违反了紧凑矿道的经济目标。

地图生成现在让矿点原有的 230 半径经济清场保持干燥（主矿已有 150 半径保护及高台）。清场原本已排除树林、石头和浅水；此次仅补足其中的泥地规则，矿场之外的泥地和泥路仍保留。改完后这两处分矿四人 353.33、五人与六人 400。实际芦苇泽短矿道的常速和剩余泥地均有回归断言，没有更改泥地的全局速度或给工人特殊加速。
