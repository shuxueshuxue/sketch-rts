# 实时 3D 战船海试

试玩：[独立海试场景](https://lexicalmathical.com/sketch-rts/audio-packs/ship-webgl-20261007/index.html)。

这是独立的渲染原型，正式游戏仍使用已有的 Canvas 渲染。场景只包含一艘战船、两名甲板船员和一个岸上靶标。按钮与右键操作下达真实游戏指令，航行、甲板路径、火炮转向、瞄准、弹道与伤害全部沿用共享模拟。

## 模型与渲染

- 从已有的 Blender 战船模型导出 GLB，静态船体与可转动火炮分别合并成 `Hull`、`Gun` 两个组件。模型保留模拟使用的尺寸和炮座原点，导出时转换成 glTF 的 Y 轴向上坐标。
- GLB 为 377,744 字节、6,201 个三角形、两个网格、七种材质。导出脚本可重复生成，无须手改二进制模型。
- Three.js 使用正交相机和真实阴影贴图。船员使用带透明裁切的竖直平面网格，与船体共享深度测试；直接绘制人物，不复制原有的地面椭圆阴影。
- 船体读取模拟朝向并插值显示，火炮读取各自的炮座与朝向。船员的动画和位移读取甲板局部坐标，船体航行本身不触发行走动画。
- 2D 对照读取同一个模拟。性能面板分别显示当前模式的帧间隔、CPU 渲染和模拟耗时；它不等同于 GPU 耗时测量。

## 本地生成

先按 `tools/art/build-ships.py` 的流程生成 `.art-build/ships/warship.blend`，再执行：

```sh
blender --background --python tools/art/export-ship-gltf.py
npm run preview:ship-3d -- .art-build/ship-webgl-preview
```

将输出目录通过 HTTP 提供访问。2D 对照的贴图使用已有的 `/sketch-rts/art/` 路径；实时 3D 模型随预览目录一同输出。

## 已验证与待验收

已通过模型结构和坐标测试、真实甲板移动与持续瞄准炮击测试、TypeScript 检查、生产构建与独立预览构建。浏览器中已确认 2D 对照运行、指令生效且靶标受到伤害。

当前云浏览器报告 WebGL 被禁用，无法创建渲染上下文；因此实时 3D 的实际观感、船体与船员遮挡、阴影和帧率尚未完成 GPU 验收。预览遇到这种情况会明确显示原因并运行 2D 对照。不能把对照画面或对照帧率作为 3D 验收结果。

下一步是在可用 WebGL2 的浏览器中检查炮座位置、转向、船员遮挡与阴影，再测同一场景的 2D/3D 耗时。在这些检查完成前，原型保留在独立入口，不切换正式游戏的渲染器，也不扩展为全建筑迁移。

## 船员颜色补修

人物纹理使用与 2D 渲染相同的阵营色，缓存按阵营色区分，左朝向也与 2D 一致进行镜像。人物卡片使用直接显示贴图颜色的基础材质，并排除船体使用的色调映射；画好的明暗与衣料颜色不再被平面法线、船帆投影和镜头方向再次压暗。保留透明裁切、真实深度及向甲板投射的轮廓阴影。

检查了农民与步兵实际生成的透明纹理，两者均包含肤色、衣料色、阵营色和暗色线条；TypeScript、独立预览构建及两项海试模拟测试通过。此检查不能替代实时 GPU 画面验收，云浏览器的 WebGL 限制仍然存在。

人物贴片改为竖直站立，仅绕竖直轴朝向镜头。原实现复制相机的俯仰角，会把人物头部移到脚下位置的侧后方，甚至倾斜穿过船帆，导致误遮挡。脚底固定在实际甲板点，继续使用真实深度，不通过强行置顶绕开帆的遮挡。

走动朝向由甲板局部位移驱动，并根据船体朝向和当前观察角度投影成左右朝向；船体位移不触发人物转身。攻击目标优先，停下后保持朝向，微小位移保留迟滞。新增绕船观察按钮，每次转动 45°，供检查不同角度的真实遮挡。

新增数学回归：八个观察方向下头部保持在脚上方、船帆前后真实射线遮挡、实际甲板走动反向与船体位移独立。这三项 CPU 检查不代表实际 GPU 画面已验收。
