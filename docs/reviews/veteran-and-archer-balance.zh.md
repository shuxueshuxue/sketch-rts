# 三星技能与弓箭手耐久调整

三星本身只增加生命，不增加武器伤害；学到的唯一技能需要带来可以察觉的战斗职责。原攻速光环只有 8%，两个战斗主动技能持续 6 秒／冷却 24 秒，治疗波每人只有 30，使升到三星后的小收益不够明显。本轮提高实际收益、同步中英说明，保留学习资格、三选一、范围与五目标上限；测距训练已有跨越塔与舰炮火力边界的价值，保持原 10% 射程。

| --- | --- | --- |
| 百战之躯 | 自身减伤 12% | 25% |
| 迅捷行动 | 自身移速 +10% | +30% |
| 协同作战 | 攻速光环 +8% | **+35%** |
| 警戒互助 | 减伤光环 8% | 18% |

| 坚守阵线 | 减伤光环 12% | 25%，仍为更小的 130 范围 |
| 沉着瞄准 | 瞄准速度 +30% | 瞄准 +80%，自身攻速 +20% |

| 坚韧恢复 | 自身恢复 3 生命／秒 | 6 生命／秒 |

团队光环同属性仍只取最强值。战斗号令与嗜血共用临时攻速层，只取最强值，号令结束后仍在持续的嗜血恢复生效；它与协同光环独立相乘为 `1.6 × 1.35 = 2.16`。若受益射手自身选择沉着瞄准，再有另两名老兵提供光环与号令，三层峰值为 `1.2 × 1.35 × 1.6 = 2.592`，受号令八秒窗口限制。多名指挥单位不会重复乘上光环。减伤的个人／光环／短时防护分别乘算，同组仍取最高；机械单位不接受医疗，入舱不能继续向外提供光环。沉着瞄准增加站定射击频率，也提升首发和转靶的准备速度，移动限制仍保留。

治疗波满额恢复 `90 × 5 = 450`，理论总治疗上限为 `450 ÷ 18 = 25` 生命／秒。自动施放通常要求有效总治疗达到 90；危急目标低于或等于 40% 生命且缺血达到 `min(45, 最大生命 × 25%)` 时允许救急。这个门槛随小生命池适配，治疗量提高后不会反而拒绝救治生命上限小于 90 的单位。原基础治疗保持单体 55／12 秒的独立冷却。

## Warcraft III 参照

实际读取 Blizzard Classic 官方指南的 [耐久光环](https://classic.battle.net/war3/orc/units/taurenchieftain.shtml#taurenchieftain-endurance)、[专注光环](https://classic.battle.net/war3/human/units/paladin.shtml#paladin-devotion)、[邪恶光环](https://classic.battle.net/war3/undead/units/deathknight.shtml#deathknight-unholyaura) 和 [治疗波](https://classic.battle.net/war3/orc/units/shadowhunter.shtml#shadowhunter-healingwave)。这些三级技能要求英雄达到五级，体现持续团队增益、前排保护、机动恢复和及时抬血的分工。

官网存档的三级耐久光环为移速 +30%、攻速 +15%；专注为护甲 +4.5，邪恶为移速 +30%／每秒 1.5 生命，治疗波首段 300、后续递减、9 秒冷却。35% 攻速是用户指定的本作参数。没有直接复制另一游戏的生命、护甲或距离标度；这些页面未标明补丁，作为 Classic 存档资料引用。[来源与三级原表摘录](../../assets/balance/warcraft-rank-three-reference.json)记录访问时间与实际 HTML 摘要。

## 两族弓箭手

林地弓箭手为 83 生命、115 金、13 伤害、319.2 射程、1.5 秒攻击间隔；烬火火花弓手原为 75 生命、110 金、9 伤害、288 射程、1.35 秒间隔。两者人口均为 2，火花另有更快的移动、瞄准和概率火地效果。短射程导致火花更容易受伤，原 75 生命又恰好比普通弓手少承受一次 16／20 点近战命中。

火花基础生命调整为 **85**，林地保持 **83**；价格、伤害、射程和火地概率保持原值。零星、无科技时，两者都需六次 16 点步兵命中或五次 20 点 `emberRavager` 命中才死亡，修复原五次／四次的脆弱门槛。健康科技和星级依然从各自基础生命推导，不引入额外种族补正。

16 场共享模拟单挑覆盖火花旧／新生命、240／310 两种距离、四组确定性单位 ID。普通弓手保持全部胜出，火花提高生命后将胜者平均残血从 24.25／28.25 降至 13.75／17，交战延长约 1.5 秒。此探针只反映这些无人工微操、无科技的单挑场景，正常接近目标与概率火地仍在运行；火地在多人阵形中有额外价值。[原始记录](../../assets/balance/archer-durability-review.json)保留具体场景和输入摘要。

## 耐久变化暴露的 AI 回归

全量回归发现默认 V2 在 `verdantCrossroads` 的双 AI 对局到 48,000 tick 仍无赢家，而同场景主线 `03c5318` 能正常结束。使用相同模拟、AI 和地图分别还原生命与技能，定位到生命变化导致的不同战斗轨迹：

| 对照输入 | 48,000 tick 上限内结果 |
| --- | --- |
| 新技能、火花生命 85 | 未结束 |
| 原技能、火花生命 85 | 未结束 |
| 新技能、火花生命 75 | 林地在 tick 16,050 获胜 |
| 原技能、火花生命 75 | 林地在 tick 16,050 获胜 |

85 生命场景中，烬火末尾仍有六名农民、八名作战单位和两座基地，其前线小队在劣势撤退与进攻之间反复切换。原 V2 小规模战斗脚本用朝己方基地的攻击移动表示退却，而记忆记录只保护普通移动撤退，导致下一轮进攻规划再次争用这些单位；攻击移动还会追击撤离的敌人，违背退却目的。

纯 V2 现在保护这两种退却命令的记忆：轻度劣势时保留攻击移动，继续还击；敌军战力超过自身 1.5 倍，或敌人确实向外移动时，改用带 `avoidCombat` 的普通移动脱离。仍锁定交战目标的攻击移动不算逃离。健康陆军朝安全方向在 600 以内选取目标，再投影到实际单位所在的同岸可达位置，途中复用固定目标；抵达安全点后允许重新参战，仍检查驻停／距移动目标不超过 110，且 420 内没有敌军或野怪，新援仍可独立向前。原重伤恢复与舰船退却目的地保持现有规则，其他明确请求的 AI 版本保留原有行为。

真实脚本、命令和模拟场景覆盖存活敌人下的退离、严重劣势、途中保护、新援推进、固定目标、到达安全位置后的重新进攻、撤退记忆过期与同岸可达性。同一份 15 场景在修复前失败 9 个，修复后全部通过；原问题地图的诊断对局在 tick 17,069 正常结束。三张地图原有快局测试通过，胜负、tick 和 CPU 上限断言保留；生产部署也加入同一组三地图检查。[AI 对照与修复记录](../../assets/balance/ai-durability-regression.json)保留消融输入、实际命令冲突、运行版本和源码摘要；诊断观察器耗时与原快局 CPU 检查分别记录。

## CPU 与分配优化

耐久变化使无营地对局出现更大的存活军队，冷启动检查首先暴露 CPU 超限。保持原战斗输入和预算，减少完整 AI 玩家视图的反复数组拷贝、陆军武器查询的临时列表、技能冷却及采矿的中间数组；单位空间索引仅在成员引用、顺序、长度和两轴格号全部不变时复用，范围检查仍读取当前坐标。满血单位跳过回血查询，无佣兵营地跳过雇佣决策，同次收尾规划按队伍复用守军计数。跨格、同 ID 原位替换、训练出生、存档恢复、满血后再次受伤、机械筛选和同盟守军 4／5 人边界都有实际场景回归。

优化前 `6408259` 与优化后 `38adfdb` 在相同 Node 20、生产挂载路径、默认 V2 和 `bareDuel` 输入下各运行 36,000 tick。每 600 tick 采样一次，包含初始状态，共 **61 组**官方 checksum、不舍入的 JSON 游戏状态摘要、AI 状态摘要，以及全部实际发出命令的滚动摘要，逐组完全一致，最终游戏与 AI 合并状态也一致。单位累计存活 tick 为 1,872,729、峰值 73、实际命令数 2,950，优化没有靠减少模拟单位或提前结束对局降低耗时。

这组单次诊断的进程 CPU 为 **12,209.387→11,332.899 毫秒，下降 7.18%**，包含采样与摘要计算，不能当作多次统计或部署 CPU 断言。部署检查另用原快局测试，三张地图的 12,000／16,000 毫秒 CPU 上限保持并通过。[分配优化对照记录](../../assets/balance/simulation-allocation-review.json)保存导入前锁定的运行提交、449 份源码清单摘要、变更文件摘要、驱动摘要和每组状态核对；历史武器与 AI 诊断保留各自实际运行的提交，不重标为当前版本。
