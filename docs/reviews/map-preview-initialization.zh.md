# 地图预览初始化开销

地图详情缓存未命中时仍生成真正的比赛初始世界，再绘制地图与出生席位。没有缩减地形、资源、野怪、联盟、席位或地图校验，也没有把同步工作移到其它页面。

## 根因与修复

`pineshade` 使用 `room-flow-config-seed` 时，单独 `generateMap` 约需 506–516ms；`createGame` 约需 501–574ms，`snapshotGame` 只需 0.07–0.69ms。因此，绕开游戏快照无法解决这次长任务。独立 CPU 采样的主要开销是地形生成器多次检查完整四向连通性：每个访问格创建四对邻格数组，`whole` 还把全部已访问格复制到另一个数组。

生成器改用每个 `Grid` 独有的 `GridFlood` 工作区，复用定长队列和可达位图，直接访问固定的右、左、下、上邻格。`whole` 使用完整遍历计数，不再复制访问列表。岛屿、障碍物及全部地形验证继续执行，随机数使用与遍历顺序保持原样。

当前 predicate 仅访问地形数组，不会重入；helper 仍为嵌套 predicate 分配独立临时工作区，并在异常后释放占用。返回位图只在下一次遍历前有效，现有四种生成器消费者均在该期限内消费。海港校验保存多个独立位图的 `seaCells` 没有改成共享工作区。

地图预览继续使用原始 `createGame` 入口，缓存上限仍为 24，地图 ID、席位顺序、联盟及自定义种子组成的缓存键保持原样。

## 一致性检查

改动前保存原始输出，改动后对 18 个案例重新生成并比较完整序列化内容：全部 15 张正式地图、54 个出生席位，以及三个自定义松影林种子。比较包含完整初始快照、地形全部字段、资源、物品、野怪、玩家颜色、预览标记、所有实体的可行走判定，以及每座主基地到所有实体的地面连通性。

前后均为 2,906,520 bytes，SHA-256 均为：

`e4b4cba7f34620f25a2b2b665a66c5d2051c6f8a03e735ea19b53e595014416c`

全部地图已有的固定布局 hash 检查通过。定向测试还覆盖固定访问顺序、四向隔离、不跨行、起点原语义、被拒绝格的再次检测、工作区复用、嵌套及异常恢复；原有 seed 一致性和障碍物周边连通性测试通过。

## 耗时观察与复现

独立 Node 冷进程单次对照中，相同自定义松影林的完整 `createGame` 调用从 **631.7ms 降至 419.7ms**，减少约 33.6%；快照复制两侧均小于 0.5ms。模块解析、TS 转译和初始化调用分开计时，这个比例仅比较真正的初始化调用。原先较晚运行的案例从 507.8ms 降至 340.8ms。此处是小样本诊断，真实浏览器长任务仍需以同一查询、同一预算验证。
