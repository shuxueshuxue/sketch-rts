# 正式世界渲染与资源载入

建筑和六种船只使用实时 GLB 模型；人物仍采用原有画风，绘制到带透明裁切的直立卡片上。地形由 Canvas 绘制，实体共享 WebGL 深度，选框、血条、命令反馈等由前景 Canvas 绘制。没有 WebGL2 或图形上下文失败时保留完整的 Canvas 路径。

## 坐标与职责

- 模拟拥有地图位置、船体朝向、甲板位置、武器炮口、弹道与伤害。渲染只读取快照。
- 地图 `(x, y)` 对应 GPU `(x, elevation, y)`。导出时将 Blender 的纵向反射并烘焙，修正面绕序；运行时实例没有负缩放。
- 正交相机补偿俯视角，地面投影与原地图完全一致。人物保持竖直，足点落在实际甲板高度；船帆、炮和人物接受同一深度判定。
- 选取使用模型射线及人物透明像素；甲板命令将屏幕点反投影到甲板平面。框选使用显示出来的人物位置。
- 船体与挂载武器独立实例化，使用模拟中的炮位、朝向和损坏状态。船体没有额外瞄准系统。弹丸外观由发射时保存的攻击类型决定，停止收到快照时最多插值一步，不提前越过命中时刻。
- 同种模型、材质、队色和人物姿态合并为实例；人物纹理按使用情况淘汰。模型、材质和实例对象可释放。

## 分阶段载入

`bootstrap.ts` 先显示小型载入页，再根据构建时生成的 `resource-manifest.json` 读取界面代码、样式和字体。首页只准备当前场景；切换场景时准备该场景。点击开始比赛或进入正在进行的房间后，再准备所有对局模型、头像和常用作战音效，完成后才创建或连接对局。

进度来自响应流的实际字节数。模型和图片带内容版本，目录和音效清单重新验证；未知大小明确标为待确认。单次最多四个请求，同一资源跨阶段共享下载和解码结果。记录页显示大小、耗时、已复用大小及失败项，主页和对局菜单均可打开。这里的大小是解压后的资源读取大小，包含浏览器缓存，不代表本次压缩网络流量。

重试保持原始启动或开局调用等待，资源准备成功才继续。不会出现重试载完后无法开局的半启动状态。

GLB 共 31 个，未压缩文件总大小 2,709,780 字节；船只 UI 头像约 309 KiB，不会为一个按钮载入多方向船体图集。WebGL 模块单独分包，无法创建 WebGL2 的设备不下载 Three.js。Canvas 回退会在对应阶段准备旧图集。

## 重建与验证

1. `SKETCH_SHIP_MODELS_ONLY=1 python3 tools/art/build-ships.py --blender <Blender>` 生成六种可编辑船体。
2. `node --import tsx tools/art/export-building-geometry.ts` 导出建筑面数据。
3. 在 Blender 后台运行 `tools/art/export-world-gltf.py`，输出 `public/art/world3d/`。
4. `node --import tsx tools/art/build-ship-portraits.ts` 更新一致的船只头像。
5. Vite 构建自动生成资源大小与内容版本目录。

新增验证覆盖所有真实 GLB、相机投影与甲板反投影、透明像素选取、人物颜色材质、实例合并、弹种区分、延迟快照、流式字节进度、并发队列与重试。CPU 场景测试只替换 WebGLRenderer，仍使用真实模型、材质、相机、射线和人物绘制；这不是 GPU 画面或 GPU 性能验收。当前云浏览器禁用 WebGL，浏览器实测覆盖正式载入和 Canvas 回退。GPU 画面仍需在提供 WebGL2 的设备上验收。
