# 甲板与航行的数学模型

本模型只处理几何、连续运动与可支撑性。攻击、所有权、装备操作和 AI 战术使用它的结果，不进入几何判定。时间参数仍以秒设定。

## 人物占地与可支撑区域

人物身体是半径为 `r` 的圆盘 `B(r)`；搬运物品改变质量与速度，不改变身体半径。碰撞安全余量单独加入 `r`，不通过放大模型表达。

单船可用甲板是凸多边形 `P`，来自船体建模数据。中心允许的位置为：

\[
E = P \ominus B(r)
\]

每条逆时针边对应向内半平面 `n·x ≥ c`；圆盘能放入甲板，当且仅当每条边满足 `n·x ≥ c + r|n|`。凸集合中两个有效端点之间的整条直线也有效，因此不需要沿线每隔几像素取样。

跨船或跨岸时，支撑面变为接触船体轮廓与可行走陆地格的并集 `F`。内部重叠边和共用接缝必须消掉，只保留并集的外边界。船体接触允许总共 0.5 世界单位的数值余量，不能跨过真实水缝。可步行连接还须满足船体接触和甲板高度差条件。

人物中心从 `a` 走到 `b` 时，其扫掠区域是胶囊：

\[
C = [a,b] \oplus B(r)
\]

路径安全要求 `C ⊆ F`：两个端点在支撑面内，中心线与每条外边界的距离至少为 `r`。这同时检查窄水缝、内凹转角和陆地孔洞。不能只检查起点、终点，也不能将多船并集误当成一个凸包。

桅杆、炮位和其他人物采用圆形障碍。障碍中心 `o`、半径 `s` 与整条中心线的最短距离必须不小于 `r+s`。对于接触解算留下的已有轻微人物重叠，仅允许距离单调增大的离开动作；不能因此进入另一处重叠。

实现位于 `navigation-math.ts`、`support-surface.ts`、`decks.ts` 与 `connected-decks.ts`。路径选择使用局部可见图；几何检查是连续的，图的候选绕行点仍是离散的，不声称穷尽所有可能路径。

## 船体占地与连续扫掠

船的状态是 `q=(x,y,θ)`，占地是 `H(q)=R(θ)H₀+(x,y)`，其中 `H₀` 为建模导出的凸船体。船能停放，要求整个船体都在可航行水域内；船心在水中不足以证明这一点。

平移的扫掠区域是起点与终点船体的凸包。转动需要覆盖中间角度：对于一个角度区间 `Δθ`，距离船心不超过 `R` 的顶点与其线性插值的偏差上界为：

\[
e \le R(\Delta\theta)^2/8
\]

因此，将两端船体的凸包向外扩张 `e`，得到包含整个中间转动的保守包络。分段限制船尖弧长不超过 2 世界单位以控制这个包络的保守量；这不是每秒推进的单位，也不替代连续覆盖。包络与阻塞格通过分离轴判定，海岸不能从两个有效端点之间穿过船体。

航路图保留原地形格精度，每格有八个朝向，并提供前进、后退、侧向泊岸和转向连接。各船型的船体姿态与连接扫掠足迹仅依赖几何，可以预生成占格模板；地形改变时，地图上的可用连接缓存失效。模板不会扩大地形格，也不会忽略船尾。

完整包络的包围盒若全是水，可由水域积分场在常数时间证明安全；否则进入详细几何判定。首尾离网格的连接仍使用实际姿态的连续扫掠。

## 计算量与状态边界

旧路径检查将候选点对、路径采样点、全图人物与多边形边叠在一起。新模型将路径采样移除，使用局部障碍、可复用的静态足迹与代价剪枝。寻路数组按搜索代号复用，避免每次命令清空整张地图；同一次起点转向只计算一次。

AI 的船坞岸线候选来自矩形占地查询。干地、足够大的连通水域、阻塞格分别建立积分场，每个候选用三次矩形计数判断，不再为全图每格重新扫描建筑占地。

几何缓存都可重新计算，不进入存档。船正在执行的航路进入存档；缓存冷暖不能改变指令顺序、路径判定或回放结果。性能统计分别记录冷启动、模拟推进、AI 决策及最慢帧；平均耗时不能替代最慢帧。

## 验证边界

回归场景包含相邻与重叠甲板、薄水缝、内凹区域、岸线孔洞、真实身体半径、已有重叠的撤离、窄航道、靠岸转向、横穿障碍的平移、地形变化与存档回放。预生成足迹需覆盖全部船型、朝向、转向与泊岸连接的中间姿态。

长局压测使用产品的指令帧运行时与 V5/V7/V8 的实际 AI 调度，同时记录最坏耗时、P99、超过时间预算的帧数和实体数量。测试机上的结果不能直接当成所有玩家设备的帧率保证。

## 相关研究与采用范围

这些问题属于计算几何与运动规划，不需要依赖学习型 AI 才能求解。下面区分已有实现、适合后续采用的算法，以及不能直接套用的假设。

| 资料 | 对应问题 | 本项目中的使用边界 |
| --- | --- | --- |
| Steven M. LaValle, *Planning Algorithms*, 2006，[配置空间障碍，第 4.3.2 节](https://msl.cs.uiuc.edu/planning/node161.html) | 将有限体积物体的碰撞转换为中心位置的可行域 | 当前圆盘净空、障碍膨胀和扫掠判定采用同一建模思路。本文 `P ⊖ B(r)` 表示形态学侵蚀；LaValle 该节的 Minkowski difference 表示点对相减，两者符号相同但定义不同，不能混用。 |
| Marcelo Kallmann, *Navigation Queries from Triangular Meshes*, MIG 2010，[作者论文 PDF](https://mkallmann.github.io/papers/10-mig-navq.pdf) | 不同半径的单位能否通过狭窄通道；带净空的导航网格与 funnel 路径 | 最适合进一步替换甲板的离散候选可见图。普通三角网格只测入口宽度还不够，LCT 要细化网格并验证三角形内部的转弯净空。当前没有实现完整 LCT，也没有其通道搜索保证。 |
| Dmitri Dolgov et al., *Practical Search Techniques in Path Planning for Autonomous Driving*, STAIR 2008，[作者论文 PDF](https://ai.stanford.edu/~ddolgov/papers/dolgov_gpp_stair08.pdf) | 需要朝向和转弯约束的刚体航路 | 当前船路是八朝向的状态格搜索，不是完整 Hybrid A*。可借鉴运动原语、几何启发式预计算和路径平滑，但汽车的曲率、倒车与非完整约束不能直接当作船的动力学。 |
| Min Tang, Dinesh Manocha, Young J. Kim, *Hierarchical and Controlled Advancement for Continuous Collision Detection of Rigid and Articulated Models*, TVCG 2014，[作者机构记录与 DOI](https://pure.ewha.ac.kr/en/publications/hierarchical-and-controlled-advancement-for-continuous-collision-/) | 快速运动或旋转的刚体在两帧之间是否碰撞 | 连续检测方向吻合；当前采用有误差上界的保守扫掠包络，不是论文中的 conservative advancement。后者需要距离查询与运动界，值得作为比较实现，不应仅靠名称替换现有判定。 |
| Jur van den Berg et al., *Reciprocal n-body collision avoidance*, ISRR / Robotics Research 2011，[作者 ORCA 项目](https://gamma.cs.unc.edu/ORCA/)与 [RVO2 实现](https://gamma.cs.unc.edu/RVO2/) | 大量人物在局部互相避让 | 适合甲板拥挤时选择局部速度，不解决船与岸的连通性或全局绕路。它假设双方承担避让责任；敌军接战、玩家强制移动和物理挤压不能一律套用和平人群的规则。当前尚未采用 ORCA。 |

优先级是先保证支撑面并集和连续净空正确，再比较 LCT 的查询成本与当前可见图，最后单独处理拥挤人物的避让。移动甲板的网格应保存在船的局部坐标；船与船、船与岸接触时建立跨面连接，随接触关系变化更新，避免每一步重建整张世界网格。

## 可复现的长局压测

运行 `npm run benchmark:naval-navigation` 可检查功能与耗时。对照产品压缩代码的性能时，使用以下命令，单独运行，不与构建和测试并行：

```sh
npx esbuild scripts/naval-navigation-benchmark.ts --bundle --platform=node --format=esm --minify --outfile=/tmp/naval-navigation-benchmark.mjs
node /tmp/naval-navigation-benchmark.mjs
```

2026-10-06，本次修复的沙箱测量：`brokenSea`、一个空闲玩家与 V5/V7/V8、15 分钟模拟，终局 78 人物/船只（其中 20 艘船）、36 建筑。创建游戏 20.11 ms，首步 60.94 ms；后续最慢步 37.47 ms，P99 15.51 ms，均值 2.86 ms，后续超过 50 ms 的步数为零。首步仍超过 50 ms，需独立继续改进，不能从平均值中抹去。此场景不代表最大军队规模，也不包含浏览器绘制成本。

基线提交 `7a56661a3f80cbb8acfc5b8f546330b216a668c9` 使用相同压缩构建方式、地图与玩家配置：15 分钟模拟最慢步 22,563.62 ms，P99 30.41 ms，均值 4.13 ms，137 步超过 50 ms。基线终局 75 人物/船只（其中 15 艘船）、36 建筑。装备、路径与 AI 行为修复会改变对局轨迹，因此这是同配置长局的压力对照，不是相同快照逐帧的微基准。
