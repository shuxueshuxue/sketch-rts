# 骑射的真实安全绕行

旧骑射只验证原生最短道路是否安全；一座塔覆盖该路就可能拒绝出兵，即使另有安全绕路。现在在原始地形道路之间加入威胁圆周之外的连接点，用原生道路与实际地形行军时间选择射击站位，并发送现有排队移动命令执行整条道路。近处也继续验证完整路段，不再提前交回直接移动。地形、移动引擎、兵种数值、初始资源、购买价格与每15帧思考均不变。

两处运行文件，无新增持久字段、记忆结构、默认或兼容路径。道路内核复用 groundSteeringRoute、groundTravelCost、retreatThreatReach 和 routeLeavesDisks。不可达是明确的查询结果。每条实际返回的路段都检查所有威胁圆；图节点只取阻挡原生道路的威胁连通分量，避免每个目标枚举全地图威胁。按不可变快照缓存路由器、路段与目标结果。这个有限节点图不保证找到所有可能绕路，也没有声称全局最优或整体CPU提升。

192项本地原生SDK检查通过：42项道路、道路任务和付费绕行，150项招募、独立任务、矿线与恢复检查。十二项付费测试以正常500初始金币和实际采矿投资，六个可绕行场景真实招募一名150金骑射，零受伤击杀对方工人、零永久损失、金币守恒；六个封闭河岸不招募。固定已有六名步兵留在另一战线，不能当作正常开局胜局。同测试源码的公开父版本6通过、6失败，可绕行六项始终没有骑射购买。内核测试另有直接穿塔控制：直接移动实际受伤，排队绕路不受伤；斜向安全近角仍可直行，真正全高隔墙返回不可达。

原任务测试中的“伏击”只有部分隔墙，实际存在绕路；因此将其拆成开放、可绕行、完全封闭三种情形，保留原健康、损失和金币断言。封闭情形仍完成两个安全营地并放弃骚扰，可绕行情形要求实际击杀工人。没有把旧的拒绝出兵断言当作新版必须保留的战术。

Node20完整构建通过。实际旧骑士败局6000、12000、18000、24000帧的只读诊断仍没有新增骑射意图；本批没有宣称修复那场败局。三路线1620格与未见种子依旧待验收，没有重复全矩阵。CI及首次生产部署均新增相同原生道路和付费场景，原CPU预算不变。
