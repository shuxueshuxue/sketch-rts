# bootstrap_1：友军矿归属与殖民预算

父版：`17a3f9eb70975a99757e2116ad2afabce464f16e`（#263）。

naval 的本地空矿、岛矿和运输任务原先只排除自己或敌方的基地。友军已开发的大陆矿会被误当作可扩张空矿，从而阻止岛矿计划；友军岛矿则可能被直接选为殖民目标。海外只剩友军矿时，殖民预算仍会扣留下一座基地的钱。

新增共用 `mineClaimedByAlly`：同盟的采矿基地，或正在采该矿的工人，占用这个矿。基地范围直接使用现有 GOLD_MINE_RULES.baseRange；这里是卸金范围，所以采用直线距离。把同一规则用于本地矿可用性、本地殖民、岛矿选择与已缓存计划、正在执行的运输，以及殖民预算。不新增距离参数、持久状态、地图／对手分支、资源、SDK 例外或兼容路径。已有敌方据点的战斗判断继续由原海军规划处理。

验证：

- 48 项原生 SDK 场景覆盖三条 v9 路线、两族、镜像方向、友军基地／矿工占矿，以及是否同时有友军大陆矿。运输实际执行移动指令，目标为真正空闲的岛矿；零己方支出、零永久单位阵亡。
- 四项中途占矿场景，两版都先选择同一个空矿；通过正常 SDK 命令让友军开始采它。候选撤回原运输，精确父版继续错误任务。
- 四项预算场景只剩友军海外矿，候选不再请求殖民且不再扣留基地资金，普通 500 金与零支出保持。场景采用全同盟以排除独立的沿岸战斗需求，没有改原断言。
- 原有海军与三路线大陆／既有海外基地扩张共 65 项检查通过，包括 v5／v7／v8 原 240 秒上限内真实建基地、真实采金的三个场景；与上述 56 项合计 121 项不同检查。原有断言、时长及 CPU 预算未改。
- 27 个历史 v5／v7／v8 指令帧、79 条指令及 AI 内存与父版相同；冻结 revision `dba796cfc152379adad9988a1314f94ffc736137` 的 54 个源码哈希未变。生产客户端／服务器构建使用 Node 20 和真实 `/sketch-rts/` 子路径。

“正在采矿”以模拟中的实际矿工订单为准：只有隔海的本方卸金基地时，工人会停止采矿，不能用一个失效指令证明持续占矿。此批原生场景提供真实可达的本方卸金路线。它修正海军和殖民侧的资源归属，不宣称完成完整全地图经营、零死兵竞速或 bootstrap_1 的强度矩阵。
