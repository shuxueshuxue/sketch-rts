# 让同一帧的治疗真正分配给不同伤兵

此前多个牧师读取同一帧，选择同一个最近重伤者，后续治疗溢出。通用 abilities 脚本还会在 medicalRecovery 之前即时治疗，先消耗冷却，后者的指定目标因此无法生效。

现在治疗模块根据本帧已安排的就地、已就绪治疗更新预计血量，后续牧师优先选择剩余伤势较重的射程内目标；未就绪或需要走路的治疗不算已到账。射程内施法仍使用直线距离，远处患者仍按道路选取。v9 通用技能只对治疗模块负责的牧师让出 heal，其他能力和冻结旧版不变。没有新增状态、数值加成、额外资源、思考频率或兼容路径。

三系列、两阵营、镜像共 12 个完整 v9 战术栈 SDK 场景中，三名牧师对三名重伤者的同帧有效治疗量从 Grove 125、Ember 98 提升到 165，零永久损失、零支出。父版本全部 12 项失败。386 项相关检查通过。首轮构建发现测试取目录 union 的 healAmount 没有静态收窄；只修正测试类型声明，12 项原断言重验通过，最终 Node 20 构建退出 0。

同一真实崩盘快照的 12000–12800 tick、完整控制器和全部记忆对照，两版仍各两次永久阵亡。该窗口没有改善，不作整体战力或胜局声明。完整 1620 格和未见种子验收仍待完成。
