# 科研需求在实验室忙碌时仍保留

同一个研究建筑承担武器和护甲升级。旧目标生成器只在实验室空闲时生成需求，另一项目研究期间需求消失超过既有十秒记忆期限，等待优先级被删除。实验室重新空闲后，原本只高一点的武器优先级又抢先，出现武器升完、护甲仍零级的局面。

现在先选可研究该项目的已完成建筑、优先空闲者，忙碌期间仍保留目标与等待年龄。无法开工时不保存这笔资金、不发送指令；空闲时由原排序、原价格与原 SDK 命令调度。没有调整优先级、年龄系数、目标等级、思考频率或单位数值，没有新增状态或兼容处理。规则 2 冻结归档不变。

61 项不同 SDK 检查及 Node 20 构建通过，包括原科研建筑先决条件和两套经济检查。新增四个正常资金与采矿场景覆盖两阵营和镜像：实验室忙碌时护甲意图保持、不锁资金且不发指令；武器 I 完成后先研究护甲 I，金币与采矿守恒。公开父版本的四个场景均未保留该等待意图。

从完整新开局败局第 6000 tick 恢复全部控制器记忆和 ID，正常继续至第 14000 tick，首次武器研究第 8595 tick、护甲研究第 10020 tick；期末武器与护甲均 1 级。旧观察在相同阶段有武器 II、护甲零级。同一 6000–14000 tick 区间两版永久阵亡都是 18 次：本次对照证明科研调度生效，尚未证明减少阵亡或获得正式胜局。完整矩阵、未见种子与其他战术路线继续。
