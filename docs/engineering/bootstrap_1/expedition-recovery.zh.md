# bootstrap_1：岛上远征的前排轮换

父版：`a6e16dc09d63168f9fbaf97c47adcee7ccd23dee`（#262）。

海军脚本占有已登岛的陆军，主战场的伤兵脚本因此无法接管。原先整队按总战力推进；正常 Sapphire Archipelago 保存世界里，枪兵在牧师下一次治疗就绪前阵亡。等待血量低于既有 35% 阈值才退，也仍会死亡；退到治疗者身边后变为空闲，还会重新追敌。

三条 v9 路线现在在同一个海军脚本内分配远征伤兵和治疗者：按道路距离选择可达治疗者，用其实际治疗冷却和正在攻击该单位的敌人攻击间隔估算下一次治疗前的伤害。预计撑不到治疗或已经达到原伤兵阈值时，先撤离即时威胁，随后持续跟随治疗者。健康兵继续原远征指令。预测使用攻击面板伤害，未建模护甲减伤；它是提前轮换依据，不是精确 DPS 模型。

治疗指令复用既有 `planMedicalRecovery`，普通主战场仍传入原患者集合；没有另设治疗阈值。撤离复用既有逃离几何；威胁范围采用直线距离，治疗者选择采用道路距离。新增一个远征协调模块，不新增持久 AI 状态、兵种属性、资源、地图／对手分支、SDK 绕过或兼容路径。只在队伍已有可达治疗者时接管，不声称解决所有无治疗队伍的保兵。

验证：

- 十二个原生 SDK 场景覆盖三路线、两族和镜像方向。正常枪兵／灰烬掠夺者、治疗者和四名射手，在 90 秒内杀掉两个岛矿守卫；原六名永久单位全部存活，实际受到伤害，零招募及治疗支出。金币严格为正常 500 加两个守卫的目录赏金，比赛没有被当作胜利。
- 同一输入、时长和断言加载精确父版模块，十二项全部因原前排死亡失败。
- 六个相关文件共 81 项检查通过，包括原召唤师前排、治疗预算、主战场恢复、骑射微操与海军服务；没有修改已有断言、时长或 CPU 预算。
- 27 个历史 v5／v7／v8 指令帧、79 条指令和 AI 内存与父版完全相同；工程分支冻结 revision `dba796cfc152379adad9988a1314f94ffc736137` 的 54 个源码哈希未变。
- Node 20、真实 `/sketch-rts/` 子路径的客户端与服务器生产构建通过。
