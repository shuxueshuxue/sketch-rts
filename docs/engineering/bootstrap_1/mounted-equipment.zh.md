# bootstrap_1：机动采购、撤退目的地与空间分类

购物此前只给近战兵考虑靴子，而且排除了全部骑射任务成员。三个 v9 控制器的独立骑射手现在能在安全道路上购买自己的靴子。已投入战斗、被敌方火力覆盖、没有脚部空位或已经携带靴子的骑射手不会开启此采购；主阵列继续使用原有卷轴采购意图。

使用已有购物记忆与经济目标，按普通商店价格扣费和库存结算。购物期间骑射分配器释放这名单位；回程完成后，重新接刷野或骚扰任务。没有增加状态、缓存、单位数值、资源额度、专用地图／种子／旧对手版本分支或决策预算。运行时只修改购物与骑射任务两个 bootstrap 模块。

## 实际 SDK 验证

六项正常属性的骑射采购场景覆盖三个 v9 控制器及左右镜像：各自正常扣费 100 金、实际穿戴于脚部，回程后重新接清营任务，清掉三名普通食人魔，原始单位存活且骑射手累计承伤为零。相同当前 #320 父版本六项均失败在未采购，不能把父版本的正常清营说成失败。

完整 AI 规划器另有两个镜像场景，要求普通矿工收入、持续正常造兵、购买骑射靴子和整场账目守恒。商店、拾取与精英培养相关 45 项检查通过；骑射、舰队与登陆任务所有权 48 项检查通过；共 95 项不同检查。63 个普通控制器状态、167 条命令与全部记忆相同，批准冻结的 54 个档案哈希原样。

同一真实 elderwood / Grove / 起点 0 的 v9_archer 对冻结 v7+v8 中盘，恢复 12000 tick 的完整世界及全部控制器记忆，运行至 15000 tick。父版本自身累计损失 13，采购候选为 4；敌方玩家击杀 7→6，野怪击杀 16→17，双方自身野怪致死均为零。候选在 14085 tick 实际支付 100 金买靴子，到 15000 已结束购物并重接骚扰任务；原骑射手仍为 109 HP，父版本对应单位为 7 HP。没有中途增加资源、单位或预置采购任务。

采购调度也改变了此前的交战和回程安排，不能把局部结果全部归因于靴子的速度加成。这不是从零开始的整场胜局，也不是整场无损；观察输出为 `/tmp/bootstrap_1-mounted-shop-next-observation.json`，父版本相应帧为 `/tmp/bootstrap_1-320-archer-elderwood-wars.json.frames/15000.json`。

## 岛图撤退目的地

正常从零开始的 sapphireArchipelago 无对手开发观察中，一名远征步兵的撤退目标每轮都跟着健康队友移动；它最终被野怪追上。候选沿用当前撤退指令的目的地，到达或离开威胁后再归还普通指挥，不新增任务状态或健康阈值。

从完整 10800 tick 世界和记忆重放至 12000：父版本失去步兵，候选保留它、剩余 21 HP；双方都清掉两名守卫。候选只有一个临时召唤物死于野怪，原始永久单位没有阵亡。28 项已有远征治疗、无治疗轮换和移动归队检查通过。没有调整单位、资源、目标地图分支或预置撤退任务。观察为 `/tmp/bootstrap_1-island-retreat-goal-solo-trace.json`，不是正式对阵胜局。

## 空间分类工作量

共享模拟的空间索引已有成员及格子记录。候选在该记录内保存原始坐标，只重新分类变化的坐标轴；成员、阵营、格子尺寸和旧索引存储转移规则仍照常检查。没有添加错误兜底、旧格式适配或独立计时缓存。

同一完整世界运行 600 tick，分类计算由 264342 次降到 136376 次，下降约 48.4%；每一帧校验和及完整终局快照一致。57 项空间索引、存储转移、碰撞、确定性和恢复检查通过。带计数器时的 CPU 时间不能用作运行时收益；另一个无计数器、逆序的 300 tick 对照为 5047.844→4840.895 ms，只是一段局部观察，不能宣称解决全部 CPU 超时。记录 `/tmp/bootstrap_1-spatial-stationary-proof.json` 和 `/tmp/bootstrap_1-spatial-stationary-plain-proof.json`。

最终组合共 180 项不同 SDK 检查通过，构建通过；63 个普通控制器状态、167 条命令与完整记忆保持一致。首次仅含采购的提交被默认 v2 CPU 门槛挡住（14.33/12 秒、17.34/16 秒）；新提交只有在原门槛通过后才合并，门槛未放宽。另一个骑射撤步候选有完整检查回归，仍未纳入。本批不是全部地图或未见种子的 bootstrap_1 完成声明。
