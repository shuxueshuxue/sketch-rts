# 远处战利品、三星培养与撤退目标

精确父版：`a99476a1e582de75b5dd507a5f37c49808ecca20`。旧物品模块只在单位附近 72 范围内选择拾取者，远处掉落物没有独立拾取和归队流程。

三条候选路线共用 `lootRecovery`：只派出一名满血、可装备的永久陆军，避开海运、刷野、袭扰和骑射既有任务。使用实际地形道路时间和每段道路的已知敌人攻击覆盖选择行程；回到按道路选出的可达基地。普通 SDK 拾取指令与排队避战归队指令完成任务，既有物品模块独占消耗品使用，不重复消费经验书。任务只记录单位、物品和基地三个 ID；受伤后交回既有恢复指挥，到家后交回主力。

经验书优先继续培养已有星级的单位，再按既有物品收益评分、道路时间和稳定单位 ID 选择。原评分偏重眼前升一级，骑士的两本书会分给两名二星单位；新候选能够连续培养同一名三星单位。没有改变经验、价格、星级门槛或单位属性。

度量复用：`safeLandTravelTicks` 提取原雇佣采购的整段道路威胁检查，雇佣与战利品共用；`armedFoes` 合并雇佣、拾取与刷野恢复的敌军事实。道路时间使用已有 `routeTravelTicks`，物理交互和攻击覆盖仍使用圆心／点到线段距离。没有把道路长度用作物理射程。

同存档复查还发现撤退目标错误：刷野集结点可以落在水格，移动引擎先投影到可走位置，原伤兵模块却对水格直接计算道路距离并放弃恢复。候选用引擎已有的 `walkableGoal` 和 `walkDestination` 计算实际撤退终点，预测、脱险和驻守共用该点。不是加入默认路线，也不放宽通行规则。

66 项不同原生检查通过：13 项拾取与归队、24 项干地／水格集结点保兵、24 项雇佣任务及 5 项原物品策略。三路线／两族／镜像的十二个拾取场景全部实际消费所需经验书，只有一名拾取者，达到三星并返回基地，原军队全部存活，普通 500 金未变。隔墙场景明确证明直线更近的单位道路更远，实际由另一名单位拾取并返回道路更近的基地；单本书对该步兵仅升到二星，按真实 160 XP 验证。

精确父版在十三个新增拾取场景全部失败，实际没有远程拾取和经验书消费；二十四个刷野场景中十二个干地控制通过，十二个水格集结点全部损失前排。27 个历史 v5／v7／v8 规划帧、79 条指令及内存完全一致。冻结清单仍使用 `dba796cfc152379adad9988a1314f94ffc736137` 的 54 个源码哈希；当前公共集成文件不是冻结源码副本，不重新冻结。

普通 Lone Market 射手／林地保存世界诊断：拾取原型从共同 6000 tick 推进到 12000，三个采矿基地、十六工人、七名守卫击杀并持有守护卷轴，但损失一名枪骑兵，且仍未培养出三星；精确父版同区间零损失、有一名三星。仅扩大恢复阶段没有修复，已撤回。对原型共同 10800 世界推进 1200 tick，实际撤退终点修正保住该骑兵，仍完成两名守卫击杀，保持三基地、十六工人，零新增永久损失。这是局部保存世界诊断，不是正常固定开局胜场，也不证明全图无损或经验分配达标。
