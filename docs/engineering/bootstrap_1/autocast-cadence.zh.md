# 自动施法到期检查复用

#326 首次生产部署在原有默认 v2 对局 CPU 检查失败：无营地约 14476 ms，梯图约 16851 ms，预算分别为 12000／16000 ms。功能检查通过。这两场默认 v2 没有执行新伤兵回撤模块，不能把失败归因于该模块；没有重跑原样失败提交或放宽预算。

本批只将自动施法的到期判断移到单位循环外：一个逻辑帧计算一次原有 `tick % 2`，到期帧仍按原单位顺序、订单、冷却和技能规则自动施法。单位原有冷却倒计时照常每帧执行，自动施法仍每两个 tick 执行。运行时代码单文件 +3／−2；没有新状态、缓存、常量、版本／地图分支或兼容路径。

使用一份真实默认对局的 48000 tick 存档，原代码与本批代码先连续执行 1200 tick，每帧核对完整世界快照和实体编号，全部一致。随后每种实现预热三次，再按父／候选／候选／父顺序测量四个原生 6000 tick 局部续局；全部末世界和编号一致，摘要均 `fcb428d7`，末实体编号均 4887。CPU 分别为 813.503、457.861、490.031、622.099 ms。这是本机一个局部世界的测量，不代表完整对局的 CPU 降幅或生产预算已经通过。

95 项技能、自动施法、冷却、原生训练出生、回调技能、老兵、地面帧及 SDK runner 检查通过。最终固定源码 Node 20 客户端／服务器生产构建实际退出 0。此前按“无已选技能帧”跳过无技能单位的写法虽通过检查，但局部 CPU 没有收益，已撤回；本批没有包含它。

冻结 v5／v7／v8 的归档和清单原样。完整 1620 格及最终未见种子验收仍未完成。
