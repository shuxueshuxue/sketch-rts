# 补兵道路和无掩护施法单位微操

正常单机扩张观察中，原清野队选择营地时检查了道路，后来加入的工程兵却直接走向远处集合点，穿过另一个营地。施法单位随后失去掩护；原“原地对抗近战”的策略又让能甩开石头人的牧师停下等它们追上。

补兵现在逐个检查实际包含建筑障碍的 steering 道路，沿用已有营地净空距离，排除目标营地之外的覆盖区域；仍在抵达集合点后计入营地战力。无掩护的远程施法单位遇到能甩开的慢速近战追兵时，复用现有微操，射击与后撤按双方速度、射程、冷却、瞄准和威胁决定。微操的瞄准速度读取实际兵种定义。医疗施法、真实前线掩护和召唤宿主队形继续保有原有优先级。

运行时代码八个模块，不增加持久状态字段或数值门槛。营地识别复用原函数；通用后排规划器的微操回调为必填，所有调用点已更新。候选策略提供新微操，旧公共策略保留原决策；独立冻结归档没有修改。

165 项不同相关 SDK 检查与 Node 20 构建通过。36 个新增场景覆盖三个家族、两个种族和镜像，包括危险补兵路线／可用路线、无掩护牧师面对三名近战追兵；后者运行 1,200 tick，零伤害、零损失并对野怪造成伤害。公共父版本在这 36 项通过 12、失败 24。原有清野集合、岛上前线恢复、立即治疗和骑射兵微操均通过。

从同一 9,600 tick 世界、完整记忆和 ID 继续到 14,400 tick：已发布的空矿改进版本仍损失五名永久单位；仅补兵道路原型降至两名；加上施法单位微操后零损失，21 名永久非工人单位存活，三座基地、16 名工人和三处收入矿。新方案这一窗口少杀一名野怪，不据此宣称整局胜率提高。这些都是当前规则 2 的局部观察，不算正式对手验收或最终未见种子。完整记录见[回执](./support-march.receipt.json)。

新增场景加入 CI 和生产发布流程，原有模拟 CPU 门槛保持。下一步以真实双对手对局继续观察经济、战斗投入和全地图任务执行。
