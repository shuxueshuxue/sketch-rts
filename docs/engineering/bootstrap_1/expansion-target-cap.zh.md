# bootstrap_1：扩张目标随军力继续增长

原 v9 的扩张目标为 `min(5, 1 + floor(army / 5))`。即使野怪已清、存在可达空矿，足够保护矿线的军队也不能令目标超过五座有效采矿基地。移除 `min(5, ...)` 后，目标仍由现有军力决定；原有道路、友军矿归属、敌方压力、掩护塔、建造与金币调度检查继续执行。

运行时只改一行，无新增状态、缓存、门槛常量、寻路算法或版本兼容路径。有效采矿基地沿用原定义：已完成基地附近存在尚未枯竭的金矿；不能用建筑总数代替。

## 原生 SDK 对照

三个 v9、左右镜像、有无第六空矿共十二项。初始有五座正常基地、每矿五名真实往返矿工、二十六名正常士兵、足量普通农场及正常 500 金；这是中局场景，不是从初始三农民起步的证明。盟友拥有另一处金矿。每 15 tick 运行普通完整规划，模拟 1800 tick。

父版本六个有空矿场景全部失败，六个无空矿控制通过。候选十二项全部通过：有空矿时第六基地完工、真实采矿并支付普通建造费用；无空矿时维持五基地。所有场景都未占友军矿、未改变友军矿金量，原有单位全部存活。
