# bootstrap_1：跨岛骑射手清营与运输船恢复

没有陆地侵入警报时，空闲骑射手可使用空闲、已修好的运输船前往没有敌方势力、没有友军矿点占用的守卫矿。使用现有兵种、资源、运输容量和 SDK 登船命令；没有地图、种子、对手版本分支或属性补偿。

## 任务分工

- 渡船任务明确记住指定骑射手，即使尚未登船也保留任务归属。陆地接应按地形行程估计排序，海上独立比较航路长度，不合并不同单位的度量。
- 一个共享矿点任务视图同时服务经济、渡船和舰队主动目标选择：骑射手正在清营时，拓荒队不抢这一个矿点，舰队不主动接管这一营地。其他矿点仍可开发，敌人仍完整参与危险判断。
- 独立清营渡船不召集整支战舰队护航。清营完成后正常释放矿点，两名拓荒工人继续真实登船开发。
- 运输船结束已有载人航次后，在可达船坞使用正常付费维修，修好后接新任务。返港选择沿水路可达、正常船体姿态能进入维修范围的泊位；不增加维修速度、金币或瞬间治疗。
- 海岸入口仍使用现有海岸选择器；没有解决所有浅滩、海岸危险或友舰碰撞问题。

## 真实 SDK 验证

新增 39 个场景覆盖三个 v9 家族的镜像自动运输、无伤清两个食人魔、任务占用、另一矿点可用、清营后的两名工人接续、舰队协同、付费返港及既有航次不中断。

正确初始化合法船体位置及航向后，舰队协同六个场景与线上 #304 基线对照：旧版六个场景均损失战舰和两名甲板船员；本批六个场景骑射手真实攻击并清营，己方无伤、无永久损失、无花费。初版缺失合法航向造成的卡船失败不计为策略证据。

另在 Sapphire Archipelago 正常 v9_archer 单机存档 42000–54000 tick 中观察了加入矿点及舰队分工、尚未加入返港修整的候选。候选清掉 3 名守卫，对照清掉 0 名；双方没有新增永久损失，均有 5 座基地、23 名工人。候选累计花费比对照多 1445 金，没有净收入或扩张数量增益。运输船仍受 72 点守卫伤害和一次友舰碰撞，因此后来加入返港恢复；该段长窗口不当作最终恢复实现的完整对照。

## 验收界限

冻结档案 54 个文件哈希相同。旧版规划输出与普通海军入口另作完全相同检查，三个 v9 家族的特殊任务显式传入所需分工规则，不添加兼容接口。

本项是跨岛任务执行与存活的局部改进，没有新增正式验收胜局。全地图单对单、单对双及未见种子验收仍未完成，bootstrap_1 继续。
