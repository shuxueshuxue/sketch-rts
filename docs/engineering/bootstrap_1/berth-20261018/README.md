## 整合决定与未完成范围

机制值得通用化，但本轮不把按具体 ID、当前朝向及局部位移写成的诊断脚本直接合入策略，也不启动无法验证该脚本的正常开局。运行源码没有改变。下一步通用实现应：

* 从真实返航任务、原生 landingSpot 与友方船体阻塞识别适用场景，不能按船名/地图坐标触发。
* 将阶段、船只、实际乘员、帮助让路的单位、目的地主基地和当前航路保存在可序列化 AI memory 中，验证中途完整保存恢复等价。
* 只保留实际相关单位的指令权，拆分保留同组其他单位；威胁、失去船只/基地或路线失效时释放控制，不能永久等候。
* 出岸检查必须覆盖当前全部船体；允许合法短路段绕行接回基地，避免普通登船招募抢走尚未出岸的乘员。
* 先在三路线的同源输入上检验通用实现，再回到已知种子的正常开局；全员回家是该局部任务完成条件，不等于殖民收益或总体胜利。

三路线、rulesVersion 2、冻结184项保持不变；没有增加等待人数，没有削弱对手。六项旧出航测试在基线同样失败的记录继续以 [上轮证据](../assembly-20261018/README.md) 为准，本轮未修改相关源码或断言、未重复声称测试全通过。认证未恢复，未写远端或改凭据。未知 `.scratch-bootstrap-20261018/` 未动。
