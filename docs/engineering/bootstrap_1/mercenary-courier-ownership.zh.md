# 雇佣兵采购任务的明确归属

mercenaryControl 曾把任何避战回主基地的普通单位认作雇佣兵返程，也会接管站在空营地附近的普通部队。正常 Pineshade / Grove / v9_archer 对冻结 v5+v7 的24000保存点，十名普通部队因此被排除在主指挥之外，满血风暴法杖射手没有得到指挥命令。

采购任务现在记录实际派出的信使 unitId 和目标 campId。只读查询描述有效任务，执行阶段结束归队、死亡、登舰或目标／基地消失的任务。原采购、实际交费、营地物理控制范围和佣兵归队规则继续使用；信使被身体挤出营地控制范围后仍向同一营地进场，采购途中保留原预算目标。普通部队的撤退和营地附近站位交给原有指挥模块。

新增二十四个三路线／两阵营／镜像 SDK 场景，分别覆盖普通射手回撤和站在空营地边缘：全部恢复正常射击，四射手保留、己方零损失、零额外花费。精确父版二十四场均错误占用普通部队而失败。二十四个原有实际雇佣与信使归队场景也通过，第一版与只读查询修正后的六个失败仍保留在开发日志；记住目标营地、恢复进场后才通过。

最终十一文件179项不同相关原生检查通过；27保存状态／79旧版指令及记忆逐项相同，冻结54文件清单不变。最终固定源码 Node20 子路径客户端／服务器生产构建实际 exit 0。

同一个正常1v2的24000→24600短窗口，起始单位损失父版3、候选2；结束时父版26战斗单位／2544总剩余生命，候选28／2731。双方仍有两座基地，没有胜负。候选损失两名长枪兵；父版使用风暴法杖，候选在该窗口没有使用。没有宣称零损失、物品效率改善或正式矩阵胜场。
