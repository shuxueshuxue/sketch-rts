# 空营地采购与归队

父版：`45b443578447302e5408b960946d29f3a503dd42`。已控营地采购已经接入经济队列，但普通单机保存世界的两个安全雇佣营没有守卫，部队仍停在家，未主动利用。

候选三路线从主力中分出一名满血、低星、无召唤／治疗职责的陆军去控制空营地。骑射手、现有刷野／袭扰小队和已有单位任务不参与。目的地按地形可达性和单位速度计算行进时间；路线的每一段用公共点到线段距离检查敌人攻击、技能、物品和下一思考周期的移动覆盖。不可达或穿过已有威胁的路线不产生采购任务。

旅途中采购资金按现有商店优先级 45 预留，抵达后沿用原先已控营地的 64 优先级和统一目标等待加权。采购者在营地明确等待；新佣兵立即回家，采购者在原角色上限或库存耗尽后回家。向营地及基地行军使用普通避战命令，持续相同目标时不重发。利用实际行军／驻守命令识别采购任务，不增加持久 AI 状态。采购及归队部队暂时移出主力集结名单，到家后恢复正常指挥；否则远处一名采购者会使主力永远集结不齐，停止刷野和扩张。

度量基础同时消除四处雇佣控制范围副本：模拟、SDK 校验、普通雇佣事实及旧塔攻工人都使用 `unitControlsMercenaryCamp`，物理控制仍按同一圆心距离和原 220 范围判断；道路长度不改变交互范围。`routeTravelTicks` 复用现有 `walkingDistance` 和每秒 tick 常数，刷野撤离预测也使用它。它只描述地形道路在指定速度下的时间，不声称覆盖建筑绕行、单位碰撞或船舶转向、风场。

验证分清任务与全局采购取舍。三路线／两族／镜像十二个独立佣兵流程场景均在原 120 秒内用正常起始 500 金完成两次实际 SDK 采购、全部归队，零永久单位损失；另十二个完整规划器场景均完成实际采购，买到的兵归队，采购者归队或在营地明确等待，零损失。完整规划器的两个林地射手场景优先攒射程升级资金，只买一名；这是全局经济取舍，不提高佣兵优先级或延长测试来强制第二次购买。两个道路检查覆盖隔墙直线更近但道路更远、不同速度、不可达水路及同距顺序。

上述 26 项加 104 项既有已控雇佣采购、刷野恢复、远征治疗、集结、守矿、经济预留、骑射骚扰、塔攻及真实命令校验检查，共 130 项不同检查通过。精确父版在十二个完整采购场景中均零佣兵、零采购，不只比较脚本名或指令形状。

普通 Lone Market 单机检查保持正式地形、矿、营地和守卫，只有一名竞争者，仍从 500 金、三工人、一基地开始。射手路线到 6000 tick 实际买到两名佣兵、清掉三名守卫、完成两个采矿基地、九工人，零永久损失；骑士从共同 2400 保存世界推进至 6000，也买到两名佣兵、两个采矿基地、十一工人、六枪兵、三名守卫击杀，零永久损失。这些是局部诊断，不是正式强度胜场。
