# bootstrap_1：刷野的道路与执行几何

父版：`c91169fd14f070230aa8f27bd0327b258188a821`。

旧刷野选择检查军队中心到集合点的直线，实际士兵却沿地形道路绕行，可能经过另一营地。候选三路线现在检查每名参战单位的真实陆路，将每段道路与其他营地的原有 260 范围比较；营地收益中的距离成本使用到集合点的平均道路长度。集合点沿用原有七个角度、400 范围和战力门槛，并投影到合法陆地点。选择后直接执行这个集合点，不再用另一次营地分组重算它。不可达道路不参与选择。

共用 `routeClearsDisks` 只处理道路折线与物理圆的关系。雇佣兵、物品回收、商店远行复用它，原公式和范围不变；道路时间仍由 `routeTravelTicks` 处理。攻击范围、威胁半径、军队是否聚拢继续使用直线度量。地形道路不包含人体与建筑绕行，也不代表受风与转向影响的实际航行时间。

共同刷野选择器显式接收接近几何，军队计划显式接收选择和执行函数。旧版提供原直线函数及原执行器，候选提供道路函数及选定集合点执行器。旧执行器原样保留，包括它既有的重算行为；候选没有备用路线、旧版兼容分支、新状态或新阈值。

验证：

- 88 个不同的本地原生 SDK 场景通过：14 个新道路场景、11 个原 v7 刷野场景、2 个道路选择场景、24 个雇佣兵控制场景、13 个商店场景和 24 个伤兵恢复场景。保留旧执行器后重新运行受影响的 25 个场景，全部通过。
- 十二个三路线／两族／镜像山墙场景运行完整作战计划 1800 tick。道路绕行处有六名正常食人魔法师，八名参战士兵均不进入该营地 260 范围、满员存活，金币保持 500。另两个镜像场景证明选更短道路的营地，而不是直线看起来更近的营地。
- 对精确父版运行同样十二个完整计划场景，十二个均因实际进入另一营地范围失败；不是模块缺失导致的失败，也不将该断言等同于十二次全部阵亡。
- 27 个历史公开策略帧的 79 条指令及内存与父版相同。另四个两族／镜像控制专门覆盖“选择的旋转集合点与旧执行器重算结果不同”，旧版执行状态仍与父版完全相同。冻结 revision `dba796cfc152379adad9988a1314f94ffc736137` 的 54 个源码哈希未变。
- Node 20、真实 `/sketch-rts/` 子路径客户端与服务器生产构建通过。未调整 CPU 预算、资源、地图或胜负条件。
