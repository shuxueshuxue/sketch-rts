# bootstrap_1：把道路长度与行程代价分开

`walkingDistance()` 的全图距离场每个正交步长为 5、斜向为 7，没有地表速度权重。此前将这个道路长度直接除以单位速度，会把近处泥地工人错误排在远处草地工人前面。

| 度量 | 共享入口 | 适用判断 |
| --- | --- | --- |
| 直线与目标船体/建筑边界距离 | `strikeGap()` | 武器和射程 |
| 连通地形上的道路长度 | `walkingDistance()` | 距离与可达性 |
| 已知畅通直路的地形行程代价 | `groundSegmentTravelCost()` | 沿线积分真实地表减速 |
| 地形行程代价 | `groundTravelCost()` | 畅通直路积分，绕路复用转向寻路的地表代价 |
| 按单位速度的估计时间与到达顺序 | `routeTravelTicks()` / `routeArrivals()` | 增援、登船、建造和跑腿 |

行程代价单位是等效裸地距离。绕路使用已有转向寻路的网格权重，浅滩为 `round(4 / .75)`、泥地为 `round(4 / .6)`；它是估计，不包括状态效果、单位与建筑绕行、到达容差和逐 tick 跨格误差。海上道路长度除以给定速度仍只是常速估计，不含风、转向或加速，不将它当作实际航行时间。

## 真实 SDK 证据

两名正常属性工人分别走泥地短路和草地长路，不加资源、不改速度。每名工人在独立同场景执行普通移动命令，防止到达同点后的身体相互阻塞。

| 方向 | 工人 | 道路长度 | 原估计 tick | 修正估计 tick | 实际 tick |
| --- | --- | --- | --- | --- | --- |
| 正向 | 近处泥地 | 384 | 128 | 205 | 203 |
| 正向 | 远处草地 | 448 | 150 | 150 | 148 |
| 镜像 | 近处泥地 | 416 | 139 | 205 | 203 |
| 镜像 | 远处草地 | 448 | 150 | 150 | 148 |

原排序在两个方向都错误；修正版与实际到达顺序一致。泥地误差由约 37% / 32% 降至约 1%，镜像网格端点不再改变直路时间估计。双方正常 HP、0 损失、0 花费。

第一版全用加权网格时，泥地估计为 208/227，镜像仍有约 12% 误差；发现引擎先走畅通直路后加入沿线积分。第一版 143 项相关检查通过，最终实现 146 项检查通过，新增场景的时间误差约束从 12% 收紧至 2.5%。此前带未来威胁评分的骑射手数学试验仍未采用。

## 架构与查询成本

共享现有 Dial 寻路内核，不复制寻路算法。道路和行程字段共用现有 128 项 LRU 上限及数组复用池，以独立键区分；缓存淘汰后的混合查询回归通过。固定绕路目标在仪器化只读构建中首次产生 1 个代价场，随后 400 次查询增加 0 个代价场；畅通直路不创建代价场。

冻结的旧 v5/v7/v8 策略源没有更改。27 个旧版规划场景的 79 条命令及完整记忆与当前 main 一致。本项是底层度量修正，不计为新的正式验收胜局；bootstrap_1 的全地图胜负矩阵与未见种子验收仍未完成。
