# 运输中的工人仍计入经济人数

父版：`8b83878198e39f9c2942956fd9193054711d569d`。

搬迁八名工人时，补员模块只数没有 deck 的单位，把船上活着的工人当作不存在。普通 Sapphire 保存世界从 24000 到 27000，原有十一工人被额外补到十四，支出三次训练费用；岛矿当前只需要五个采矿工位。这不是新的战略需求，是同一份劳动力被重复购买。

候选的 `missingMiningWorkers` 合并活着的自有工人（包括运输中）、已付款训练队列、有效及正在建设的矿区和原施工人数。补员、生产人口预留、统一经济的 worker 目标共同读取这个缺口。施工选人仍使用原来可在陆地工作的工人集合；不把船上工人当作当前可施工者。原每矿五工位、总上限、费用、人口、施工人数与训练规则不变。仅两个候选模块，运行时 +13／−12，无新持久状态、参数或备用逻辑，旧策略和冻结源码未改。

十二个三路线／两族／镜像场景都从正常 500 金开始，经真实 SDK 命令实际登船八人，保有十一工人；完整规划器不再购买重复工人，仍下正常经济命令，零单位损失。另四个两族／镜像新矿缺员场景仅五工人（含两船上工人），仍通过 SDK 付费训练、真实产出第六名工人，普通费用守恒。十六新场景加原 39 项施工、经济、缺矿预留检查及 34 项医疗、已控佣兵采购、混编和塔攻工人交接检查，共 89 项不同检查通过。精确父版十二个足员场景全部实际发出多余训练命令，四个缺员对照照常通过。

同一普通 Sapphire 保存世界的候选原型保留十一工人、相同八人装载和航行进度，并较早买出普通战舰和一名额外骑射手。没有免费资源或单位属性变化，没有新增永久阵亡；第二岛及全图利用仍未完成，这个续局不是正式强度胜场。
