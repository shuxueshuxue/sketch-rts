# 岛矿与船坞工人的道路选择

海军nearestWorker原已排除甲板工人、忙于其他施工的工人和不在同一块陆地上的工人，但在可达工人之间仍按直线距离选择。现将这一处调用改为已有shared/route-selection的nearestByRoute，海军基地与船坞复用同一目的地的地形距离场。运行时单文件+1/-1，零新增持久记忆、阈值、地图或对手版本分支。矿点关联、塔覆盖和攻击范围继续使用它们的物理规则；没有把地形距离当作船只受风、转向和加速度影响的航行时间。

十二个三路线／两族／镜像SDK场景：两个工人在同一座岛上，直线较近者隔墙绕远；候选选道路较短者，正常付费建成第三基地，己方零死亡。精确#294父版十二场均在选人断言失败。开工时实际扣400金，最终金币加全部花费仍为500。场景固定已有基础设施，隔离施工任务，不称正常开局竞速或整局强度收益。

首版场景错误要求隔墙工人的行程超过整个观察窗口；实际道路虽更长，却不超过该窗口，改为核对两者真实道路次序。随后两轮候选检查错误把建成后的总花费等同400金：现有模拟施工生命值浮点累积留下极小缺口，完成的同一帧自动修理多扣1金。最终分别检查开工扣款与完整账本，保留实际额外支出，没有修改修理或施工规则。

六文件132项原有海军、矿权与通用道路检查通过；最终四文件30项施工／三矿交金／并行建设／海军查询检查通过，重叠海军查询2项仅计一次，共九文件160项不同检查。27保存决策／79旧版指令及记忆完全一致。固定最终源码Node20子路径客户端／服务器生产构建实际exit 0；冻结清单保持原54文件修订。

保存的SapphireArchipelago局面仍显示另一项问题：工作岛矿分别5人和2人，四名闲置工人待在已满员岛上，全局劳动力核算掩盖了第二座岛的缺口。这属于后续按陆地连通区域核算的独立任务。本次不宣称已修复全图配工、全岛开发、零损失或正式1620格验收。
