# bootstrap_1：清营也要有退路

原主力检查每名士兵去集合点的道路，但清完营地后另选返程目标。古木林的实际单机开局中，队伍安全走到弱营、清完后返回主基地，穿过另一处龙营，损失两枪兵与一祭司。只有去路安全不足以保证一次清营任务安全。

营地选择现在明确接收主力的撤回点，同时检查营地内部、集合点返回该点的地形路线。原有每名士兵的去路检查继续执行，危险区域沿用 `CREEP_ROUTE_CLEARANCE`，没有增加门槛。

共享 `groundApproachRoute` 与现有地形距离、行军时间使用同一纯地形语义：地形允许直走时检查直线，否则读取地形道路。直接使用原网格流场会漏掉实际直走穿过的危险区域；混入建筑遮挡又会把基地中心误当成绕路目标。新的地图视图通过独立对象身份排除建筑遮挡层。清营与雇佣、购物旅程的安全判断复用这个入口。

本批运行时四模块 +22 / −11 行，无新增持久状态、缓存、阈值常量或寻路算法。建筑绕行、单位避让及流场转角平滑仍由实际移动处理，本估计不能保证每个位置的真实轨迹完全一致。物理射程与塔覆盖继续使用物理距离；海上风、转向及船体航行不在此度量内。

## 原生 SDK

三个 v9、左右镜像、有无沿途龙营共十二个普通属性场景：一基地、五名实际矿工、八步兵、正常 500 金，远处友军驻军。每 15 tick 进行战斗规划，模拟采矿与战斗 2600 tick，不运行采购。验收是实际受袭与存活，不规定必须取消所有清营。

精确父版本以 #315 的 `7ed341f1813bbc2f4d6aaca40d83a0abb237fd62` 为准，采用连续采矿维护费与分币结算；#313 的先前试验另作历史记录。父版本十项通过，两个召唤师镜像在返程分别受到龙营 58、57 次攻击。候选十二项全部通过，原有八士兵、五矿工均存活，零龙营伤害、零永久损失、零花费。六个无龙营控制实际清掉目标野怪。四个射手、骑士有龙营场景在父版本也能平安完成，不能算新增修复成果。

清营几何、组队、救护、营地归属、扩张授权、购物、拾取、老兵、雇佣预算与退回所有权及共享度量共 232 项不同检查通过，采矿与召唤经济另 78 项通过，共 310 项。额外 24 项雇佣控制中 22 项通过；两个 Ember 射手完整规划场景未在既定窗口内将第二雇佣兵带回。#315 在同样窗口、同样单位位置与花费下也失败，未修改或放宽其断言。总计 334 项检查、332 项通过、两个既有失败；构建通过。
