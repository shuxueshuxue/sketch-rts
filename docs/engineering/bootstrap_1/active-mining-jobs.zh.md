# 将实际长途采矿任务计入人手需求

原需求仅由有矿的基地计算；基地矿枯竭后，即使工人仍在另一座矿长途往返，也会认为现有工人足够。现在以既有采矿基地和实际仍有资源的远矿任务作为劳动需求的位置，按可步行连通的陆地分组。已排队工人和船上工人沿用原计数；友军认领矿、枯竭矿和已经有己方基地的矿不重复计入。

两个运行文件；不新增持久字段、默认值或兼容分支。调用者明确提供施工人数和队伍关系；每矿五个岗位、施工人数规则、36人上限、价格、资源、配额和15帧思考原样。没有创建虚构基地，需求位置只使用实际建筑和资源坐标。

184项相关原生SDK检查通过。新增16场景覆盖两种族、镜像及活跃任务／友军矿／空矿／已排队四种状态：实际补齐两名普通价格工人，零永久损失，已排队不重复付费，现金与携带资源守恒。同源码父版本12通过、4失败，四个活跃远矿均漏补工。原岛屿与渡运断言未放宽。
