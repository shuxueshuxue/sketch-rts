# 清野、护送和建设共用选矿函数

此前三路线的经济和指挥各自按策略版本选择矿点函数。召唤路线继承 `nextExpansionMine` 的直线排序、1200 敌方基地排除和零敌军门禁；另外两条 v9 路线使用 `v9ExpansionMine` 的道路排序、900 基地排除和本军半数战力容忍。选择逻辑重复在建设、清野和护送中，候选不能明确配置三者的共同目标。

现在 `collectV6Goals` 和 `planV6Army` 接受必填的 `chooseMine`。普通策略显式传入原函数，候选三路线显式传入已有的 `v9ExpansionMine`；没有默认函数、缺失结果替代、兼容层或新内存。经济、清野优先目标和护送复用同一函数。召唤路线其余集结、敌军干扰与防守门禁保持原规则。本批运行时四个文件 +19/-13。

十二个文件共 173 个不同原生检查通过，包括旧版通用指挥、经济、二矿、枯矿替换、海外殖民、矿点护送和塔推进。四个两族／镜像新场景实际运行 1500 tick：隔树林矿的直线更近、道路超过本侧矿两倍；候选通过正常付费建成本侧二矿，零己方死亡。精确父版 `f9495d3d884f3a5a38bf6254db3ce17c70252191` 四场均未开始建矿；该父版文件树与 main 的 #284 提交 `cc82e227aa83ba48517388c1fd92df2fe8552bd9` 相同。

27 保存决策／79 条旧版指令及记忆与父版一致，冻结清单未更新。最终固定源码 Node 20 真实子路径完整客户端／服务器生产构建 exit 0。正常召唤路线同一 6000→8400 保存世界，两版均两矿、11 工人、金币与军队组成相同；十四个既有正常比赛保存决策也一致。因此只能认定局部选矿修正，不能认定本批改变了此前败局，更不能计为 1620 格或 holdout 验收胜利。
