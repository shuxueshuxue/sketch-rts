# 既有军队升级不再重复预留下一波招募金

生产队列忙碌时，已有单位购买意图会保留优先级与等待时间。bootstrap 还为下一波招募预留资金，这适合新增工厂，但同样限制了已有军队升级：足以支付高优先级研究时，因为低优先级单位生产尚未结束而推迟研究。

现在只从额外整波预留的适用范围中移除 upgrade 目标。扩建产能、工程基础设施、各生产类型预留、首个牧师、基础建设待扣资金和原优先级与老化规则保留。没有修改价格、资源、单位数值、状态结构、思考频率或冻结基线，也没有兼容路径或默认补值。运行时一项条件改变和一条注释。

113 项 SDK 检查通过。新增 24 个三系列、两阵营、镜像与忙碌/空闲对照中，高优先级研究都立即开始并按原研究时间完成；原付费招募仍出生，单位购买意图保留，零阵亡，现金与实际支出守恒。父版本十二个空闲对照和四个首个牧师场景通过，十二个忙碌场景推迟 165/180 tick。四个首个牧师场景证明其预留继续生效。

最初尝试删除整个整波预留，在同一真实 6000–12000 tick 世界、ID 和全部记忆对照中阵亡从五次增至十三次，该原型已撤回且未发布。最后限定为升级目标的版本两版均五次永久阵亡，期末武器和护甲均一级；不宣称此窗口改善作战或取得正式胜局。精确父版本结果复用此前同一基线继续运行，没有重复跑完整矩阵。

最终 Node 20 项目构建退出 0。正式 1620 格与未见种子验收仍待完成。
