# bootstrap_1：伤兵撤退道路与治疗入口

旧逻辑只检查治疗建筑的位置，随后按地形距离选择最近一座。建筑本身在敌塔射程外，其接近道路仍可穿过射程。伤兵进入治疗范围后也可能仍受塔火，却因“已经能治疗”而原地停下。

这批改动将三种度量分开：地形道路用于距离排序，原生转向点用于检查实际建筑占地，攻击覆盖用于决定道路是否可用。治疗命令走向原生移动可达的建筑外位置，检查的道路与命令的目标一致。撤退可从已有覆盖向外离开，不能先深入、再进入另一个覆盖或离开后重新进入。仍在覆盖内的伤兵继续移动，而不是停在治疗半径边缘。

敌人的显式 `move + avoidCombat` 会抑制原生普通攻击；治疗判断遵守该命令，同时保留当前可用技能和物品的覆盖。它不假定正在撤退的敌人永远不会重新攻击，每个原有决策窗口重新计算。

运行时改动限于四个模块，没有地图、种子或对手版本分支，没有改变单位数值、资源、决策周期或 CPU 门槛。相同入口按坐标合并移动命令。`mountedThreatReach` 的技能与物品部分提取为共同函数，其原有射程结果不变。

60 个两族、三种 v9、镜像站位的真实 SDK 场景覆盖穿越塔区、向外逃离、治疗范围内受击、树林绕路和友军塔：父版本 18 项通过、42 项失败；候选全部通过。另有 6 个几何检查、36 个原有治疗检查和 12 个可用法杖场景。共 263 项不同的相关 SDK 检查通过，包括原有风暴治疗交接、骑射技能与物品、岛上治疗和持续撤退。原有两个坐标断言改为实际建筑入口，存活、满血、资源开销与伤亡断言均保留。`npm run build` 通过。

正式胜率之外的局部观察：相同 tick 8400 世界及三份完整记忆回放到 9000，早期候选与父版本均为 14 个常驻非工人单位、没有新增死亡；被观察步兵分别为 102 与 82 HP。这是中途替换候选的开发观察，不计入完整对局胜率。

早期候选从正常开局完整观察 Grand Estuary 的 `v9_summoner` 对冻结 `v5 + v8`，tick 37282 原生判定获胜，保有 6 座完成基地、22 个常驻非工人单位。该局发生在最后的撤退意图修正之前，来源哈希单独保留；不将它称为最终提交验收。总损失 247 包含召唤宿主，不能等同于常驻士兵阵亡数。

转向道路包含建筑占地，个体碰撞、推挤、状态效果和移动目标变化仍由实际模拟处理。正式 1620 项地图 / 种族 / 方向 / 对手组合及未见种子验收仍未完成。详情见 `recovery-road-coverage.receipt.json` 与 `fresh-summoner-estuary-dual.receipt.json`。
