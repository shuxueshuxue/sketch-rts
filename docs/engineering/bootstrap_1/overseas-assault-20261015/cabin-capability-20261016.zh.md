# 真实满载船的船舱能力试验

固定生产源码 `ade412414d9232206f39e20f0182f0086605433c`、规则 2、184 项冻结 manifest。输入是此前未合宏观候选实际运行得到的 194400 完整 world / nextId / 三方记忆；这是换码存档上的公开操作试验，不能归为 ade 自动策略、普通开局、胜局或泛化验收。三方正常 AI、对手资源与人口始终保持，未修改单位、生命、金币或归属。

原始船载 11 人，包括三台不支持入舱的攻城槌及八名合法步行乘员。八人各占 2 份船舱额度，共 16，船舱总额 21；额度不是人数上限。`canEnterCabin` 的合法性不等于乘员已经走到门口，也不保证拥挤队列即时完成。

## 三段实际操作与一项否定

最初外部 driver 缺少 SDK trace 的 playerId/source，正常规划的两条意图进入日志后 observer 抛错，原生 step 行数为 0。该失败的 driver、日志、输出和 metadata 更正原样保留。不能把它称作船舱原生失败，也不能因尚未 step 就声称没有导入 Game 或恢复后世界完全未变。

修正 metadata 的独立重试从同一 194400 输入开始：首轮正常 P0 规划之后，仅增加一次公开 `enterCabin`，三方 AI 正常续跑 600 tick。八人都实际得到 enter 订单；40241 于 194401 入舱，其余七人在保存帧中一直排队。194415 运输 AI 改接兵地点和 sinceTick，phase 仍 loading。194610 原实物进度 age=810 > 原 800 门限，首次取消装载转 return；194611 原生卸下十名甲板乘员，七人的 enter 随卸岸转 idle。舱内 40241 被原 unload 跳过，195000 仍在船上。独立归因报告和 40 个 pre-think 的状态矩阵在 `independent-entry-attribution/`，没有把队列困难先断言为门 bug 或 AI 偷令。

从这段真正 195000 完整终态续跑 30 tick，首轮正常规划后只增加一次公开 `leaveCabin`。40241 当帧真正回到甲板；正常运输 AI 在 195015 下 unload，195016 真正上岸，生命仍 95，船载清空。不需要额外人工卸客。出舱和上岸是两项真实状态变化，不能合成舱内直接上岸。

另一条分支重新从相同 194400 输入开始，首轮正常规划后依次公开卸下三台攻城槌，再公开令同八名步行乘员入舱。四条追加意图在各自执行前合法，且都改变实际 snapshot。不是删身体或虚拟释放质量。三方 AI 正常运行 210 tick，到原 194610 卸载时点之前结束：八人于 194403、418、432、452、474、495、517、557 真正进入，末态使用 16/21；正常 AI 在 194430 自己重新装回攻城槌 34834。另两台仍在岸上，三台均 420HP。末态船载 9 人、实际 load=3073，八名舱内乘员继续计质量；它没有携带原来全部军队，没有取得收入、对敌伤害或胜利。该对照支持继续设计装载顺序，不能单独唯一归因于某一台攻城槌的某个阻塞点。

## 恢复、视觉与后续边界

全部实际窗口严格恢复完整 world / nextId / 三方记忆，1464 份生产源码与 184 manifest 前后相同。另从第一重试的 194595 冷 JSON 恢复，到 194625 的 30 tick 覆盖真正超时和十人卸岸：两个 pre-think、终态 world/id/三 mem、33 条原索引日志、0 hit、16 原事件全部相等。此闭合没有追加公开操作，但输入继承先前人工入舱，不变成自动策略成绩。

图像由对应实际保存 world 使用客户端 drawWorld 静态重绘，输入 hash 保持，未 step 或改档；不是历史动画。根亲看 194610 原队列图与另一分支 194610 八人舱内图，记录在独立 render metadata。原始源码 1464 文件和完整历史冻结 497 文件的已验证 archive 原封复制入包；不是从 main 或规则 3 重建。

自动功能尚未实施。它需要同一 ferry owner 贯穿步行乘员真实上船和入舱、机械乘员后装或合法重排、实际位置/入舱进度、舱内行为过滤、质量与额度、到站先卸 open crew 再真实出舱和卸岸。不能只增加一条 enter 意图、过滤舱内身体来假造容量或 landed，也不能降低原来军力要求。仍需验证自动任务、完整比赛、三条路线及最终未见种子；原故障容器未提交修改的恢复缺口继续保留。
