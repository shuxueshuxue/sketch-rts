# bootstrap_1：按双方道路判断营地归属

营地直线距我方基地约 900，山崖却让本方道路长过敌方基地的道路。原主力仍把它视作本侧营地，弱于敌方总军力时也会开始一段长远征。此前的进攻道路范围与逐兵清营道路检查不能纠正这一层候选归属。

主力计划通过必填 `campOnOwnSide` 选择器表达归属度量。三个 v9 家族用共享 `nearestByRoute` 找双方最近可达基地，再比较道路长度；没有陆路连接的敌方基地不参与陆地归属竞争。普通主力入口显式使用其原有直线度量。营地刷野的本侧筛选复用该选择器，没有可选参数或缺省兼容路径。

本批运行时两模块 +9 / −2 行；新增持久状态、缓存、门槛常量和寻路算法均为零。物理射程、塔覆盖、营地聚合及金矿收金范围继续采用物理距离；道路归属不表示已经模拟船舶航行或建筑绕行。

## 原生 SDK 对照

八步兵、五个真实往返矿工、敌方基地及驻扎的十六步兵，一个普通弱野怪营地。三种 v9、左右镜像、通路和山崖共十二项；每 15 tick 规划，普通 SDK 模拟 600 tick。
