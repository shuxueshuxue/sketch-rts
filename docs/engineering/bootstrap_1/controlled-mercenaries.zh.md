# 将已控雇佣营接入候选经济队列

V6 及候选 v9 的统一经济目标原来没有雇佣采购，脚本栈也未挂旧 mercenary。站在安全营地旁依然不买，不能只归因于旧模块的双敌限制。

候选为已控、清空守卫、有库存且冷却结束的营地生成 hire 目标，沿用旧普通角色上限（近战二／射手三／治疗二）、物理控制范围和队列人口计算。目标优先级 64，与混编工程兵同一档，沿用统一目标等待加权及金币／远航／医疗预留；同一种佣兵一轮只购买一次。雇佣与普通训练共享本轮人口账本，无额外采购脚本、资源或 SDK 例外。

旧 core 的三个雇佣事实函数移入独立 mercenary-model，旧调用同用此模块；三个原函数主体的规则保持相同。没有 fallback／兼容路径，冻结归档未修改。

三路线／两族／镜像十二个 500 金双敌场景，完整候选栈实际雇佣并由 SDK 扣款；另四个两族／镜像场景只剩两个空人口，多个营地和训练目标同时存在，最终只雇一人，所有订单被 SDK 接受。十六新增项加原 47 项正常混编开局、重甲／工程队列、医疗预算、旧雇佣及冲突检查，共 63 项不同原生检查通过；精确父版十六项均没有雇佣，失败。27 历史帧／79 指令及内存保持相同。

普通单机 6000 保存世界中两个雇佣营均无守卫，但军队仍在家，距最近营地约 2066；因此本批不能代表完成雇佣战略利用。后续继续验证安全营地行军和预算预留，完整 bootstrap_1 强度矩阵未完成。
