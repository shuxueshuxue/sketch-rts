# 训练需求先参与等待排序，再分配生产建筑

同一建筑生产多种兵种时，旧生成器先按基础优先级分配建筑，再对生成出的目标增加等待分。低优先级支援兵种可能始终没有目标，因而无法等待、无法获得既有等待加分。忙碌训练队列也会让需求消失；超过十秒的训练可删除未满足需求的等待年龄。

现在保留已完成生产建筑上的未满足训练意图，优先选空闲队列。队列忙碌或人口不足时保留需求与年龄，但不锁资金、不发训练指令。排序完成后，既有执行器为每座建筑每帧分配一次训练；已分配的建筑在资金判断前跳过，避免同一建筑的另一训练需求阻塞剩余建设预算。

运行时代码仅涉及两个经济模块，删除生成阶段的独立建筑占用集合及其参数传递，复用既有执行阶段的集合。兵种、数量、基础优先级、价格、等待系数、状态格式和思考频率均不变，没有默认值或兼容路径。规则 2 冻结归档不变。

83 项不同 SDK 检查及 Node 20 构建通过。新增 16 项覆盖两阵营、镜像和两套经济执行器：长队列中的支援需求保留起始年龄、在主力配额填满前完成训练；另一空闲生产建筑可立即接单；已经分配的生产建筑不会阻塞下一笔可负担建设，农场通过实际工人移动、开工和结算完成。父版本通过 12 项空闲与预算对照，失败 4 项忙碌队列场景。
