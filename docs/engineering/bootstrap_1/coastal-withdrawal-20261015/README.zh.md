上一批完整 AI 重放已证明，两艘原始战船分别在 16,521 与 31,913 tick 死于龙群与岸上弓手，重放结束世界与原比赛逐字一致。本批先保存撤离意图，避免重新攻击、维修回港打断局部脱离，并检查实际选定的岸上射击站位。该中间版本保住龙群附近的船，但第二艘仍死亡；`dragon-resume` / `archer-resume` 是该中间版本的换代码续局，不是最终源码的比赛成绩。

进一步原生操作实验从同一个 31,200 世界及策略记忆开始，双方 AI 正常运行至 31,575；之后只接管待测战船，其余 AI 照常。直接东北撤退、先倒向行驶 100 或 220 tick 再东北撤退均被击沉；向北的较小转角航线存活至 33,600，生命 464。没有瞬移、改血量或削弱岸上对手。脚本、完整世界、控制命令和失败记录均在 `diagnostics.tar.gz`。

最终实现从当前船首采样 16 个合法避险终点，排除仍处于威胁射程及缓冲内的站位，优先较小转角。撤离目标保存在策略记忆中，抵达前不被再次接敌或回港打断。`heading-resume` 的同档完整 AI 续局至 36,000：原船存活，401/464 HP；`surviving-battery.png` 是客户端真实渲染，已视觉检查。

这是有界候选搜索和终点威胁检查，不是整条撤离道路的危险最优化证明；动态堵塞和狭窄海域仍需实战证据。保船本身不等于完成进攻或赢得比赛。
