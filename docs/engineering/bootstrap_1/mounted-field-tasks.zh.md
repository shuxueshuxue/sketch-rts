# 空闲骑射的独立战斗

已有骑射独立任务只接矿线和野怪。没有这两类目标时，两名正常购买的骑射手交回普通阵型指挥，面对六名近战追兵全部阵亡。新增独立战斗任务，在现有恢复任务之后、普通阵型之前接管空闲骑射；当前刷野编队、矿线防守与原骑射任务保持各自控制权。骑射与主队分开计数，仅本帧任务真正运行后才从主队可用力量中扣除。

复用已有骑射站位、可用单位选择、治疗者优先排序与走射执行。物理射程、实际道路、同队骑射正在面对的追击分别处理；可以沿道路加入同伴的战斗。新增 field 是单次微操输入，不写入存档；唯一新增缓存按快照和玩家保存本帧分配，零新增持久结构和字段。没有默认、兼容、数值改动或思考频率改变。

18 项真实 SDK 场景覆盖三路线、镜像，以及普通步兵无升级／普通步兵付费速度一级／灰烬近战付费速度一级。两名骑射真正花费 300 金；有升级的场景正常支付 185 金并等研究完成，始终使用正常初始 500 金。六名追兵各自选择最近的活骑射追击，最终全部被击杀；友军零受伤、两个骑射都存活。公共 #357 对完全同一测试源码 0 通过、18 失败，原版实际出现 224 伤害、两名骑射死亡、六名追兵仍存活。场景没有改兵种属性、注入玩家升级或额外金币。

初版组合检查发现抢刷野成员、只运行主指挥的场景提前扣掉尚未执行的任务成员，导致矿工损失；已修正本帧分配与任务优先级，相关 61 项通过。原骑射自由单位场景只更新了执行器名称，血量、编队、人口和花费检查没有放宽。实验性的瞄准距离改写与持续移动打法降低了击杀效率，均未进入本批实现。

这是现有骑射的执行修正。此前实际 Pineshade 骑士败局在四个保存节点都没有骑射手，不能拿这项小场景结果宣布全局获胜；下一项继续检查招募是否能识别暴露近战部队。完整 1620 格与未见种子仍待完成。最终相关检查与构建证据见同目录 receipt。
