# bootstrap_1：混编骑射手地形压力试验（未发布）

压力场景为八名普通骑射手、四条普通红龙、真实狭岸浅滩，同一清营任务同时执行 600 tick；三个 v9 家族及镜像方向均测试。任务记忆由 SDK 场景初始化，用于暴露密集混编的控制问题，不代表普通清营分配器会自动派八人刷一个营地。检查仍要求八名骑射手无伤、真实命中、零永久损失与花费。

线上 #307 的正向局部观察中，两名骑射手各挨三次 42 伤害后死亡。第一处误差是沿浅滩逃跑仍按标称 90 速度估计；第二处是全方向危险时，避开队友的排序优先于逃离敌人的距离。共享地形移动进度和危险排序修正后，正向三家族均无伤，镜像三家族各受一击 42，全部八人存活。再计入普通移动停止容差后，仍是 0 / 42 伤害，未满足六项全部无伤要求。

不改攻击、速度、血量、资源或检查门槛。未发布骑射手运行时的这些候选，也未将压力局部结果算作完成清营或新正式胜局。基础移动预测在普通工人 SDK 中验证了 0.4 / 1 单位误差，另用于已取得八个真实炮弹场景改善的地形躲避批次。

继续调查互相拥挤、路径穿越其他守卫火力与下一步出口。bootstrap_1 的陆地防守、全局扩张、物品与星级保存、正式矩阵仍继续。

加长出口候选另观察完整清营过程，未改变资源、属性、守卫或费用。单骑在两个方向跑到 12000 tick 仍有四条龙存活，只有 44 / 45 次真实命中；两方向均无伤无损，但没有完成单骑清营。八人组分别在 5537 / 5174 tick 清空四条龙，零永久损失，累计仍受 126 / 90 伤害。公共 #309 对照为 8296 / 5206 tick 清空，受 426 / 216 伤害，损失 3 / 1 名骑射手。

因此，600 tick 六项无伤不能代替完整清营的无伤验收；八人组改善也不能证明单骑已能清空强营。以上候选均未 PR 或部署，未增加正式矩阵胜局。记录保留，以免重复尝试已经观察到回归的组合。

追加完整清营检查（#311 之后）：

实际移动预测、普通撤步补停止范围、危险排序与并行开火窗口组合，使正常单骑分配在三个家族及镜像六项中全部无伤清空四条红龙，自然达到三星；全部 240 次真实命中，零花费、零永久损失。详细双向观察为 33264 / 32485 tick，仍约需 27 分钟。#311 在相同 48000 tick 窗口剩两条龙、127 次命中。八人完整清营仍有 42 / 138 伤害，零永久损失；600 tick 压力无伤不能代表八人全程无伤。

相关 110 项回归首先发现付费升级后的治疗鱼人营地清不完。原因包含升级速度超过骑射手原有瞄准位移额度、瞄准重置，普通治疗抵消射击。按真实逐帧步长限制战斗撤步后该场景恢复无伤清完，但完整 153 项骑射检查中仅 146 项通过；准备装备守卫、冲锋内圈、墙角脱身与已耗冲锋退出共有七项失败。#311 对照的这八项既有场景全部通过，因此不是基线故障，也没有放宽断言。

随后同时提供瞄准小步与完整脱离、在安全时优先保留瞄准的组合，只通过选取十三项中的七项；六项仍失败。使用普通可达终点投影并恢复原开火时长的组合，选取十六项中通过八项，且单骑四红龙清营再次停滞，撤回。当前保留此前有完整清营证据的源码候选供继续诊断，仍有已知回归，未 PR、未合并、未部署。没有地图/种子/对手版本分支、属性或资源增强、CPU 预算修改及防御性兼容路径。

这些都是局部 SDK 观察，新增正式胜局仍为零。主力扩张、道路归属、雇佣兵、岛矿、召唤与农民塔攻、骑士和工程武器等其他路线继续。


## #320 引擎下的撤退步长候选（未发布）

骑射原有带冲锋目标的瞄准窗口不能统一替换为普通追击窗口。同步当前 #320 引擎后，保留原窗口和身体避让优先级的地形／瞄准位移候选，在 12 个既有真实 SDK 场景中通过 7 个，失败 5 个：两项法杖营地准备、一项冲锋内圈无伤、两项悬崖撤离。结果 `/tmp/bootstrap_1-mounted-preserved-windows-sdk.json`。没有发布这些候选，也没有修改旧测试判定或单位数值。

此前短步／减半到达距离试验使用旧 #312 引擎，分别为 3/10 与 5/12 通过；不能作为当前引擎结果。同步后的身体避让优先候选通过 6/12，却破坏冲锋内圈首次射击。原始文件及输出保留于 `/tmp/bootstrap_1-mounted-*-withdrawn.ts` 和对应 SDK 报告。结论仍是需要同时证明逃生与持续射击；单独提高刷营速度不够。
