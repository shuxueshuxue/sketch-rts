# 从能执行的目标中选择最弱防守

旧指挥流程先取防守需求最低的基地，再检查主基地进攻规模、陆路范围和敌军响应。第一个目标不满足原远征门槛时，其他能打的基地未被考虑，军队因此停留。

共享规划器现在生成原顺序的候选，把原进攻判定交给明确的选择器。通用指挥器仍只判定第一个目标，保留其既有战术；bootstrap 的三个系列沿原防守排序逐项判定，找到能执行的目标就停止。使用既有陆路范围与到达时间、原战力、原响应比例、原等待和重组规则，没有放宽门槛、改变单位数值、资源、持久状态、思考频率或加入地图条件。运行时代码涉及两个模块，没有默认值或兼容路径。规则 2 冻结归档不变。

167 项不同 SDK 检查通过，含原通用指挥器、前排暴露、地形道路、防守、阵型和行军。新增 24 个场景覆盖三系列、两阵营、镜像与有无反应军队：远方最低防守目标不适合当前远征时改取近处可执行目标；无反应军队时仍优先取原来的最低防守目标。实际移动后目标生命减少、八名士兵均存活、没有资金消耗。父版本通过 12 个无反应军队对照，失败 12 个远征受阻场景。

Node 20 项目构建通过；最后将选择器限定到 bootstrap 后，另外对最终两个模块、SDK 场景与其依赖使用同一项目配置做严格类型检查，通过。完整新开局败局的相同 12000 tick 世界、ID 与全部控制器记忆分别原生继续到 14000 tick，两版均五次永久阵亡、期末十二名常驻军队，最终世界相同。本次不宣称该窗口改善战斗结果或取得正式胜局；1620 格官方地图与未见种子验收仍待完成。
