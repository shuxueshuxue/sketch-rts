# bootstrap_1：瞄准循环直接读取标量

`aimAt` 每次读取 `aimingProfile`，只使用其中的速度和位移容差，却创建一个短命对象。直接读取相同标量，速度表达式提取为一个函数；公开的 `aimingProfile` 仍返回原来的描述。没有新增缓存或状态，资格判定、运算顺序、规则默认值和瞄准行为保持一致。

验证环境为 Node 20.20.2。瞄准、移动失效、老兵、灰烬射手、船舱和单位更新七个现有测试文件的 100 项检查全部通过。从真实 Greystone 对局第 12000 tick 的 85 个单位存档继续 900 tick，父提交与修改版的 30 个世界快照逐字段相同；联合 SHA-256 为 `9d85c394dc5aaf821c3c4da0db5186c39406bcc3befd14640454884deddd5680`。两边均调用 `aimAt` 106 次，其中 97 次需要瞄准；该路径的 profile 对象创建从 97 次降至 0 次。

这是分配次数与行为一致性的证据，不代表已经达到发布所需的 CPU 预算。PR #260 原提交的两次 CPU 检查分别为 12196.683 和 12120.796 ms，均超过 bareDuel 的 12000 ms 门槛；其他两张地图通过。保持原预算和完整模拟时长，修改后重新接受同一发布检查。
