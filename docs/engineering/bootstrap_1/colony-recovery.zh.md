# bootstrap_1：已占岛屿的本地恢复

问题来自真实无对手开发过程，而非地图特判：伤兵在殖民地，两个已训练的治疗单位留在战舰甲板上。陆军医疗无法跨海步行；海军又拥有登陆部队的任务，普通陆军治疗建筑恢复命令不能接管这些单位。

候选只在已经完成的海外基地所在陆地有危重、可治疗的永久单位且没有本地治疗建筑时提出正常付费建造目标。位置围绕本地伤兵，工人按道路到达时间选择，危险和建造合法性沿用现有几何规则。海军复用 `postRecoveryAssignments` / `postRecoveryCommands`，恢复到满血后释放任务。没有新增策略状态、地图/种子/旧版本分支、单位属性或资源奖励，也没有兼容或 fallback 路径。

## 验证

- 12 个真实 SDK 场景覆盖三个 v9、两族和镜像地形；旧控制器 0/12，新候选 12/12。既有治疗单位在无法步行到达的另一块陆地，新建筑由普通工人付费完成，伤兵最终满血，永久单位无死亡；记录实际交金并验证金币账目。
- 连同登陆恢复、无医疗撤退、治疗建筑连续恢复和撤退目的地连续性，共 104 项通过。
- 63 个普通旧控制器状态、167 条命令及完整策略记忆逐项相同。构建通过。
- 同一 sapphireArchipelago / Grove / v9_summoner 无对手实局的 18000 tick 全世界和策略记忆重放至 21000：旧控制器的步兵仍为 21/145 HP，候选恢复至 145/145。双方都在 19290 发出第三基地建造命令，结束时三个完成基地、两个有剩余矿量的基地、四名野怪击杀；双方该窗口均无原有永久单位死亡。

这是局部开发与恢复证据，不是从零开始的全图无损刷野、1v2 胜利或正式全地图验收。前一版按基地固定偏移摆放治疗建筑曾拖慢第三基地；最终位置改为本地伤兵中心后，同档对照的开工时间相同。采购等待、工人道路、建造和多轮治疗均计入 SDK 检查的完整时间窗口。

公共 PR #321 的既有 CPU 门槛仍未通过：裸图 14626.605 ms（门槛 12000），ladder 17379.968 ms（门槛 16000）。本候选不宣称解决该问题，也不修改门槛。
