# 局部移动度量与登陆船体净空

## 问题与改动

骑射手登陆后，原控制器只验证地形可走和陆地单位的圆形占位。它可能选择穿过仍停在岸边的真实船体的退路，实际移动被船体截断，而守矿单位继续接近。岸边浅水和泥地也会使同样的直线长度花费更多时间。

本次只修改 `mountedEscape` 的候选评估，并增加两个共享度量函数。自动渡海、矿点任务分配和舰队协同没有包含在本次提交中。冻结策略、兵种数值、资源、CPU 限额均未修改。

| 需要回答的问题 | 使用的度量 | 边界 |
| --- | --- | --- |
| 武器或范围技能能否覆盖目标 | `strikeGap`、实际技能半径及交集 | 不用道路距离代替攻击距离 |
| 两点地形路径有多远 | `walkingDistance` | 地形加权道路长度；不含实时单位及建筑绕行 |
| 各单位何时到达同一目标 | `routeArrivals` / `routeTravelTicks`，传入各自速度 | 不把不同单位的速度混用；不代表船舶风向、转向和加速后的真实 ETA |
| 两点是否属于同一片陆地 | `sameGround` | 连通性，不是远近排序 |
| 下一小段直行需要几 tick | 新增 `groundSegmentTravelTicks` | 逐 tick 读取引擎地面速度倍率；调用方保证正速度与可走段，不含状态减速或身体绕行 |
| 直线匀速运动是否穿过扩大的威胁圆 | 新增 `segmentAvoidsExpandingDisk` | 检查整个时间段的二次距离函数，包括中途交叉和切点；不是敌人路径预测 |
| 陆地单位这一段移动是否撞船 | 复用引擎 `constrainGroundShipStep` | 使用实际船体与扫掠圆盘，不能用船中心的圆形代理 |

控制器使用局部地形耗时估计威胁的扩张时间，并将扫掠结果用于候选排序。该排序采用匀速段预测，不声称准确重演一段路径上变化的速度、敌军路线或状态效果。下一步转向空间保留原本的检查长度，并加入真实船体检查；无目的地逃逸时比较地面速度倍率，向既定目标移动时继续优先接近目标。

运行时增加两个共享函数，无新增记忆状态、地图分支、对手版本分支、资源或数值加成，也没有 fallback 或兼容层。

## SDK 验证

基线为公开 main `6a11a52d4f649134e9335ab7d90219c3a120cb66`。新场景用普通 SDK 指令完成真实上船、航行和卸载，随后仅启用各版本已有的 `mountedTasks`。骑射手与运输船使用正常数值，岸上是两个正常 ogreWarrior；不手操战斗、不替换移动函数。

| 检查 | 基线 | 修改后 |
| --- | --- | --- |
| 三种 v9 × 两侧镜像，船体旁清除两个守矿单位 | 3 通过、3 未完成清除 | 6 全部完成，骑射手和运输船满血、0 受伤、0 阵亡、0 花费 |
| 草地、浅水、泥地和草地进入泥地的局部耗时对照实际 SDK 移动 | — | 差值限定在原移动指令到达半径造成的提前结束范围 |
| 中途交叉、逃逸、静止／较慢运动、精确切点 | — | 4 通过 |

六个新场景证明的是登陆后的底层微操，不是自动运输、全图扩张竞速或对局胜率。既有付费装备、技能、撤退和清营地场景继续作为回归检查，不能用这个局部结果替代 bootstrap_1 的正式全地图矩阵。

曾尝试把转向空间扩大到整段射程，真实花岗岩守卫回归场景出现六次清矿超时；对应基线六次全部通过。6000 tick 局部记录中，射击从 81 次降到 68 次，双方均无伤。该候选已撤回，没有放宽原本的 24000 tick 清除要求。
