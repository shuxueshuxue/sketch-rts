# 登陆船体净空与距离度量边界

骑射手登陆后，原控制器只验证地形可走和陆地单位的圆形占位。它可能选择穿过仍停在岸边的真实船体的退路，实际移动被船体截断，而守矿单位继续接近。

本次只给 `mountedEscape` 的候选移动段和下一步转向空间加入引擎已有的 `constrainGroundShipStep` 检查，使用实际船体与单位扫掠圆盘。原评分、转向检查长度、兵种数值、资源和 CPU 限额不变，无新增记忆、地图／对手分支、fallback 或兼容层。

| 需要回答的问题 | 使用的度量 | 边界 |
| --- | --- | --- |
| 武器能否覆盖目标 | `strikeGap` 及实际技能几何 | 不用道路距离代替攻击距离 |
| 两点地形路径有多远 | `walkingDistance` | 地形加权道路长度；不含实时单位及建筑绕行 |
| 各单位何时到达同一目标 | `routeArrivals` / `routeTravelTicks`，传入各自速度 | 不把不同速度混用；不代表船舶受风、转向和加速后的真实 ETA |
| 两点是否属于同一片陆地 | `sameGround` | 连通性，不是远近排序 |
| 陆地单位这一段移动是否撞船 | `constrainGroundShipStep` | 实际船体与扫掠圆盘，不能用船中心的圆形代理 |

## SDK 验证

基线为公开 main `6a11a52d4f649134e9335ab7d90219c3a120cb66`。新场景用普通 SDK 指令完成真实上船、航行和卸载，随后仅启用各版本已有的 `mountedTasks`。骑射手与运输船使用正常数值，岸上是两个正常 ogreWarrior；不手操战斗、不替换移动函数。

三种 v9 × 两侧镜像共六个场景。基线三个通过、三个未完成清除。修改后必须六个全部清除，骑射手与运输船满血、0 受伤、0 阵亡、0 花费。已有原始地图、付费装备、技能、撤退和四花岗岩守卫场景保持原断言，其中原先未进入部署流程的四守卫场景也加入部署检查。

这些场景证明登陆后的底层微操，不代表自动运输、全图扩张竞速或对局胜率。自动渡海、矿点任务分配和舰队协同没有包含在此次改动中；冻结基线的全地图矩阵与未见种子验收仍未完成。

## 未发布的移动评分实验

同时尝试了逐 tick 地形耗时和扩张威胁圆的扫掠模块：草地、浅水、泥地及混合地形耗时、几何交叉与切点检查通过，但上层评分未通过全部真实 SDK 回归，不能发布。

将转向空间扩大到整段射程导致六个四花岗岩守卫场景清矿超时，基线六次全部通过。6000 tick 局部记录中，射击从 81 次降到 68 次，双方均无伤。恢复原转向长度后，这六个场景重新通过，但原始 Grand Estuary 花岗岩营地出现骑射手死亡：163 个检查中通过 162 个。该评分及新增模块全部保留在未发布实验中，本提交仅包含独立的船体净空修复，没有放宽回归断言。
