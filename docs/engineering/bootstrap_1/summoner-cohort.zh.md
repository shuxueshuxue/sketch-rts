# 召唤军团的集结与支援站位

主军的集结指令将前排送往敌方基地外，原后排模块在缺少近处掩护时却将召唤师送回主基地。已经分配给该次进攻的召唤师现在使用主军同一个集结点；医疗、驱散单位和未分配的新兵保留各自的行动范围。进攻与集结都只把宿主前方的近战单位当作推进掩护。

`planCasterScreen` 的单位清单和近距离站位参数改为必填，由调用者确定控制范围。共享算法内部的全军筛选从一处降为零处。`v6AssaultStagePoint` 同时供主军和召唤师使用，集结距离沿用现有数值。新增序列化状态为零；资源、兵种属性、思考间隔和冻结策略原样。

支援单位使用已有的近距离站位，使治疗和驱散能进入技能范围。原生召唤突袭场景中，两个阵营、两个方向均保住支援单位和六名护卫，并通过真实技能击杀精灵。同场景旧版本也通过；首个驱散从第18帧提前到16帧，林地护卫伤害同为156，灰烬877→871。这是有限的局部差异。

170项相关检查与完整生产构建通过。144个旧策略主军、后排命令和记忆对照完全一致。四个同输入的集结场景中，旧版召唤师距离集结点仍约三千单位，新版四名宿主均进入300单位内，四名医疗和驱散支援保持原驻地并存活。清场拆除优先级仍通过四项原生检查。

正常资源开发对局的36000至48000续局仍超时，累计永久损失38，与已有完整旧轨迹相同；剩余敌方永久部队26→21，己方军队同为23、工人7→6、金币35→93。此处比较已有完整轨迹，未重新执行完整父版本续局；不据此声明整局因果收益或正式胜率。两个早期集结原型分别损失医疗／驱散单位，已保留为实验。一次短窗口的死亡偏移31已按起始快照36校正，原始文件保留。
