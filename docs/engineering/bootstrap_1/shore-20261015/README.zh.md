## 现场与普通操作

父版本正常开局 Sapphire Archipelago / Grove / side 0 / v9_archer vs 冻结 v5 的 48,000 tick 世界中：

- `unit-p0-warship-1071` 自动追击 `guard-1-0`，目标中心距离约 380；最近水域点距离约 311。
- `unit-p0-warship-1120` 自动追击 `satellite-guard-1-0`，目标中心距离约 394；最近水域点距离约 293。
- 两船实际只有一门舰艏炮，射程 312。旧 `canReach` 用水域点判断，未验证船体、炮座和射界。两个目标在有限的船体/炮座姿态扫描中均未找到合法射击位置；这不是数学上的不可达证明。

`stuck.png` 来自真实客户端 Canvas 渲染。恢复完整世界后，分别向最近合法船位发普通移动指令，运行 1,800 tick，再对原目标发显式攻击并运行 1,800 tick。两船均移动成功，但目标生命保持 600、350，船自身未损血。没有传送船体、加射程或删除地形。

候选原生续局保留已有命令，不调用 AI：两船解除自动追击并正常结束旧目的地航行。这里只证明解除追击，不能把随后闲置算作战略成果。

## 实现

`src/shared/shore-fire.ts` 提供可复用的岸上射击站位查询。它检查当前可用火炮、实际炮座、射界、最小射程、老兵射程和完整船体，并检查水域连通。搜索固定的 48 个方向、4 层距离；每个船对象最多缓存 16 个目标，装备、目标位置、地形等变化会重新计算。没有把移动中的友军占位当成永久不可达。

这是自动任务选择的有限搜索，不是完整航线可达性证明；极窄炮位可能漏检。玩家显式攻击保留原行为。机械自动索敌和当前 AI 的舰队选敌共同使用该查询，避免策略放弃目标后机械索敌立即重新抓回。

继续实战后补充 `src/ai/policy/coastal-risk.ts`：将能攻击船体的岸上军队纳入舰队派遣判断，按现有兵力评分和路线各自的进攻余量评估附近支援，排除远处军队和舱内乘员。弱势时不继续驶往该岸边站位；已经接近火力范围的舰船通过普通移动指令退开。没有提高己方数值、降低对手强度或改变伤害规则。

一个旧测试直接把工人对象改名为战船，却没有安装火炮。本批将其改为原生生成战船，仍要求同一个近岸工人攻击行为，没有降低预期结果。

固定最终源码从普通开局重新运行至既有上限 48,000 tick。`verified-match.tar.gz` 保留全部世界、nextId、策略记忆与购买记录，`source-hashes.json` 标识源码。结果仍超时，双方基地未被消灭。

最终运输船、两艘战船和巡逻艇均存活；一艘战船剩余 417.77/464 生命，另一艘满血。更少野怪损失与舰船存活是局部成果，人口较低、现金积压、没有对敌击杀表明资源转化和进攻仍未完成。没有运行高成本全矩阵，没有未见种子或双敌泛化通过声明。

失败实验同样保留：

- 只修射击筛选的完整原型保存在 `final-match.tar.gz`（文件名是实验当时的命名，并非本批最终版本）。该局只剩一座基地、损失 5 个单位，统计归因均为野怪。它还包含后来撤除的额外野怪追击边界检查，不能用作最终版本成绩。
- 从原型 12,000 tick 世界停止 AI 重新派遣、仅保留命令继续运行，第一艘战船到敌岸后约 92 tick 被敌方弓手击沉。这个实验说明旧目的地的危险，不是原型自动整局的死因证明。
- 加岸上兵力判断后的同一存档 AI 续局至 16,800 tick，两艘战船均满血留在安全水域，见 `coastal-resume.tar.gz`。这是中途换策略的诊断续局。
- 开发期间两个未完成的整局尝试已主动停止，其快照、日志保留在 `diagnostics.tar.gz`，没有计作完整比赛。复核撤掉了意外扩大野怪追击边界检查范围的改动；最终整局保留原追击边界语义。
- 首次构建发现缓存可选字段不满足严格 TypeScript 类型检查，修正后重新构建成功。原始失败和通过日志均保留。

## 验证与下一项实战问题

最终 12 文件、179 项聚焦测试全通过，覆盖实际近岸开火、远岸目标退出、显式命令保留、火炮损坏、目标移动后重选、岸上强敌撤离、附近与远处支援、海军原生战斗、追击、登陆、三路线舰队任务归属和冻结规则入口。最终 `npm run build:production` 成功。六条冻结 v5/v7/v8 指令流与状态摘要仍与原冻结引擎相符；这不表示当前引擎的比赛轨迹应与冻结引擎相同。

沿实战继续调查了两项未完成问题：

1. 原型登陆存档中，船和登陆工人在树林旁互相阻挡。三个普通离岸移动目的地均不能让船移动；真实碰撞探针显示离岸转动首先碰到 `unit-p0-worker-1`。让该工人先沿岸移动 80 或 160 单位，运输船便能自行驶离。`landing.png`、`landing-contact.json`、`landing-foot-results.json` 及脚本保留该回归场景。尚未将这项手操变成自动登陆通道清理，不能声称已修复。
2. 最终完整比赛 48,000 tick 的唯一经济目标是 `farm`，优先级 115、成本 120，但最后一次购买停在 42,870 tick。工人已迁到其他岛屿，原主基地无工人；供给设施仍使用 `safeMainBuildPoint`，而 `availableV6ConstructionWorkers` 要求同一陆地区域。这是下一项需要用实际目标签发和正常续局验证的建设选址问题，不能简单归因于没钱或把现金积压称为优势。
