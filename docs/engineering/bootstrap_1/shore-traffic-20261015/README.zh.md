# 岸兵实体约束进入船舶航路规划

父提交 `c07247db`，独立承接分支、规则 2、已验证冻结策略与普通资源人口不变。原工作区未提交改动仍不可恢复。

## 问题与修复

上一批 120,000 tick 世界的运输船长期执行回港命令，但身体没有位移。碰撞查询确认：地形与只考虑船舶的交通查询都允许转向，连续碰撞却在转向起点撞到岸兵；沿船首倒退可以脱离。上一批保留了八组普通移动命令的失败实验和具体接触单位。

现在静态实体查询同时包含合法陆地上的岸兵（排除甲板乘员），`shipRouteTraffic` 将它与船舶交通约束组合，供离岸、分帧搜索、风向改道、路径跟随修正及队列转角使用。分帧任务冻结附近岸兵的位置和形体，恢复时仍用同一输入重建搜索；交通变化键也包含岸兵，避免空路径忽略其离开。实际碰撞体、伤害、单位属性、金钱与移动规则未削弱。

只修即时离岸的初稿能释放原存档运输船（1,200 原生 tick 位移 944.51，无新增死亡），但缩小后的测试仍发生友军擦碰，定位到后续航路细化遗漏同一约束。该初稿结果只在 `native-probe.log` / `traffic-*.json` 中作为过程诊断，不能归属最终源码。最终实现补齐相关规划路径后，双镜像测试均无损离岸。

## 回归与存档

- 裁剪真实地图地形为 64×64 格、保留两名碰到船首的岸兵，不用瞬移或缩小碰撞体。精确父版本两个镜像均原地不动，最终候选两者均驶出 500 格以上，船与步兵生命完全不变。
- 中途恢复后，最终完整世界和 nextId 与不中断运行一致。测试的 `scriptedVictory` 是场景运行配置，恢复实例也显式设置；初次遗漏它造成的测试失败已保留，未改引擎来迁就测试。
- 十文件共 114 测试：113 通过，1 个已有失败。失败为 `ship-maneuver-recovery.test.ts` 中要求参考路径恰好一个点，而实际返回两个点；精确父版本单独运行同样失败，原断言未改。见 `parent-maneuver.log` 与 `tests-final.log`。
- 生产构建与类型检查通过。源码哈希固定本批归属；长局启动后只修正测试恢复配置，运行时源码没有变化。

## 比赛作用与边界

从上一批 120,000 tick 完整世界、nextId 和双方策略记忆开始，精确父版对照至 126,000，候选继续观察至 144,000。不是从零比赛，也不能将观察窗口结束冒充终局。

在 122,400 tick，候选运输船已到 (6344.20,3878.62)，仍保持原生命；父版停在 (3238.85,4353.06)。候选随后正常回港维修，再去另一个已开发岛装载殖民队。`transport-loading.png` 是 126,000 tick 的真实客户端渲染，已视觉检查，船上确有装载的部队。最终结果见 `results.json` 和续局归档。

完整 bootstrap_1 的规定对手组合、官方地图、未见种子和终局胜利验收仍未完成；不会因局部无损离岸或人口增长宣称达标。

已有失败的追加诊断：在隔离父工作树内，只把“恰好一个参考点”改成“终点确实是目标”的临时副本继续执行，后续倒退距离断言也失败（35.01 > 20）。因此它不只是可以直接删掉的格式断言；本批没有更改原测试或宣称该恢复场景已解决。临时探针与日志保存在诊断包，不作为通过证据。

范围限制：分帧任务本批冻结的是附近单位，仍未携带建筑视图，沿用接续审计已经记录的限制。普通同步重规划与实时候选修正能查看建筑，但不能据此宣称所有跨帧建筑阻挡、动态拥堵和窄岸部署都已解决。

最终续局已实际跑完至 144,000：八座基地、175/184 人口、67 非工人单位，现金 62.91，累计花费 21,238；己方单位损失 0，敌方累计损失 3，清理野怪 6，无建筑被摧毁，无胜者。运输船存活且满血 392/392。相对 120,000 起点，新建一座岛上基地、完成工人迁移并恢复收入，但没有解决最终进攻。
