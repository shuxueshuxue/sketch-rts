# 登陆骑射任务的归属

普通海军此前占用所有离开主基地陆地的战斗单位。骑射模块虽然可以选择岛上的营地，完整规划器却过滤掉其指令；原版六个三路线／镜像 SDK 场景在24000 tick没有射击，四只普通石人全部存活。

`navalUnitIds`现在显式接收泛化登陆归属的选择函数。普通策略明确保持原选择；bootstrap只释放已有骑射目标的登陆单位，真实海军服务、清理登船通道、舱内乘员、登船和预留船员继续先占有单位。三条v9路线均可操作实际获得的骑射手，不增加骑射生产配额或购买优先级。

患者和治疗兵也保持海军恢复归属。归属与实际恢复指令共用`recoveryAssignments`：同片陆地的可治疗永久伤兵，按真实生命和下一次治疗前的敌军攻击判断，不增加第二套门槛。初版只释放骑射时，六个治疗对照虽然有follow指令，后来仍被mountedTasks攻击覆盖，伤兵距治疗兵305；最终候选六场距治疗兵71、保留follow、实际恢复20→75生命。该对照没有死亡和消费，不能算战斗胜利。

运行时四文件+25/-10、零新持久状态、零规则或阈值；海军选择函数为必传参数，没有缺省、兼容包装或不可达道路的替代选择。道路目标继续使用`nearestByRoute`／`walkingDistance`，射击、施法和威胁范围继续按真实战斗几何判断。

## 验证范围

新六场清营检查使用完整规划器和普通SDK命令，一名未升级Grove骑射手对四只普通重甲石人，三路线／镜像，要求全部击杀、零伤、零损失和零消费。最初6400 tick六场未清完，失败保留；沿用既有mounted-micro清野检查的24000 tick观察上界后，归属候选23779／23971 tick清完，共312次实际命中，没有修改原有检查的窗口、CPU预算或伤亡断言。约二十分钟仍然低效，本批只解决任务被遮蔽，不宣称提高射击效率。

另18场验证登船、已有船员预留和治疗优先级，实际执行命令并推进模拟。最初六个预留船员场景没有让新船经过首帧，航行状态未初始化而失败；修正测试设置，正常推进首帧后18场通过，没有修改运行时船舶初始化规则。
