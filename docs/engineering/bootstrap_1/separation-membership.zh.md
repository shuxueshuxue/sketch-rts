# bootstrap_1：复用碰撞分组的已核实坐标

PR #322 的 `4809804` 在原 CPU 门槛下失败：裸地图 14186.959 ms > 12000 ms，ladder 17225.228 ms > 16000 ms。此前 #321 已通过检查并部署。默认对局使用 v2；新岛上治疗和撤船策略不在这条路径上执行。两份运行时的 1200 tick 初始局部回放中，29 条指令、完整内存、每帧完整世界和实体计数器相同。这只排除了该窗口中的行为变化，不能解释整场耗时。

对真实后期局部状态采样后，减少碰撞分组中的重复工作：

- 记录已核实的原始坐标。坐标不变时无需重新计算格子；在格内移动后更新记录，碰撞窄阶段仍读取当前坐标和半径。
- 使用模拟循环已经核实的 native grounded frame，省去同一批单位的重复船舶和舱内检查。训练、召唤、恢复、观察者和自定义工厂仍遵循现有帧判定。
- 数组按当前有效成员数保存；死亡、退出和恢复继续清空分组成员。桶、碰撞对和访问顺序不变。

与 `4809804` 相比，普通初始对局 1200 tick 的格子计算 3844 → 566，船舶/舱内检查各 13398 → 0；真实战场 300 tick 的格子计算 23085 → 14605；真实岛上状态 300 tick 为 42192 → 1541，船舶/舱内检查各 26197 → 26197；真实后期默认对局 1200 tick 为 111065 → 45919，船舶/舱内检查各 55638 → 0。

四段回放均比较每帧完整世界和实体计数器。初始对局还比较每帧指令与完整 AI 内存。计数是实际重复计算的减少，不是整场 CPU 改善比例；发布仍要求新提交通过原有 CPU 检查。没有复跑失败提交或放宽阈值。

冻结 v5/v7/v8 的 54 个策略文件哈希保持不变。全部正式地图的单人/双人对手矩阵和未见种子验收仍未完成。

最终本地验证：614 项相关 SDK 检查通过，TypeScript/Vite 构建通过。CI 和部署检查保留了碰撞、船舶运动和舱内移动的现有边界用例。
