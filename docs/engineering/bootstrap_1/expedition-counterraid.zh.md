# bootstrap_1：远征窗口内的矿线反击

原判断只计算能在主力抵达之前赶到进攻目标的敌军，遗漏了同一时间内能袭击我方收入的另一支敌军。Grand Estuary 的正常射手开局中，四名士兵因此去攻打远处扩张，随后援军零散进入敌塔射程，矿线被另一名对手摧毁。

只修改 bootstrap 调用的地面应援兵力函数：以每名主力的道路行军时间确定抵达窗口，同时计算敌军到目标及我方仍有矿可采的已完成基地的道路时间。两类敌军按单位对象去重，避免把同一兵算成两份。矿与基地的收金范围仍是物理距离，遵循共享采矿规则。复用现有地形速度、单位速度和距离场，不增加寻路缓存、地图/种子/对手分支、资源或属性。

这不是实际移动路线的碰撞模拟，也没有把塔附近视为一定能击退敌军；静态塔覆盖和正在执行的接敌、伤兵、运输任务沿用现有规划器。它修正出征前的威胁漏算，后续接敌仍需继续迭代。

## SDK 道路对照

普通四人混编队、五名正在采矿的工人、两名敌方玩家；另一支四骑士队伍在远处守位。只改变道路地形，资源、速度和战力相同。完整执行 300 tick 普通模拟及每 15 tick 的三个 v9 家族规划，包含左右镜像，共 12 项。

- 通路直达矿线：主力留在基地附近，没有提前进攻。
- 相同直线位置被山崖迫使绕远：主力实际离开基地，继续攻击无人防守的敌方扩张。
- 两类均有真实矿工交金，资源守恒，零花费、零伤亡。

#309 main 在六个通路场景中全部提前出征；六个绕路控制场景仍通过。候选十二项通过。敌骑士在此控制场景中守位，不能把它称为已经击退反击或新增胜局。
