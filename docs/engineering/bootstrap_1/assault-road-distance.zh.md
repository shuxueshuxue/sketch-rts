# bootstrap_1：按道路距离区分近处与远处进攻

目标与基地直线相距 900，隔着一段山崖却要沿道路绕行数千。原主力规划器仍把它视为近处目标，跳过远征兵力准备；能在绕路期间赶到目标的敌军已经计算出来，却没有用于阻止出征。

共享 `routeWithinDistance` 表达可达道路是否在长度预算内，复用 `walkingDistance`。bootstrap 的三个 v9 家族将它用于目标与工作基地的距离判断；普通主力入口通过必填 `withinHomeReach` 选择器保留原物理距离规则。既有地面威胁范围查询也复用同一道路范围度量。没有可选兼容参数或缺省行为。

各度量的职责保持清楚：

| 问题 | 度量 |
| --- | --- |
| 武器能否打到、塔是否覆盖、基地能否收金 | 物理直线距离 / 交战边缘间隙 |
| 能否走到、哪一个更近、是否在道路长度预算内 | `walkingDistance` / `nearestByRoute` / `routeWithinDistance` |
| 哪支队伍先到，地形慢行要多久 | `routeTravelTicks` / `routeArrivals` |
| 一段移动实际推进多少 | `groundMoveForecast`，包含地形速度与移动停止范围 |
| 道路是否穿过别的营地或火力圆 | `routeClearsDisks` |

道路长度不包含地形速度折损；行军时间包含地形速度和单位当前速度。道路范围不是建筑碰撞模拟，船舶的常速道路估计也不包含风向、加速和转弯。本批没有新缓存或寻路算法，也没有改距离门槛、费用、属性、资源或冻结档案。

## 真实 SDK 对照

四名普通混编士兵、五名矿工、敌方出生基地与直线距离 900 的扩张；另一支八步兵队伍距离扩张较远，能够在山崖绕路期间赶到。敌兵守位，仅用于控制位置。场景完整执行 360 tick 普通模拟，每 15 tick 规划，三个 v9 家族及左右镜像，共 12 项。

- 无山崖：继续进攻，实际打伤扩张基地。
- 有山崖：留队备战，主力仍在我方基地附近，敌扩张未受伤。
- 两类场景都有实际采矿交金，资源守恒、零花费、零伤亡。

#310 运行时在六个山崖场景中全部提前出征；六个通路控制场景通过。候选十二项通过。没有将这一短窗口算作击败援军或正式胜局。
