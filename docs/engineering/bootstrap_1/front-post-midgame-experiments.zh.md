# 休养候选与中盘观察

正常 loneMarket 林地 v9_knight 对两个独立冻结 v5，在 #317 规则下从同一 6000 tick 世界和全部玩家记忆分叉。只增加治疗设施休养的原型在 9000 tick 有 1 损失，主线为 0。跟踪发现恢复后的枪骑兵在 8670→8767 tick 被地面灼烧躲避任务长期占住，其短移动又自动重新迎敌。最终躲避改为非战斗移动，脱离实际危险后恢复治疗任务；从原型 8700 tick 的完整世界与记忆诊断，病人恢复撤往月井，被普通牧师治疗，9000 tick 存活到 84 生命。

最终源代码从原 6000 世界续至 9000：双方零损失，第一对手损失 1→5。继续至 15000：主线/候选己方损失 7/10，敌方士兵击杀（排除野怪）15/31，普通支出 8222/7953；双方未获胜，不能将早期零损失延伸为整局结论。候选具有 4 骑士、2 弩炮、3 牧师；主线为 6、2、3。

候选第三基地 13200 tick 起基于正常建造增长，13500 生命 431.66，13800 为 99.61，14100 已毁，未完成。预训矿工增长到 16，之后 11 人挤回主矿、5 人到自然矿。这是扩张防守损失留下的冗余，不是训练目标把两矿直接设为 16 人。需要继续检查施工基地与其他矿线争夺防守优先级；主将已经读入施工基地，不能误称完全忽视所有施工建筑。

原生的新火船场景未产生预期的对称伤害状态，失败发生在策略执行前，未计为检查通过；改用真正商店风暴和原生弩炮伤害构造控制权交接，三策略、两种族及镜像共 12 项通过。

#318 精确 PR 提交默认 v2 CPU 首次通过，合并为 b4ca2c956692db38fa52f43861a155315bd83f92。首次生产部署 38129747276 在射手旧有恢复测试的“600 tick 内达到约 36% 即回队”要求停止，没有构建上传。新规则保持满血休养；后续验收必须按实际道路行军与治疗速度计算观察时间，并要求满血且实际重新入队，保留途中不召回条件。尚未验证 #318 生产发布，线上最后已验证为 #317。
