# bootstrap_1：按实际可调用的远征兵力决策

跨岛远征此前先把所有同岛士兵计入战力，再在脚本冲突过滤时排除骑射手清营任务与伤兵、医师。结果是第二个营地的进攻决策借用了实际不会前往的兵力，只有未被占用的一名步兵接到命令。

两处运行时代码改动共 9 行新增、6 行删除：远征入口明确要求 `troopAvailable` 策略；bootstrap 从已存在的骑射手任务、伤兵和医师分工得到可调用单位集合，舰队对这一个集合同时计算战力、处理救援和发出进攻命令。普通海军入口显式保持原有全员资格，不添加可选参数或兼容入口，不改变对敌方危险的完整感知。

三个 v9 家族、两个镜像方向的 12 个真实 SDK 场景验证：独立骑射手任务在另一营地持续真实作战；单独可调用的步兵不再借用该队战力赴死，保持正常 145/145 HP；换成三名真实可调用骑士时仍主动进攻并清掉另一个营地，三名骑士存活。没有加钱、改兵种属性或按地图、种子、对手版本分支。

压力场景中八名骑射手对四条红龙仍有骑射手损失，本次只证明单独可调用兵力的保存与足够兵力的正常进攻，不将它描述成全队无伤刷野或新的正式胜局。该微操问题继续调查。
