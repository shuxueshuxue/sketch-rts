# 同步重规划重复输入：只读发现与待协调方案

尚未修改 sailing.ts 或同步重试行为。父线程只确认该路径无实现重叠，明确要求实现变更前提交具体方案；本文件供协调下一步范围，不代表已获准实施。

## 实际调用和输入证据

基于候选 884e5214 的一次完整六人 14400 tick 诊断，记录完整船对象、地图地形内容/尺寸/风、起点和目标姿态、预算、voyage/noTraffic、profile、运动限制、速度/载荷/平衡/帆等派生输入。保留 -0、undefined、NaN/Infinity 区别，不用四舍五入坐标。数据以 SHA 引用字典保存，原始 query-inputs.json.gz、探针与分析脚本在归档中；整局命令和最终 checksum 与基线一致。

调用链可在冻结源码 [sailing.ts](https://github.com/shuxueshuxue/sketch-rts/blob/884e5214faa76544fd4c9d38802ea2b5ebf0147a/src/shared/sailing.ts#L510) 查看：航向推进失败 → waitForTraffic（272–279）→ replan(false)。178 的 allowCruise 条件未满足，不走分片任务；252–253 进入同步规划，noTraffic 时预算 Infinity；255–256 仍赋值路线并重置计时。

整局展开 6,358,153 节点，其中同步无状态搜索 5,857,945（92.1%），私有任务 500208。符合 noTraffic/Infinity/voyage=false/非嵌套/waitForTraffic 的 721 次调用累计展开 5,580,650 节点。

保守比较同一船上一次根同步调用的**完整捕获输入**，有 321 次完全相同，仍重复展开 4,519,765 节点，占全部展开约 71.1%。这不是仅凭船 ID 和目标推断。示例 tick 10009→10029，unit-player-5-cutter-1448，两次各展开 62673 节点。见 [完整分类](sync-duplicates.json) 和 [严格输入对](sync-exact-pair.json)。

更早的 tick 9989→10009 只有搜索投影相同，完整船对象中的 blockedTicks、route.points、route.end 字段不同，未将它算作这个严格示例。允许跨更多历史或忽略路线字段会找到更多重复，但本提案不据此扩大等价承诺。

探针未逐次保存完整返回路径和别名关系；因此还没有证明结果复用正确，也没有实现性能收益。带钩子的重复搜索包含时间约 3.60s，仅供定位，不可直接换算成正式 CPU/p99 收益。

## 建议的最小实验边界

只在原 waitForTraffic→replan(false) 调用位置，对确认无 traffic 回调执行的纯查询保留每船上一次输入与结果。固定单项、弱所有权，不做全局 LRU，不扩大每任务全图数组，不修改公共任意回调查询 API。

初始用保守完整输入守卫证明等价，再逐字段审计是否可去除与搜索无关的状态。必须核对起终姿态（含 heading）、船型/尺度/装备几何、运动限制及其载荷/平衡依赖、真实风、地图内容与尺寸、预算和 voyage。读取对象身份本身不能代替内容版本；同一船同一目标也不足够。

复用的是计算结果，交给执行器的 route、points、end 和 pivot 应重新物化，并保留结果内部应有的别名结构。执行器会 shift points、修改 exact 等字段，直接交回旧对象会污染下次结果。仍在原 tick 执行重试、准入、路线赋值、计时重置和物理碰撞检查；不改变重试频率、预算或完成时间。派生缓存不进快照，冷恢复或输入变化照常完整计算。

验收先比较逐调用返回值与对象别名约束，再核对全程逐 tick 状态/命令、旧快照和中途恢复、风/装备/地形/姿态变化、失败与无路线结果、回调次数和取消回收。以全部严格重复事件及完整场景固定顺序多次对照，分别报告 mean、p99、max、CPU、内存和净代码。若完整输入守卫的复制成本抵消收益，应改数据所有权或淘汰，而不是再叠兼容分支。

这条路径可能消除大部分节点扩展，但扩展不是全部成本；未证明全局 10×，也不能保证峰值下降。它比继续微调私有任务更值得下一步验证。需要父线程确认上述 sailing.ts 局部实验范围后才实施；terrain.ts 与 hullPassageClear 继续排除。
