# 将“全图预处理后筛选”改成“一次求解最近可行点”

2026-10-15，独立只读设计。未改生产源码、未编译或运行性能基准。这里重新定义内部问题，不在旧 Field/whole/shore 列表外继续加缓存。收益仍是待验证假设，内存倍数不能当作 tick 倍数。

## 真正需要求解的对象

当前 `src/ai/policy/naval.ts::shoreSpot` 并不需要“全部岸位”和“每个主城到每个格子的距离”。它需要一个点 s：

`在静态合法岸位中，满足己方可达、离己方主城不太近、比敌方更近、可建造、火力安全、接入指定海域，且己方路程最小；同路程取原row-major最先的点。`

所以可以把候选产生、距离确定、谓词验证和停止证明放入同一个查询。**终点不是预先给出的坐标，而是一个谓词。** 地面图不变；继续使用 `terrain.ts::grow` 已有的8桶Dial/Dijkstra松弛内核，5/7边权与禁切角规则都不变。只把“必须跑到队列空再返回Field”的输出协议变为“每个最终距离确定时允许查询消费者检查该格，获得足够证明就结束”。完整距离场消费者仍可把同一内核跑到底，不新增第二套寻路算法。

## 一次 exact query 的执行方式

### 1. 从己方全部主城出发；确定一个格子就生成至多一个候选

把己方有效主城格同时以距离0入队。原 grow 的整数边权是对称的，因此首次确定格子 s 的距离等于原 `min_hall walkingDistance(s,hall)` 的整数部分。只在settled时生成 `(col+.5)*cell,(row+.5)*cell`；无需遍历整图的岸位Point列表。

每个settled格先做廉价必要条件：自身是不是合法候选中心、原距离换算后是否达到HALL_BERTH、附近footprint是否可能同时含陆和海。只有通过者才逐项验证原footprint、levels、动态占地与枪塔规则。局部footprint直接检查 k 个格；k由船坞尺寸决定，不先支付三张全地图积分图。若候选很多，O(k·P)也可能超过一次积分图，这个反例必须测，不预设局部永远更快。

己方可达性已经由搜索到达证明。原“有限gap之后再some(hall=>sameGround(spot,hall))”在同一普通有效地面图下是冗余证明，内部新查询可删除；不用为此生成全部陆地区域labels。

### 2. 敌方竞争是阈值判定，不是完整敌方距离场

候选己方整数成本为 g，只需要知道 `enemyDistance(s) > ownDistance(s)`。同一个Dial内核为全部敌方hall维护一个查询内cursor：

- 已有敌方路径上界换算后≤己方gap，即可拒绝；不必把该路径settle。
- 否则继续敌方cursor，直到确定s距离，或frontier最小成本的原浮点换算值严格大于己方gap。后者证明不存在足够近的敌方路径，可接受这一项。
- 该cursor在本次查询内单调前进，所有候选共同使用，不能每候选重新从敌方hall开始。

没有敌方源时结果直接为Infinity，符合原min空集合。这里一次查询可能拥有两个内核cursor，但只有一套松弛算法。无需H张完整距离场、无需S×H次walkingDistance、无需每候选map+spread数组。

### 3. 海域条件按“需要证明什么”回答，不先标全部海域

海域是最容易把设计变成伪优化的部分，不能省略：原合法岸位需要footprint中某海域有至少64格深水；末尾还要求 `walkableGoal(spot,'sea')` 与指定water相连。这两项不一定指同一个海域，不能偷换成“海面附近就算合法”。

用相同遍历内核、sea passability回答组件见证，查询内只保存已遇到格及其组件关系。对“某来源组件至少64深水”可在找到64个深水时证明true；找不到必须穷尽该组件才能证明false。对“两点相连”，找到连接即可证明true；没有发现连接只能返回unknown，穷尽相关可达集合才能证明false。原walkableGoal的选择和tie必须保留。

优先复用本次查询已得到的海域见证；不承诺首次就能便宜证明一个遥远海域连接。最小实现可以保留现有组件判定作为精确后置谓词，先检验地面/岸位物化是否真的被删除；若冷峰值仍由该谓词占据，才让同一内核支持局部组件证明。**不得把保留whole冷成本的第一步宣传成完整架构已解决。** 一片大海且指定water很远时，确切连通/否定仍可能要求大面积探索。

### 4. 最优查询只处理到胜者成本层结束

得到一个完全通过谓词的候选后记录 `(originalGap, rowMajorOrdinal)`，继续处理所有可能与它同gap的settled格，挑原ordinal最小者。frontier下界的原gap换算严格大于bestGap才结束。队列内部同cost的顺序不必改；不能靠“第一次弹出的合格点”处理ties。

未决的低成本海域谓词不能丢在后台后直接接受更贵候选。最小实现同步把该谓词证实/证伪；允许查询内调度也必须在停止前解决一切可能胜出的未决项。没有任何合格点时必须穷尽己方可达区域，或获得覆盖其余区域的严格拒绝证明。

## 存在性和最优性不能混用

| 用户代码真正使用的结果 | 可以停止的时刻 | 必须保留的结果 |
|---|---|---|
| `if (!shoreSpot(...))` 一类纯布尔分支，例如 naval.ts 的规划存在性检查 | 任意一个候选的所有条件已证明true | 只保留true/false；没有必要求最近或处理距离tie |
| 返回点后选择builder、建造、布置炮塔 | 已找到合格点，且frontier严格不可能产生更低或同gap更早ordinal的点 | 原最优点值、原tie与后续策略结果 |
| 同一同步执行先问存在性，随后需要最优点 | 可以暂存cursor与见证，随后继续；不能把第一个见证假称最优 | 生命周期只到原同步执行边界；不得引入跨tick完成时机变化 |

布尔false在最坏情况下仍需检查全部相关可达空间。任何声称“恒定次数局部检查即可证明没有合法岸位”的设计都缺少信息。敌方枪塔把所有近岸挡住、环形陆地只有很远唯一合法岸位、完全无合法岸位，都是必须保留的宏场景。

## 可以直接从这条策略数据流删除什么

- 删除先建立全部shore Point数组再枚举的阶段；用settled格产生候选。
- 删除该query的三个全图shore积分图；只检查真正到达的候选footprint。其他确实需要完整shore列表的公开消费者不因此删掉。
- 删除为己/敌每座hall准备完整Field的阶段与S×H评分循环；两个单调cursor分别给己方排序和敌方阈值证据。
- 删除纯决策查询的全图next数组、父链、路径重建与128目标Field LRU依赖；这里没有人请求一条行走路线。
- 删除已经由己方搜索到达证明的再次land连通查询。
- 若海域见证完成，再删除此query依赖的全局sea labels/count；不能删除实际仍需要全图区域枚举的其他功能。

不是把这些结构换名字塞进一个更大的query cache。cursor拥有距离暂存和8个桶，结束即释放/归还既有工作区。第一轮可沿用dense dist数组以减少代码，但其初始化仍O(N)：若目标是连初始化也不支付全图成本，需用已有generation工作区风格或touched-cell清理；仅为这个变化再设计大型稀疏容器体系不值得。

## 复杂度与数量级机会的真实来源

N：全图格数；H：参与评分的hall数；S：所有合法岸位；K：己方探索格数；E：敌方阈值探索格数；W：必须证明的海域访问格数；P：实际评估footprint的候选数。

- 旧首次查询约 O(N + HN + SH)，外加动态谓词；完整字段与列表有明显全图工作集。
- 查询式方案约 O(K + E + W + kP)，加frontier的原Dial成本。若仍dense初始化，必须再加O(N)初始化时间。
- 多数可行岸位离home近、远处地图巨大时，K/E/P可以远小于N/S；这才是可能出现10–100×条件峰值改善的原因。不是“同样完整场少分配一点”。
- 无解或远海证明困难时K/E/W可接近N，局部footprint还可能付额外kP；必须报告坏例。不能由52×更少内存推导任何tick比例。
- warm重复查询可能更适合旧完整Field复用。要比较真实决策密度和首次峰值；新设计不应被预先要求在所有热循环里获胜，也不能只报最好的一次冷调用。

## 等价性中最难的四个边界

1. **浮点tie不能直接化为整数tie。** 原表达式为 `(cost * terrain.cell) / STRAIGHT`，要逐字保留换算。即使cell正有限，不同整数cost在极端尺度也可能映射同一Number；因此处理到换算后的frontier界严格超过bestGap，不是仅处理一个整数层。HALL_BERTH和己敌比较同样使用原值。支持范围须避免整型距离溢出；不能默默扩大旧Int32图语义。
2. **候选边界必须精确。** 原shoreSpots的footprint cell范围、row-major序、levels、深水组件条件都需匹配；不复用此前已经失败的local perimeter替代判断。
3. **公开可变Terrain不属于可偷偷改写的对象。** 已有levels、cell、cols变动反例说明旧runtime/旧shore列表/当前坐标混合的公开行为确实存在。新query只适用于拥有不可变图版本契约的私有生产入口；旧公开函数仍按旧行为。若生产对象本身不满足契约，必须先由所有者决定迁移，不能以“通常不会改”为正确性论证。给每个旧对象增加影子缓存修复所有畸形输入会失去净简化目标。
4. **返回Point身份与调用副作用。** 旧私有shoreSpot返回shore列表中的稳定对象。若跨调用身份是验收要求，完全删除列表且每次新建Point不等价；可让纯布尔入口不暴露Point，并让最优新内部接口返回cell ordinal，再在明确消费边界生成值。需要先核实消费者只读坐标、没有身份比较/修改；不能将这一接口迁移伪称旧函数严格引用等价。带getter/自定义回调的任意公开输入也不能改变读取次数；只对引擎拥有的普通冻结快照适用。

## 原始资料：支持的是查询协议，不是移植一个框架

- [Boost Graph 1.85 Dijkstra官方文档](https://www.boost.org/doc/libs/1_85_0/libs/graph/doc/dijkstra_shortest_paths.html) 明确区分distance输出、可选predecessor及visitor事件，并提供不遍历全图初始化的no_init入口。这支持“一个内核、不同消费者/初始化协议”，不支持本方案的具体游戏谓词或任意早停。
- [NetworkX原始 `_dijkstra_multisource`](https://github.com/networkx/networkx/blob/6da4704cbf32ba6f50f6d9c46cc0a071e3a87985/networkx/algorithms/shortest_paths/weighted.py#L784) 同一实现接收多个sources、可选target和cutoff；[851-861](https://github.com/networkx/networkx/blob/6da4704cbf32ba6f50f6d9c46cc0a071e3a87985/networkx/algorithms/shortest_paths/weighted.py#L851) 将源统一入队，在最短距离确定后遇target终止，而不是先物化所有结果再取target。SHA通过GitHub API解析并读取对应原文件核对。把固定target扩为可行谓词、补上同分层与enemy阈值证明，是本报告推导，不冒称其现成实现。
- [Dijkstra原论文出版记录](https://link.springer.com/article/10.1007/BF01386390)，1959，Numerische Mathematik 1:269–271。浏览到的是出版元数据，全文有访问限制；这里不据未读全文宣称其讨论了本项目多目标谓词。

region/scanline拓扑压缩本轮不选作主方案：它要求新的预构建图、跨窗口距离或区域内精确回退，很容易重新引入“先算一个世界再回答一个问题”。除非测得W连通证明才是剩余主因，否则先让现有搜索直接输出所需答案，删除中间产品，优于另写压缩导航算法。

## 如何验证设计而不偷换游戏

首次实验只在同步私有shore决策入口替换查询协议，保持同一tick调用、AI频率、预算、yield和建造时刻；不预热到前一tick，不延后剩余工作。独立oracle仍调用原完整模块，比较存在性、最优坐标、同距ordinal、后续指令和完整状态；旧可变对象反例要求旧接口继续通过。

计数必须为：己方settled K、敌方settled E、海域访问W、候选P、实际footprint格检查、最终停止下界、整个query和整tick耗时。至少测近岸可行、最近岸位全被占、只远端一处可行、完全无解、大连通海与许多小海域、多个己敌hall、冷/暖、不同地形规模。看到K/E/W相对N显著下降才有第一性原理证据；未实现前不能提供速度保证。
