# 共享单位与规则版本 2

本阶段承接用户追加的同质单位合并授权。美术阶段的同规则性能证据固定在 `9819046` → `78ee99a`；本阶段更改单位数据，不得将新旧规则下的模拟、胜率或 AI 验收结果直接比较。未修改另一工程车道的冻结报告、策略优先级、配兵数量或验收阈值。

## 合并映射与取舍

运行目录从 57 种单位收敛到 55 种。两个旧单位及两个同义技能从运行定义、命令目录和 UI 删除，只有旧存档导入边界认识旧名称。

| 旧单位 | 共享单位 | 旧技能 → 共享技能 | 保留的实际职责 |
| --- | --- | --- | --- |
| pyreCaller | summoner | cinderSoul → summon | 同种 spirit，40 秒冷却、60 秒存续 |
| emberAcolyte | priest | emberMend → heal | 非机械友军定点治疗，55 点治疗、12 秒冷却 |

统一采用已有 Grove 定义，避免逐项挑选双方最强数值或缺乏依据地取平均。Grove 单位数值不变，Ember 变化如下；单位伤害类型、老兵专属技能池、半径、人口与等级门槛在各合并组中相同。

| 属性 | pyreCaller → summoner | emberAcolyte → priest |
| --- | --- | --- |
| 生命 | 88 → 95 | 78 → 90 |
| 移速 | 59 → 56 | 62 → 60 |
| 普攻伤害 | 7 → 8 | 6 → 7 |
| 普攻距离 | 208 → 218.4 | 192 → 201.6 |
| 瞄准速度参数 | 440 → 400 | 480 → 440 |
| 金价 | 174 → 180 | 130 → 135 |
| 训练时间 | 9.5 → 10.5 秒 | 8.75 → 9.25 秒 |

这不是无玩法影响的改名。治疗者更耐打，召唤者普通攻击略增强，同时移速、瞄准和造价有所取舍；两个种族不再拥有同职能的独立冷却别名。合并后的新统计需要在规则版本 2 单独评估。

## 保留的差异

- Spark Archer 的命中有点燃地面的被动，伤害为火焰箭，并与 Ravager、Runner 和 Ash Hexer 的灼烧收益联动；不能按普通弓手合并。
- Ash Warden 使用穿刺近战伤害，Footman 使用切割伤害；身体质量也不同。Lancer 另有显著接触距离差异。
- Witch 的 curse 与 Ash Hexer 的 ashCurse 有不同减伤比例与灼烧交互，保留独立单位和技能。
- 骑兵的坐骑、冲锋和移动瞄准，工程与船只的武器交付方式，野怪的毒、网、践踏等能力保持原有职责。
- 三种佣兵保留雇佣库存、购买位置、价格、基础强度及升级资格；拥有同类武器或治疗技能并不足以认定同质。

## 一个战斗定义，多条生产关系

`UNIT_RULES` 只定义战斗与费用；`RACE_TECH_RULES` 定义种族到单位、生产建筑的关系。共享 caster 在 Grove 的 sanctum 和 Ember 的 cinderSpire 生产，沿用原有 42 人口上限门槛。工人、七种船与各族不同的 workshop 名单也进入同一关系表。

`trainingBuildingFor`、`trainableUnitsAt` 与 `canTrainAt` 服务模拟、命令校验、AI 生产查询和 UI。权限检查整条关系，不能把“建筑全局能训练”与“种族全局能训练”交叉拼成未授权组合。研究位置由建筑的 researches 单源派生，保留 Ember 射程研究的两个既有入口。

共同单位的战场、训练预览、队列、装备头像和尸体使用 owner race 决定装束，队伍颜色仍独立。命中、伤害和技能只使用共享规则；视觉皮肤不复制单位定义。

## 导入、回放与联机

`RULES_VERSION = 2` 独立于仍为 17 的校验和算法版本。无规则版本的旧记录视为版本 1。旧存档在导入时一次性转换单位、变体基类、队列、武器来源、技能、冷却和自动施法字段；保留已支付费用、剩余训练时间、实际生命与已有老兵选择，不重抽技能或凭空回血。详细边界见 [存档与规则迁移](save-rules-migration.md)。

旧回放不能通过替换名称获得原结果，跨规则重模拟明确拒绝。联机握手与权威消息携带规则版本，避免两套规则混跑。AI 代码仅适配共享角色名称及种族生产查询；同一策略在新单位数据下可能产生不同决策，这不是跨版本 AI 达标证明。

## 其他必要影响与验证范围

剧情焚咒师继承移速 59 → 56；两名原 pyreCaller 基类角色继承瞄准速度 440 → 400。Oru 显式移速 60 及剧情生命、伤害、射程覆盖值保持。原生火罐改用已有 fire 投射物类型，摆脱借召唤师名称选择颜色的依赖。

中立场景中的旧 emberAcolyte 归一为 priest 后，适用 priest 既有的人形装备资格；这是罕见的中立脚本实体差异。制式武器引用共享单位后也采用其统一攻击数据。

共享身份也统一已有角色判断，而不保留隐藏的种族例外：`shouldPrioritizeWoundedPriestTraining` 原先排除 priest 和 fieldMedic，现在余烬治疗者也不再计入“至少 3 名受伤战斗员”的触发计数；疗者上限和受伤比例阈值保持不变。海军补充乘员原先按 `heal` 技能优先排序，现在同样识别余烬治疗者。以上是单位、技能身份合并的自然语义变化，并非调整 AI 配兵数量、策略优先级或验收条件。

AI 的生产者、降级训练、人口波次和资金预留查询读取同一族生产关系；场景授予异族建筑时，不再为不能生产的共享单位生成训练指令或预留预算。

生产、命令校验、单位 tier、AI 生产/研究查询、恢复预算与技能目标相关的 12 个测试文件共 132 项已通过，日志见 [focused tests](validation/shared-unit-focused.log)。其他子系统与最终全套回归以各自验证日志为准。

研究命令、研究建筑前置和升级预留也按 `canResearchAt` 检查种族关系。预留仍允许为本族尚未建成的研究建筑筹资，不增加新的研究时机或数量策略。`src/ai/policy-v2prod/` 是历史生产 AI 的冻结副本，本阶段保持文件不变；它只用于冻结 Grove 基准，不能把其旧建筑查询当作新族内容的接口示例。其最终指令仍须通过共享命令合法性检查，异族研究不会获得执行权限。冻结策略在规则版本 2 运行的结果仍不是旧规则验收证据。

测试迁移审查发现一次机械去重误伤：`policy/v6/economy.test.ts` 中重复的 summoner 字符串表示多名真实单位，不能当作目录名单去重。已恢复该文件 HEAD 的原始 6、7、3、3 名单位编队；不改变阶段推进断言。对所有已改 AI/shared 测试的字符串数组逐段比对后，其余减少重复项仅见实际 Set 分类与单位 tier 目录。数字字面量序列不变并不能证明测试场景数量不变，因此验证同时检查实体数组的顺序与重复次数。

## 真实客户端训练验证

执行 `node scripts/art-gameplay-proof.mjs --suite shared-units --port 34616 --out docs/art/refactor/units/gameplay`，使用本地真实服务器、Chromium 和普通房间 UI，通过 WebSocket 发送训练命令；不加速 tick、不直接生成受验训练结果。

[运行报告](units/gameplay/gameplay-proof.json)记录两族各自的生产菜单、实际队列与训练完成：每族从 500 金减至 185 金，出生 priest（90 HP/7 普攻）与 summoner（95 HP/8 普攻）。8 次非法请求均返回 HTTP 400，未扣金或入队：双方各自持有异族生产建筑时拒绝两个共享单位，两个已删旧单位名也拒绝。浏览器异常为 0，共保留 17 张真实截图。

已人工查看 Grove/Ember 的召唤师战场与选择面板，以及 Ember 牧师菜单/队列截图：召唤师蓝布与余烬褐布、法杖端部色彩区别在世界和头像中一致；牧师与召唤师的装备、头饰轮廓可以辨别。菜单与队列同角色像素一致，两族的菜单、队列和选择头像均重新绘制出不同衣装；哈希比较仅证明重绘，不替代视觉判断。该场景验证训练和表现，未模拟压力战斗或作为性能指标。

首轮 proof 的固定第二生产建筑落在继承的生成地形森林中，队列到 0 后没有合法出生位置，因而超时。失败记录保存在 [首次场景记录](units/gameplay-attempt-1/gameplay-proof.json)。最终脚本用项目已有地形与放置查询选择合法宽阔地块后再布置场景；另按服务器实际默认初始金验证花费，未依赖 REST 解析未接收的玩家金种子。
