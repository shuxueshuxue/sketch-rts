## 像素质量优先

分阶段真实 GPU 诊断确认：裁切后的平面端点和插值会改变 alpha 边缘；恢复原平面可消除原测试差异，但远缩揭示另一个 mip 网格和终端层问题。最终方向为非空卡片保持完整源域，包括非二次幂 640/320 动作纹理；保留统一组合与纹理数组，不恢复旧画师实现。此前透明裁切的内存收益只属于历史实验，不能移用为新版本收益。[严格 GPU 复验](gpu-parity/README.md) 已完成：8 场景、16 次近远尺度/阴影/混合尺寸比较均为零差异；11 项批次测试包含镜像拾取通过。

## 性能计时边界的更正

先前 `gl.finish()` 后几乎没有等待，不能单凭这一观测认定 GPU 执行便宜。逐调用发现每帧约 16 MiB 累积传输处有一次数秒阻塞；换成 fenceSync/flush/clientWaitSync 确认完成后，上传调用变快，而数秒延迟移到真实完成等待。旧数值保留，属于原同步提交和驱动背压的观测。

进一步把纹理初始化与实际绘制分别提交并等待完成，初步完整诊断均值为：准备约 677 ms，纹理初始化 CPU 44 ms 加完成等待约 4681 ms，实际绘制 CPU 2.5 ms 加等待约 586 ms。异步轮询包含调度延迟，是完成耗时上界，不是硬件 GPU timer query。接下来只根据相同内容、分辨率、过滤与可靠完成观测评估优化。正式最终对比已完成，见[最终实测](performance/formal-completion/FINAL-RESULTS.md)。

进一步将上传与 mipmap 分开提交并分别确认完成，12 个测量帧保持状态、可见覆盖和最终 RGBA 完全一致：上传 CPU 58.250 ms、完成等待 6.683 ms；mipmap CPU 0.067 ms、等待 4687.883 ms；绘制 CPU 2.692 ms、等待 568.842 ms。主要瓶颈为整数组 mipmap 重建，随后逐脏层生成与最终存储方案均通过严格保质对照。此为隔离归因，不是产品优化成绩，详见 [实验记录](performance/UPLOAD-EXPERIMENTS.md)。
