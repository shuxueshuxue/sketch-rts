# Page mip generation experiment (not production)

Baseline production remains the per-layer staging uploader at `85220a3`. The experimental patch uploads base layers directly then regenerates dirty array-page mip chains through the public Three copy API. The 16-layer version passed the color/depth/distance pixel oracle but regressed the real 1000-unit replay: completed-render means 10689.17 and 10694.26 ms across its first two 12-sample cycles, versus approximately 4508 ms for the preceding retained production implementation. It was stopped during the third cycle because the regression was decisive; `page16-rejected.log` is deliberately partial, not a completed benchmark. No performance claim is based on this trial. Main production implementation was restored. The original candidate allocated a four-byte seal scratch; the saved patch includes the subsequent release of that scratch, with identical transfer behavior.

A one-layer-page counter-experiment is run separately to distinguish unwanted regeneration of unchanged layers from transfer overhead. The temporary worktree/runner retained the historical name `four`, but its tested LAYERS constant is **1**. This is a diagnostic extreme: it increases draw calls and texture objects, and is not accepted merely because it avoids the 16-layer regression.

The one-layer trial also regressed: first 12-sample cycle mean 7089.68 ms, p50 7182.90, p95/max 8252.30. It was stopped before completing cycle two. Both experiments were rejected; neither uploader nor page-size change remains in production. These partial experiments diagnose this software GPU and are not a replacement for the completed 36-sample production benchmark. No scene visibility or simulation change was used. Pixel equality alone was insufficient to accept a performance change.
