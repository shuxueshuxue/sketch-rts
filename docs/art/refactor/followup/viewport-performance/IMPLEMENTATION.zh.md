# 视野驱动的表现处理

本轮从 `b50cc879` 主线独立分支 `perf/viewport-presentation` 实施，最终生产实现冻结为 `35dca2b`。首轮 `5eb401d` 的新快照开销退化，保留在 stage1 作为未收敛候选，没有作为交付性能结论。未改变共享模拟、战斗规则、经济、AI、随机数或维护费。性能报告及原始数据见同目录 README 和 comparison.json。

## 问题与职责

原代码已有单位、建筑、船只和地形的绘制范围判断。缺口是许多 CPU 表现工作发生在单位范围判断之前，GPU 的 Canvas HUD 层还构建、过滤、排序了一份完全不用的全体实体列表。单位受击偏移在范围判断前对特效数组执行 `find`，可能放大为单位数乘特效数。空镜头的血滴与甲板血迹仍被写入 GPU 实例缓冲。

现在 `PresentationViewIndex` 在新快照、tick、集合替换或数量变化时更新空间网格及实体/首次命中索引。每个存活 ID 复用条目，仅在覆盖分区变化时移除/加入网格引用；删除、重新排序、体型和普通/特殊状态变化会同步。GPU、Canvas 地面和 HUD 层共享这个索引及实体查询表。每次镜头查询仅取普通地面单位的候选，再保留原有精确显示位置判断；候选按原快照顺序排列。镜头移动或 zoom 变化不需要重建快照索引。

候选的保守包围范围涵盖原单位脚点、身体偏移及 180 世界单位缓冲，也涵盖整个冲锋/滑动插值轨迹。非常长的插值、船只、甲板单位及没有统一尺寸约束的剧情 painter 使用现有精确定位路径；不为了统一索引误裁高度、旋转船员或自定义画面。

完整动作帧、方向投影、装备表现、贴图身份和 GPU 卡片准备在候选及精确范围判断之后执行。HUD 层直接使用候选单位，不再进行未使用的全世界实体排序，也不为只画血条/状态的单位重新生成攻击姿势。受击偏移读取保持原 `find` 首条语义的命中索引。瞄准线和建造计划保留屏外来源、屏内目标；其来源集合在快照索引建立时提取，不按单位是否入镜删掉。

## 屏外历史与再入镜头

全体单位的实际释放事实、动画时钟、步态、朝向、移动插值和接触溅血历史仍按原规则推进。它们属于后续显示需要的信息，不能随镜头移走暂停。空闲单位不生成完整姿势：动画 tracker 仅维护当前有效方向和待清锁的 ID 集合，逐帧轻量观察攻击/持械方向，保留原方向对象身份。过期、打断、移除会清锁；3 秒持械方向及 450ms 收回保持原时钟。

朝向 tracker 对同一快照的重复绘制直接复用，按新命令快照、可变 recorder tick 和集合变化刷新。移动、朝向及动画历史复用 Map 和观察记录，静止朝向复用不可变状态，动画每 ID 交替使用两个记录与各自的小缓冲。Action、direction、carry 和已经创建的动作帧保持原引用；71,448 次公开输出比较与首轮逐项相等，详见 animation-equivalence。

血迹接触通过血滴在世界中扫过的完整区间查找接收者，不依赖镜头。范围包含原接触算法访问的完整 96 单位网格，并考虑跳 tick、甲板当前平移和旋转；所有活跃 burst 合并成一次查询，接收者去重、按快照顺序排列并共用一个接触索引，保留同距离接触顺序与原胶囊共享。48 个重叠 burst 的完整表现输出及武器表面准备次数与原全局查询一致。

甲板单位的垂直释放必须以甲板朝向作为第一次攻击的镜像选择；它们跳过全局地面方向观察，保留原裁剪前动作朝向路径。已增加船头朝左、全局初始朝右、屏外向上/向下释放后入镜的实际卡片回归检查。

`World3DLayer.positions.get(id)` 对候选对象立即返回本帧坐标；屏外普通单位的 UI/效果查询按需计算精确插值位置、身体偏移和朝向，并缓存到本帧。`size`、迭代及 `has()` 描述本帧已准备/已查询的坐标，不代表世界总人口。下一帧和 reset/dispose 清除缓存，避免持续保留全世界投影结果。

## 墨迹裁剪

血滴及甲板血迹在写入实例前，按真实正交相机的高度投影与完整旋转矩形范围裁剪，保留 2 屏幕像素余量。高处粒子和位于屏外但形状延伸入镜的血迹仍提交。身体血迹和速度线使用原有可见人物锚点。接触、血迹附着、淡出和地面残留事实继续保留，裁剪只影响本帧实例提交。

测试用 486 组真实 THREE 相机投影的角点交叉检查边界；可见实例的矩阵、颜色、透明度与无裁剪输入逐项一致。

## 验证及剩余成本

`npx vitest run src/client/art src/client/unit-animation.test.ts src/client/unit-facing.test.ts src/client/unit-motion.test.ts src/client/presentation-view.test.ts src/client/world3d src/client/world-renderer.test.ts src/client/world-presentation.test.ts src/client/combat-presentation.test.ts src/client/combat-surfaces.test.ts src/client/blood-contact.test.ts src/client/projectile-origins.test.ts`：43 文件、413 测试通过。`npm run build` 包含类型检查并通过；保留已有的大包提示。浏览器前后测与实际战斗证明另列在 README，未完成时不计入验收。

正式固定视野前后测的 18 张合成截图 RGBA 零差异。另完成 160 个真实模拟 tick 的战斗对照：80/80 模拟快照 SHA 与 80/80 原画面 PNG SHA 一致。第 2 tick、30 滴血仍在飞行时移开镜头，旧版仍提交 30 个空中实例，新版提交 0 个并统计裁掉 30 个；两版的世界血滴记录仍为 30。原时钟移回后恢复 32 个实例（30 滴与 2 个身体印记），画面字节一致，未推进模拟。

这次降低的是屏外表现的重复处理。快照索引和必要历史仍有随世界人口增长的 tick 成本；建筑、船只、剧情特殊对象、尸体、全局光环及血迹接触还有各自的遍历。完整姿态的 Canvas 绘制、像素读取、GPU 上传和贴图驻留没有在本轮重新设计。不能把 CPU 提交下降解读为显存下降、所有开销只与可见单位有关，或已经获得硬件 GPU 的相同 FPS 提升。
