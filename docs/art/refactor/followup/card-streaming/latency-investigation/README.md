# Mixed-scene latency follow-up

The original final native-residency comparison reduced tracked card texture bytes but regressed mixed-scene CPU mean by 6.1% and complete-wall mean by 3.1%. This investigation keeps that result and its slow samples intact. The focused fixes below reduce specific CPU costs; they do not establish that the remaining upload waits or real-frame stalls are solved.

Peak bookkeeping preserves every sampling point and all actual allocation peaks. It caches immutable page mip bytes and avoids constructing full public draw statistics during raster work. Its p99 and real-wall regressions remain in the report.

Mask packing preserves alpha threshold 102, row orientation, UV behavior and complete authored raster dimensions. Aligned little-endian inputs use word comparisons and skip blocks with zero alpha; other layouts use the original byte semantics. The formal comparison verifies 24 decoded PNGs, 8 fact snapshots, 480 CPU clocks and all 24 phase resource/call/order snapshots exactly. CPU >100 ms samples still increase 31 → 32, and complete-wall mean increases 2.34%; the mask microbenchmark is not a game-FPS result.

The survivor-retention candidate stays out of production. It saves 25 real Canvas misses per lifetime before the empty/return probes, while keeping an extra 5,113,212–5,229,952 bytes of compressed pixels. Peak tracked CPU ownership is unchanged, but endpoint ownership increases 7,787,776 → 12,900,988–13,017,728 bytes. CPU p95 and complete-wall mean regress. Exact pixels and reuse alone do not make that tradeoff a successful resource optimization.

Two-hit admission improves measured mixed CPU mean 9.36% and complete-wall mean 3.48%, with exact images, GPU uploads and layout. It avoids encoding single-observation poses and ends with 45 fewer true Canvas misses per lifetime. Its lower encoding cost also prevents the old adaptive backoff, so the full encoded working set stays resident: tracked endpoint CPU ownership rises 7,787,776 → 58,531,040 bytes, an increase of 50,743,264 bytes (+651.6%). The 38,824-byte lower peak does not offset this sustained allocation. Up to 1,024 ghost keys coexist with up to 1,024 encoded entries; their JS metadata bytes are unmeasured. This 48 MiB candidate is not selected as the default optimization. A separately frozen 16 MiB candidate has its own [15 deterministic semantics cases](rle-twohit-budget-semantics.json) and must be measured as an admission-plus-budget policy, not presented as a same-budget admission result.

The full admission-plus-16-MiB comparison does reproduce its 55.3% tracked CPU-buffer peak reduction, but not the pilot's speed result: full mixed CPU mean increases 0.55% and complete wall increases 2.06%. Actual Canvas misses increase 123 per lifetime. The [ordinary-world comparison](rle-budget-canonical-abba/report.md) separately reports hidden 0 and 9,900: hidden-0 CPU increases about 16.5%; hidden-9,900 CPU increases about 4.57% and complete wall increases about 6.48%. Neither ordinary working set reaches the 16 MiB cap or evicts entries. Admission forces 77 additional real paints/readbacks while saving only about 3 MB of tracked ownership. The ghost admission scheme is rejected as the global default. Its [initial single-lifetime pilot](rle-budget-pilot/report.md) remains intact and is not substituted for the full result.

Segmented uploads preserve pixels and transfer bytes but increase warm partial-copy calls 1,724 → 10,929 per lifetime (6.34×). CPU and complete-wall means regress, so the 64 KiB candidate also stays out of production. The formal run has no per-copy observer and does not establish that the original 241 ms wait disappeared or moved to a particular segment. The [portable mock](upload-chunk-mock/proof.json) verifies the contract, not real native filtering or performance.

Changing only the original cache's default budget to 16 MiB reduces tracked mixed CPU-buffer peaks 60,687,364 → 26,356,908 bytes (56.57%), with unchanged endpoint ownership and GPU resources. Its full mixed CPU mean improves 5.57% and complete wall improves 2.91%, but real Canvas misses increase 150 per lifetime, CPU p99 and fresh-tick p95 worsen, and submission and return-to-view wall means increase. There is no two-hit admission or ghost metadata. The separate ordinary-world check verifies exactly the same paints, hits, ownership, uploads, images and clocks at hidden 0 and 9,900; its working set stays below 16 MiB and never evicts or backs off. Its only non-timing resource-field difference is `rasterCache.budget`. That two-arm check is work/quality validation, not an ABBA timing or FPS claim.

The [combined-pipeline ABBA](pipeline-abba/report.md) supplies independent before/after evidence: 24 images with exact RGBA and PNG hashes, eight facts and 480 clocks, frozen provider/module/method/source proofs, with every lifetime retained. Tracked peak CPU ownership falls 60,720,132 → 26,356,908 B (56.59%) and before-view GPU texture ownership falls 210,914,668 → 191,718,124 B (9.10%). CPU mean improves 3.77% and complete wall only 0.97%. Its **696.9 ms CPU maximum**, candidate-B2 lifetime-1 **52.838 ms CPU mean**, subsequent real mean 348.745 → 349.050 ms and p95 1039.8 → 1068.8 ms remain adverse evidence. All real frames still exceed 100 ms. Pages/chunks rise 10/61 → 14/70 and fresh Canvas misses rise 150; full/native resources and key layouts are reported, not incorrectly equated. Untimed aggregate snapshots cannot independently prove individual instance submission sequences or picking.

The measured default-budget provider's exact `f9c83…e78b` bytes were promoted at `37a8594`; [integration provenance](upstream-integration.json) records unchanged client/shared/server trees through `1e03c5f`. The formal timings remain **AEC-source** measurements, not renamed final-HEAD results. Final integrated validation records **133 files / 1066 tests** and a passing production build in [tests](final-validation/tests.log), [build](final-validation/production-build.log) and [commands](final-validation/commands.json). Camera/picking proofs are separate from the formal aggregate resource audit.

## Attribution and useful negative results

- [Method profile](profile-report.md): readback is the principal disjoint CPU segment; SVD gating and ordinary draw assembly are small. Nested timings are not added together.
- [Chrome trace](trace-analysis/report.md): long Canvas calls contain deferred Skia drawing. One 241 ms CPU-to-scratch update spends 240.631 ms waiting on the graphics command channel; the trace does not identify a unique internal GL operation. Main-thread GC does not account for these principal observations.
- [Canvas attribution](canvas-attribution/report.md): replaying 36 actual cache-miss painters after disposing WebGL retains exact RGBA. Reading one pixel first moves the deferred work rather than reducing paint-plus-read time. All captured bytes and failed/slow observations are retained.
- [Mask microbenchmark](mask-micro/report.zh.md): separate Chrome and Node measurements over those 36 actual rasters support the word implementation. All actual inputs are sparse, the real dense group is empty, and the two slower Node paired samples remain reported.
- [Deterministic RLE policy semantics](rle-semantics.json): standalone original and candidate classes retain the exact codec, detached caller outputs, budget/LRU/entry limits, exception behavior and clear/second-life ownership. Mock-clock cases validate the proposed recovery-only backoff; they are not performance evidence or production acceptance.

## Reproduction and scope

Every formal run preserves source/provider/harness hashes, raw clocks, first cold-stream frame, complete per-lifetime distributions, screenshots and resource ownership. CPU samples use the original renderer-render no-op while retaining raster and GPU-transfer submission work; real samples wait for a WebGL fence. Neither is a measurement of simulation time, and complete wall includes software rendering and scheduling. Resource counters measure owned typed arrays and card textures, not total process memory or VRAM.

The isolated formal drivers are [peak](../../../../../../scripts/art-card-latency-formal-proof.mjs), [mask](../../../../../../scripts/art-card-mask-formal-proof.mjs) and [RLE candidate](../../../../../../scripts/art-card-rle-formal-proof.mjs). They retain the original mixed fixture's 18 preparation frames, 60 CPU warmups, measured `n=114..173`, and real `n=480..491` cold jump. Run trials sequentially, with fresh browser lifetimes, no other heavy work, and new output directories. No sample exclusion, lower-quality drawing, reduced visible content or simulation change is used.

The [combined driver](../../../../../../scripts/art-card-pipeline-formal-proof.mjs) uses the same clock and archived helpers. To rerun its 48/16 comparison after promotion, restore frozen AEC source, the frozen 5b baseline and the external candidate from a run's `source-snapshot/candidate-card-raster-cache.ts`; verify the archived harness/helper hashes. Current HEAD has the new default and deliberately fails the driver's old-current-cache corpus requirement. Existing artifacts can be audited without a browser using [analyze.mjs](pipeline-abba/analyze.mjs) and [summarize.mjs](pipeline-abba/summarize.mjs); do not combine old-epoch timing samples into a synthetic before/after.
