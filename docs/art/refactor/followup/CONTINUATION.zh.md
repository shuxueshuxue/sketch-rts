## 纠正证据，而不是绕过失败

异步 GPU 完成等待会让浏览器清空默认绘图缓冲。最初新增的 fenced 小场景录像因而缺少单位图层；其“80 帧一致”不能证明单位画面一致。已删除这些失效 PNG/MP4，保留标明局限的原 JSON；测试脚本显式保留 GPU 缓冲并检查该属性，生产设置不变。

已在冻结的 `da2ec82` 和 `b2f74b7` 上重新采集：包含可见单位、武器与阴影的全部 80 个 PNG 哈希一致。`preserved-before/after` 是有效当前对照。千人基准原本就启用了缓冲保留，不受这个问题影响。

修正后的小场景 CPU 提交均值 53.16 → 37.37 ms；完整渲染均值 383.23 → 358.02 ms，但 p95 688.30 → 695.60 ms。单次软件 GPU 回放不能证明稳定尾延迟或硬件帧率改善。千人 36 样本基准均值 4488.68 → 4507.89 ms，无显著提升；CPU 恢复缓存因不划算自动释放，最终内存没有持续增加，学习期间的峰值仍增加。

继续调查了整页 mip 生成：16 层页的前两轮均值约 10689/10694 ms；单层页诊断约 7090 ms。两种方案均更慢，已停止后续重复测试并撤回全部生产实现，只保存 [实验补丁与明确标记为不完整的日志](page-mip/README.md)。没有减少单位、分辨率、特效或模拟工作量来制造提升。
