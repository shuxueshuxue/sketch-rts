# Equipped living figures and death-time remains

`death-equipment.png` is generated by `npx tsx scripts/art-death-equipment-review.ts`. Each row uses actual pickup/wield commands followed by death cleanup: round shield, a different unit's issued bow, and a story priest retaining its authored robe while wielding a greatsword. It compares default, equipped living figure and persistent remains. The PNG was visually reviewed.

Death cleanup captures only appearance facts before the unchanged inventory drop operation: `equipmentCaptured`, `rightItemKind`, `weaponKind`, `leftItemKind`, `ownerRace`. They are primitive values. Optional `deck` copies the attachment; snapshot export copies it again to avoid aliasing. Wreck passenger filtering, item drops, entity IDs, targeting and combat rules remain unchanged. The checksum migration is handled separately because corpse facts participate in canonical state.

The model entry points are `paint(..., presentation?)`, `paint.release(pose, presentation?)` and `remains(brush, team, presentation?)`. Story composers consume gear overrides while retaining their authored anatomy, size, costume and details. An automatically issued weapon matching the story unit's simulation base does not replace its authored weapon. Explicit different issued weapons and greatswords pass through both renderers, model cache identities and release sockets. Equipment shield style is explicit, and greatsword/bow/two-hand constraints also apply to remains. Missing facts in older records retain the historical default appearance.

Validation: new death-equipment tests (5) cover real equip/death/drop behavior, owner skin, snapshot/restore and older records, story cache/loadout/socket priority. Existing story-remains (29), caster-skins (3), release-socket (4), rig (8) passed. Corpse tests (3) include live deck snapshot/restore isolation and wreck passenger filtering. Logs retain initial failures and subsequent focused outcomes. The initial new test incorrectly assumed a bow leaves the offhand shield wielded; the fixture expectation was corrected to match the existing two-hand inventory rule. An existing renderer test was updated to request explicit round shield style instead of conflating any `shield:true` with a round item.

The root's final typecheck and full-suite evidence supersede the intermediate in-flight typecheck notes. Deck renderer integration and same-tick projectile validation have their own follow-up evidence. The application has no live campaign HUD/model context; recorder story world models consume gear, but no new campaign portrait UI is claimed.

The subsequent item-consumer correction passes an issued item's actual `weaponKind` to ground drops, inventory buttons, equipment-panel icons and drag ghosts. Bow, pike and javelin icons now reuse the held-weapon geometry rather than all using a sword icon. Generic shop previews without a source item retain a generic sword study. The root's focused run passed all 3 item tests, including source geometry pixel equality and the 80px/size58 guard bounds. `issued-item-consumers.png` was generated and visually reviewed at native sizes, with a former/new greatsword icon comparison. It is explicitly a shared-painter metadata study, not a claim of DOM interaction or actual dropped-item gameplay verification. `issued-item-sources.json` records the generating command and source hashes; `issued-item-review.log` records script completion.
