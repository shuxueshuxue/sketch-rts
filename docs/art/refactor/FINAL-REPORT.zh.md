## 实际改造

覆盖 **55 个最终单位入口及遗骸、23 个剧情角色模型、14 个建筑、11 个地点、7 船、17 物品、27 个技能／状态 SVG**。这表示现有资产有明确、统一的消费入口，不表示每个模型都被重画。完整清单见[资产覆盖](final-asset-inventory.md)，职责与资源生命周期见[架构](architecture.zh.md)。

人物由体型、部位、材质、衣装细节、骨长约束和武器挂点组合。人形和兼容角色复用动作，动物保留自身解剖结构，船体、工程机械、建筑、地形和语义 UI 使用各自适合的表达。已删除无人调用的 14 套建筑画师、`card.paint` 与单位包装；保留的船卡用于目录和模型尚未就绪的肖像，不是重复人物实现。

身体保持左右两向；攻击以水平、上斜 60°、下斜 60°为三种源姿态，镜像并进行有限调整，最终缓存为 13 个方向样本。攻击与施法独立，有 idle 和由真实事件确定的攻击变体。接触／释放时锁定朝向与挂点，恢复末帧回到 ready 姿态；表现不推进模拟随机数。装备只读映射不改变战斗规则，世界、肖像、背包、掉落和拖拽图标使用实际装备身份。剧情身体、释放位置和遗骸保留作者造型；普通联机界面没有独立剧情模型上下文，本任务没有新增剧情 HUD。

冲锋与高速受迫位移产生沿实际运动方向的克制速度线。非机械目标遭到致死、或命中后生命不超过当次实际伤害两倍时才出血；数量、大小和速度随伤害调整。血滴以重力轨迹落地，地面、身体和甲板使用不同附着坐标，船转动时甲板痕迹跟随，沉船后清除。攻击恢复期间附体血迹跟随实际显示朝向。死亡清理前捕获装备、阵营和甲板事实，遗骸不再丢失新创建尸体的这些信息。

## 保质与性能设计

没有通过降低分辨率、减少可见内容或删去特效来提速。早期透明裁切虽保持基级像素，却改变了插值与远缩 mip；已撤回裁切并保留完整源域。旧裁切收益只属于[历史阶段](STAGE-9de6820.zh.md)，不能当作当前成绩。

纹理数组按脏层生成完整 mip 链；新卡片逐张绘制和上传，CPU 不再保存整页 RGBA，只保留原 alpha≥102 拾取阈值的精确位图。GPU 搬迁复制全部 mip，成功后再切换映射，失败保留原缓存；上下文恢复从当前快照重新绘制可见卡片。可见内容可以超过软预算，不会为了缓存数字删掉单位。

[卡片内存验证](followup/card-memory/README.md)通过 45 项定向测试和全局类型检查；10 个场景、20 次真实 GPU 比较均为零像素差异，包括真实人物、近远缩放、阴影和冷热混合后的搬迁。真实上下文丢失／恢复保留相同画面与拾取对象，重置和释放无 GL 错误。恢复时间的小场景诊断只有两张活体卡片，不是大型军队恢复时延的上界。

正式对照使用完整画质基线 `0f93be6` 与最终生产候选 `7b8186e`，同一 Chrome 151／SwiftShader、1280×720、DPR1、相同五个测量输入文件。15 轮的模拟、可见数量、动作／特效覆盖、缓存内容以及三张最终截图全部一致；截图逐 RGBA 零差。完整方法、分布、逐帧数据和中间阶段对照见[正式性能报告](followup/performance/formal-completion/FINAL-RESULTS.md)。

动态均值下降约 **58.48%**；静态总体持平，不能宣称普遍提速。三组全部样本仍超过 33.3 ms，千单位压力场景没有达到实时目标。动态模拟预计算的 60 次 `stepGame` 均值为 13.12 ms，与渲染分开记录，不包含 AI 规划、快照序列化和命令生成。

动态场景的主卡片缓存 CPU 数组由 **816.84 MB** 降至 **28.22 MB**（含新 scratch，约减少 96.55%），其中拾取位图 25.53 MB；受控 CPU 峰值 32.31 MB，单张临时 RGBA 峰值 1.64 MB，画布 backing 另计 2.95 MB。GPU 数组估计仍为 1.089 GB，尺寸与画质没有减少；含 scratch 的精确受控 GPU 存储约 1.093 GB，观察到的峰值约 1.302 GB。待释放源页已经包含在该峰值中，不能再次相加。这些是指定缓存的存储计数／估计，不是进程 RSS 或驱动实际占用；测量遥测本身也会影响 JS 堆。

这里测的是 `World3DLayer.draw` 加确认 GPU 完成的墙钟，含提交、驱动背压、等待和轮询调度，不是纯 GPU 时间、显示帧率或完整游戏帧。动态覆盖 48 陆地种类；静态船名单为 6 种，未含 fireShip；建筑、地点、剧情 UI 和 Canvas 地面血迹不在该性能负载内。加载 32 个 GLB 不等于绘制 32 个模型。全资产目录和其他实机证明不会被用来扩大这个性能口径。

## 持续内存与生命周期续验

`ede4146` 后补做了[30分钟持续负载与独立7分钟固定场景对照](followup/browser-stability/README.zh.md)，生产代码未改。主运行7576帧、83819次正常缓存键淘汰、11次prepare，浏览器与活动GL无错误。资源计数有界；最终释放后卡片自有CPU/GPU归零、PSS降至481.59 MiB。固定场景20次prepare的公开GL资源差额不增长，保留renderer静置后PSS由绘制中位604.50降至566.68 MiB，销毁后465.51 MiB。

**仍不宣称长期进程平台已证明。** 主运行10–20分钟切换段PSS斜率+2.65 MiB/分钟，固定绘制段也有上浮；自然静置能回收，未定位到明确生产泄漏，但没有数小时动态浸泡或驱动实际显存证据。没有强制GC、重启浏览器或降低画质。完整范围、分段统计、首次验证脚本死亡选择错误及修正均保留在续验报告。

## 独立的规则变更与剩余边界

用户另行授权的共享施法单位收敛使用规则版本 2：`pyreCaller→summoner`、`emberAcolyte→priest`，对应技能合并为 summon／heal，采用 Grove 原数值并经种族科技表生产。这确实改变部分价格、训练时间和属性，不能称纯美术改名。普通快照导入的一次迁移与跨规则回放拒绝分开；checksum 18 纳入新死亡事实。详见[数值说明](unit-consolidation.md)、[存档边界](save-rules-migration.md)和[剧情重演边界](followup/story-save-boundary.md)。

- 本环境只有 Chrome 151／SwiftShader 软件 GPU，没有硬件 GPU 帧率或驱动内存实测。千单位压力场景仍远非实时，不能把优化比例当作流畅承诺。
- 血迹是有弹道和贴附关系的有界表现，不是流体模拟；预算饱和会淘汰旧痕迹，越舷血滴不模拟入水，附体血迹不转移到尸体。读档／回跳清除历史残留。
- 旧尸体缺少的历史装备和甲板事实不能反推；活来源在首次观察释放前已经换装时，仍没有完整的发射时装备历史。缺命中事实的旧效果不猜测出血。
- 兼容骨架可换武器与动作，但不是每种非人形都能显示所有可携带装备；没有把四足动物强行改成人手。没有连续动作交叉淡化或完全流体效果的承诺。
- Canvas 原生测试的内存受事件循环清理调度影响，既有自然让出诊断降低增长，但尚无长期平台期证明。缓存账面字节不能当作整个进程 RSS 上限。
