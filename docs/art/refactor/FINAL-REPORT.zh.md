完整清单见 [最终资产覆盖](final-asset-inventory.md)，职责设计见 [架构](architecture.zh.md)。覆盖 55 个最终单位入口、对应遗骸、23 个剧情角色模型、14 个建筑、11 个地点、7 船、17 物品和 27 个技能/状态 SVG。船帆、船载硬点、建筑 GLB、连续地形和语义 UI 保留各自适用的表达；不声称每个资源都被重新绘制。

人体部位、骨长约束、刚性武器/双手支撑、材质和细部钩子已进入共同组合入口。世界、装备头像和训练菜单消费同一外观；实际换装复验确认双手巨剑、去盾及肖像一致。攻击、施法、工作和 idle 分开，攻击变体由事件确定，不推进模拟随机数。

身体保留左右两向，动作使用 0°、上斜 60°、下斜 60°三种源姿态和受约束的终端调整，缓存为 13 个有限方向样本。脚底和骨长保持约束；释放/命中时锁定方向，恢复末帧回到同一 ready 姿态。弓、杖、嘴部等释放挂点来自实际解算链，投射物首次出现后固定起点。见 [方向设计与图表](directional-actions.md)。

速度线按冲锋/高速受迫位移生成，不为普通走路增加拖线。血迹仅在非机械目标遭到致死或剩余生命不超过本次实际伤害两倍的命中时生成，量和散射随相对伤害调整。解析重力决定血滴落点；地面、身体和甲板分别保留局部/世界附着。地面通常 5～9 秒、附体 3～6 秒褪去，数量受预算约束。GPU 墨迹共用一个深度测试实例批次。详见 [效果约束](combat-accents.md)。

## 同规则性能结论

环境为本容器 Chrome 151 / SwiftShader 软件 GPU、1280×720、DPR1；不是硬件 GPU 帧率。第一轮失败数据仍保留在 [首轮报告](RESULTS.md)。完整第二轮及逐帧原始数据见 [a62c95b 报告](optimization/RESULTS-a62c95b.md)。

| 同规则场景 | 78ee99a → a62c95b 渲染均值 | 解释 |
| --- | --- | --- |
| 26 骑兵 Canvas | 0.733 → 0.738 ms | 未证明 Canvas 提速 |
| 280 单位全陆地种类固定快照 | 44.437 → 3.650 ms | 原有规律性约 2.4 秒冷姿态卡顿未再出现 |
| 千单位真实动态快照 | 12741.058 → 4679.897 ms | 降低 63.3%，仍全部 36 帧超过实时预算 |
| 同动态纹理数组 CPU 字节 | 721420288 → 452984832 | 降低 37.2%，仅纹理存储，不是总进程内存 |

对原始 `9819046`，动态均值降低约 67%；该对照包含动作表现改变，不能全归因于批次。`78ee99a→a62c95b` 的模拟哈希、动作计数和可见数量一致，未通过减少可见内容或分辨率获取收益。千人动态末帧仍需约 113M 纹素，超过 12MP 软预算；可见内容受保护，因此不为预算删兵。

最终规则版本 2 的方向和墨迹成本见 [完整报告](final-performance/RESULTS.md)，不用于跨规则提速结论。千人软件 GPU 动态渲染均值 5017.969 ms、p95 5601.800 ms、最大 5745.400 ms，全部 36 个样本超出实时预算。每轮覆盖 24 个出血事件、22 个真实投射物挂点；陆地场景不覆盖甲板血迹，另有浏览器专项实证。

完整 Canvas 路径包含血迹、速度线和投射物，四场各 600 帧、每场完整观察 400 个模拟 tick，覆盖 57 个出血事件及 42 个投射物。画布资源复用前后模拟哈希、逐帧表现覆盖完全一致，五张同帧截图逐 RGBA 差异为零。1800 个预热后样本渲染均值 4.043→4.076 ms、p95 13.741→13.849 ms，未证明 CPU 提速。进程末尾 RSS 2.430→1.916 GB，降低约 21.2%，但连续四场仍从 0.923 GB 增至 1.916 GB，内存问题未解决。受控画布账面占用 53.1 MB 不能代替进程 RSS。

独立诊断中的两次显式 GC 仅将 RSS 1.922→1.837 GB，不能将大部分增长解释为简单的延迟 V8 回收，也不能仅凭 RSS 断言强引用泄漏。正式性能结果没有强制 GC。后续 [原生 Canvas 最小复现](final-performance/diagnostic-native-canvas/art-native-canvas-lifecycle-findings.md) 将增长定位到 NAPI 读回与事件循环调度：640² 画布同步读回 400 次约 865 MiB，仅重置不读回约 63 MiB；每 20 次自然让出事件循环、没有强制 GC 的 2400 次读回约稳定于 232～235 MiB。这支持延迟原生缓冲清理的解释，但不证明浏览器内存泄漏，也不是生产修复或可替换正式成绩的数据。

[完整游戏自然让出诊断](final-performance/diagnostic-yield/comparison.json)进一步复验：每 20 帧在计时、采样和截图后让出事件循环，不强制 GC，四场 RSS 为 585→636→650→659 MB；相对同步版，全部模拟哈希、逐帧特效覆盖及五张截图 RGBA 完全一致，受控画布仍为 53.1 MB。这确认同步无让出的 headless 生命周期显著影响 RSS；四场仍微增，尚不是长时稳定证明。等待时间未计入渲染耗时，不能据此宣称帧率或产品性能提升。

## 未解决与使用边界

- 软件 GPU 千人动态场景仍远未达到实时性能目标；没有物理 GPU/驱动内存数据。Canvas 同步 headless 重复场景 RSS 仍增长；独立自然让出诊断显著降低增长，说明测试后端调度有重要影响，但浏览器长期内存与录制长任务仍需实测。
- 同 CPU 源的裁切重建逐 RGBA 不变，但 CPU/GPU 画布抗锯齿不同，GPU 过滤后的严格像素等同门仍失败（最大通道差 113/95，均差约 0.00674/0.00490）。没有将失败阈值放宽为通过；浏览器画面审查和源像素测试不能代替此门。
- 血迹是有弹道和贴附关系的受控二维效果，不是完整流体；预算饱和会提前淘汰，越过船边的滴不模拟入水。读档/回跳清除历史表现残留。
- 尸体没有生前装备/甲板快照；首次看到事件时来源已消失，不能精确还原历史装备。缺受击事实的旧效果不猜测出血。
- 本地实施与验证完成情况以以上记录为准。PR、推送、合并、部署留给父线程另行决定。
