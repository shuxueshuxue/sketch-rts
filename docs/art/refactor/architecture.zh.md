# 美术与渲染迁移

工作基线为 `9819046`（包括 #314/#315 的持续采矿维护费规则）。第一阶段美术迁移不修改模拟、AI、经济或战斗数值；渲染读取既有快照、装备和冷却事件。其性能对比必须在同一规则版本下冻结。用户后续授权的同质单位合并另立阶段，明确记录数值、科技树和规则版本变化，不能用跨版本数据宣称渲染或 AI 提升。尚未合并、发布或部署。

## 职责

- `art/appearance.ts`：单位的体型、装备默认值、阵营造型与生物类别；没有攻击伤害或冷却数值。
- `unit-animation.ts`：根据快照观察位移、甲板局部位移、攻击冷却、技能冷却及维修/采矿进度；产出有限、共享的动作帧。选择变体不调用随机数生成器。
- `art/motion.ts`：攻击、施法、移动、呼吸和工作动作的可复用意图。命中/释放事件到达后首先显示接触姿态，再恢复，不在伤害发生后重新播放前摇。
- `art/rig.ts`、`body-parts.ts`、`equipment.ts`：体型约束、固定长度两骨链、手腕挂点、双手支撑和武器几何。换武器不替换身体/护甲/坐骑；不兼容的动作族回到该武器支持的族。
- `art/materials.ts`：纸上绘制的明暗、金属高光、布料与细部纹理；`painted-units.ts` 只组织身体层级和外观细节。兽类和攻城机械保留各自的解剖/机械结构，不强套人形骨架。
- `art/unit-appearance.ts`：读取现有 `activeItem` 和制式武器来源，为战场与装备/选中头像产生同一表现配置。只提供外观投影，不写入模拟。
- `art/story-rig.ts` 与剧情 `models.ts`：剧情身份以服装、头饰、部位细节组合到同一人物/生物系统；去掉独立人体和四足体实现。
- `art/model-manifest.ts`：建筑、专用场景建筑与船只 GLB 清单。既有模型库、船帆形变、船炮挂点与建筑几何各保留适用职责。
- `art/effect-presentation.ts`、`canvas-effects.ts`、`effect-renderer.ts`：外观判定/轨迹数据、Canvas 绘制和事件筛选/裁剪分别管理；WebGL 弹道消费同一投射物判定。
- `art/environment.ts`：地标、树木、矿山与障碍的环境几何；`atlas-art.ts` 负责缓存、锚点、镜像与肖像入口。

## 缓存与批次

Canvas 的 `RasterCache` 保持原绘制密度和锚点，只裁掉透明边缘，并保留过滤边距。缓存按实际保留像素限制预算，复用工作画布；部位变化、动作变体、朝向和装备均进入缓存键。裁剪不删除任何有 alpha 的像素。工作池最多 4 张/4MP、裁切备用池最多 8 张/1MP；嵌套绘制独占工作画布，淘汰结果延至下一次顶层调用回收，以保护即时借用者。返回结果只保证在下一次顶层 get/clear 前可用，实际入口立即绘制。重置清除像素、裁剪、路径及保存栈；clear 使用代次保护在途绘制，过量画布显式缩至 1×1。统计覆盖缓存、备用、工作、借用和待回收资源。

这一资源生命周期修复有像素等同证据。同步原生 Canvas 测试的 RSS 显著大于受控画布账面字节；独立自然让出事件循环的同场景诊断显著降低增长，指向原生读回缓冲的清理调度，但尚未证明长期平台期。不能将缓存预算称为进程内存上限，详见 [该阶段实测](final-performance/RESULTS.md)及[自然让出对照](final-performance/diagnostic-yield/comparison.json)。

WebGL 的 `PaintedCardBatches` 保持原绘制密度和完整源域，包括 320/640 的非二次幂动作纹理。每层保留独立 mipmap，避免普通图集相邻图像串色；每页使用实例层索引合并 draw call。原有透明裁切会改变顶点插值和远缩 mip 网格，已移除；其历史内存收益不适用于当前实现。[严格 GPU 复验](followup/gpu-parity/README.md) 的 16 次近远尺度与阴影比较全部零差异。

`cardRect` 保持原平面端点的 float32 舍入及脚线，世界矩阵只承担世界变换；包围体和拾取覆盖同一展开后的平面，可见、阴影和拾取消费同一透明度数据。CPU 读取频繁的工作画布选择 CPU 绘制后端，避免每个新姿态同步读回 GPU；这与此前 GPU 画布后端的抗锯齿差异是另一边界，不能称所有旧截图逐像素相同。建筑和船只继续通过 `ActorBatches` 管理。缓存回收未被当前帧引用的资源，不为预算删除可见对象。

最后的 CPU 存储改造将卡片缓存收敛为 `finish(renderer)` 单一入口：逐张绘制缺失姿态、压成原阈值 alpha≥102 的拾取位图、原地翻转行、上传完整 mip 链，随后释放该张 RGBA。纹理数组使用无 CPU 数据的完整 GPU 存储；拾取仍按原始 texel 判断，不用包围盒代替透明轮廓。严重碎片化时逐层复制已有 GPU mip，全部复制提交成功后才切换映射、释放源页；失败则退掉目的页并保留源映射。缓存不长期保存绘制闭包。

上下文丢失会清掉卡片缓存，下一正常帧从当前快照重新绘制可见资产，因此恢复是一次冷绘制。真实上下文恢复验证包含画面零差、拾取同一对象、重置和释放无 GL 错误；小场景恢复时间不代表大军队恢复的上界。内存统计分别列拾取位图、单张临时 RGBA、scratch、画布后端与 GPU 搬迁峰值；`WorldLayer.cardStats()` 是主卡片缓存，甲板遗骸使用同类的独立策略缓存，二者不能冒称整个进程内存。验证证据见 [卡片内存改造](followup/card-memory/)。

死亡装备和甲板事实属于模拟输出中的只读表现数据：在原掉落流程前复制，不影响伤害、掉落、寻路或命令。`deck-remains` 将不可变甲板局部坐标映射到当前显示船位；Canvas 置于船甲板绘制顺序，GPU 复用同一卡片类的透明、深度测试、无深度写入策略。船位、年龄和透明度不加入遗骸图像缓存键。故事角色的专属造型仍由作者定义，穿戴装备经相同入口覆盖。

整页 mipmap 重建已被定位为动态软件 GPU 的主要瓶颈。`e06e047` 已接入逐脏层 GPU 生成：有限尺寸的单层 scratch 生成完整 mip 链，再通过公开 renderer API 逐级复制到纹理数组。完整源域、过滤和画质不变；严格画面对照与真实上下文恢复/重置/释放已通过。[第一阶段同环境实测](followup/performance/formal-completion/STAGE1-RESULTS.md)的动态 GPU 世界路径完成墙钟下降约 55%，静态近持平，船场景略慢；这不是完整游戏帧或硬件 GPU 帧率。密集更新整页的隔离实验存在退步，不能将稀疏更新收益推广到所有场景。最后 CPU 存储改造的正式对照另行记录。详见 [生产接入与质量证据](followup/dirty-mip/README.md)、[性能归因与实验](followup/performance/UPLOAD-EXPERIMENTS.md)。

## 验证原则

完整目录见 [资产盘点](asset-inventory.md)。基线、场景、环境和计时口径见 [测量方法](MEASUREMENT.md)。保留逐帧数据与模拟快照哈希；将模拟、快照生成、渲染提交与 GPU 等待分开。SwiftShader 数据只能表示本容器软件渲染，不能宣称物理 GPU 的帧率。

旧人物 fallback 和全局画笔姿态上下文已由显式动作与统一 composer 取代。Canvas 是产品原有无 WebGL 回退与录制途径，应继续保留；它不是旧人物实现的兼容包装。
