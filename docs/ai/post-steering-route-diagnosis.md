# #516 后路线、召唤兑现与沿途塔群：240局诊断（2026-10-18）

结论：三个问题需要分开定价。严格的“出发时漏看沿途塔群”有35次、28/240局；取消这批塔火后18次、17局从亏损变为不亏/摧毁目标，具有可重复的伤亡证据。archer 的 stall 增幅几乎来自一只120金的拾取兵，不能解释主力普遍停走。召唤物寿命与到场有模型缺口，但新一波补召唤、已经撤退和实际交战克制混在一起，目前不足以支持全局削弱 strengthOf。

本轮只诊断，临时探针和反事实干预均未提交，没有修改生产判定、调阈值或开新PR。#519 已关闭；[两版锚点不合并记录](caster-safe-retreat-anchor-not-merged.md)及其分支保留。

## 2. Summoner：现存战力相加，不检查本次接敌能否兑现

`policy/v6/strength.ts:41–45` 的 unitStrength/strengthOf 不读 expiresTick、施法冷却或到场时间。`general.ts:351/358–360` 的继续进攻使用它。**出发时则不同**：`strength.ts:58–60` 的 marchStrength 已把现存spirit替换为施法者60s/40s的平均1.5只，所以不能声称出发与继续全程都把现存召唤当常驻。

80场summoner对局（240局中的80场）里，79场出现434次主要接触；定义为至少4名施法者的军团、接触点900内至少4名己方军人，双方军人伤害在静默30秒后重新出现。其中195次、67局在接触时仍是attack。

用成功召唤事件精确记录 caster→spirit，再追溯实际对军伤害；“贡献者”是自己或自己的spirit在指定窗口打中过敌军的原队列施法者，包含开战前已召出的spirit。与物理到场分开：

| 正在进攻的195次接触 | 按施法者人次加权 |
|---|---:|
| 首次接触时在700屏障范围内 | 59.2% |
| 首10秒实际提供对军伤害 | 49.7% |
| 首60秒实际提供对军伤害 | 80.4% |

首10秒贡献不足75%的有137次、58/80局（也就是58/240局）；其中41次亏损，平均我方312金、敌方497金。其余也常是好交易，不能把137次全叫作“纸面战力导致失败”。这显示兑现有延迟，不等于每个未到场者都该永久降权。

寿命敏感性：找首次接触前5–30秒最近一次获准继续的判断，冻结当时队列，事后只扣自然到期、在接触前已消失的旧spirit。**12次/10局**会使原“继续”变成“不够0.8”；其中8次/6局随后60秒亏损，均值 **1202:514金**。但11次接触时 general 已转 hold/defend，仍在attack的只有 **44 ember tick9813一例（1/240局）**，该例随后损失240:0。很多旧spirit已被新一波补上；这些是敏感性及观察损失，不能把1202金都归因于寿命遗漏。

对01 grove的旧反例：被否决的仅去重8e分支在10927将8caster、11spirit等相加成16.955；5个spirit会在12.9秒内到期，施法者仍落后前排。60秒2340:475、8caster全死。但只扣这5个即将到期者仍足以越过当时去重后的10.405门槛，寿命一项不足以解释首个判定；即时屏障、施法者到场与战斗克制也参与。#516后的main同局获胜，该旧失败没有混入上面的240局发生率。

## 3. 沿途塔群：严格35次/28局，18次可由塔火反事实挽回

`policy/ground-threat.ts:38–39`只看前排未来一个THINK_TICKS（15tick/0.75s）内会入射程的塔；`general.ts:309–319`出发按目标基地的守军/塔和响应军队选目标，`attack():659`随后直接下发行军目标。目标主基地外、路上另一个基地的塔不等价于目标的守军。

先普查实际伤害：目标外900的已知塔，实际命中仍距目标850以外的原进攻成员；转出attack、60秒目标未倒且我方付费损失大于敌方，得到153次/95局。其中至少两塔实际开火的107次/74局。该宽口径包含出发前已经在塔下、临时转目标和撤退伤害，不能全部声称是“出发前没看路”。

严格口径进一步要求：出发前30秒原队列没有受塔火；所有这批塔均在前排0.75秒窗口以外；**出发当时预测的原生道路已穿过至少两座后来实际开火的塔**。同队/同塔群60秒内的general反复启停去重。结果：

| 严格沿途塔群样本 | 次数 / 240局中的局数 | 原60秒我方:敌方平均损失 | 塔最后一击直接金额均值 |
|---|---:|---:|---:|
| 亏损撤退 | **35 / 28** | **831:246** | **308** |
| 取消指定塔火后变为不亏或摧毁目标 | **18 / 17** | **554:253** | **313** |

35次的我方损失中位数615金；29次取消塔火后净交换改善。18个被挽回的窗口平均少损399金，净交换改善969金。窗口可能重叠，不能把各窗口金额累加为独立总损失；“挽回”指这次进攻的60秒交换/目标，不是整场由负变胜。

可复现一例：main41c9c208，v9_knight/v9、25 grove，seed v5-final-1，布局 `v9_knight-layout:v5-final-1:ladder-25:10`。tick27885出发，28055开始受沿途五塔火；出发时这些塔不在think窗内，也无此前30秒塔伤。60秒损失 **1310:440**，其中1195由塔最后一击；反事实同前缀只取消指定塔火，变为 **0:630**。具体塔ID与路径判定在JSON中。

物理反事实是塔伤因果贡献的诊断上界：它保留塔和敌军、保留原AI判断，却给原队列一个60秒无这批塔伤的窗口。它没有证明现实存在同样快的安全绕路，也没有证明加整路检查会净增胜场。更宽的153次中有些取消塔火反而更亏，进一步说明不应把所有撤退/跟进都套同一条安全规则。

## 后续判断

优先级建议先由上面的严格塔群样本评估；archer应区分单兵拾取停滞与派遣先手，召唤力量应区分即时到场、重召唤和真正坏交换。当前证据不支持把全局撤退阈值、召唤权重或跟进行为再一起改动。是否值得修由这组发生率、金额和之前两次240局的翻转风险共同决定。
