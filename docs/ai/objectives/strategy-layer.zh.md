# 房间 AI 战略目标层设计稿

状态：设计稿，待主人确认。基线 main `883f57c5`。输入是三份模块契约及其真实对局证据：
[陆地](land-contract.zh.md)（#556）、[防守](defense-contract.zh.md)（#555）、[海战](naval-contract.zh.md)（#554）。
下文用 L1–L8、E01–E08、N(a)–N(e) 引用这三份文档里的事件编号。

主人的要求：岛屿争夺/防守与大陆争夺/防守之间不冲突；AI 有目标感、有侵略性；不是 if-else 的堆叠，
而是“定义目标 + 目标需要的条件 + 满足条件的行为 + 局势评估”，能自己推出计划。

## 1. 现在缺的是什么

现有模块（扩张、新矿留守、进攻目标、前压、回防锚点、追击缰绳、驱赶小队、工人撤离、首航、夺岛、持续转运、
舰队、医疗）各自都能把一件事做完。三份证据一致地指向同一类缺口，不是某个模块写错：

1. **没有人决定“哪个目标更重要”。** 每个模块按自己的规则挑兵，`unitClaims` 只记录“这个兵现在归谁”，
   回答不了“这个矿口和那座岛谁更值得救”。表现为：本土挨打时第二艘船照常装船出航（E01、N(d) 环海）；
   岛厅被拆时本土 16 名兵守着无人进攻的旧矿（E02）；夺岛补运抽走正在进攻的射手（L2、E05）。
2. **抢占没有交接。** 被借走兵的目标不知道发生了什么：进攻被记成“兵力磨损”撤回（L2、E05）；守矿兵被留守
   名单删掉又要回来，几秒一次来回（L1、碎海 887 个 A-B-A 三元组）；治疗把守兵带走后矿口没人补位（E03、L3）。
3. **“占用”和“下命令”混在一起。** 在岗的留守兵不需要新命令，就不声明占用，于是被海军当成空闲兵拉走，
   随后又被拉回（N(a) 碎海 8355）。`follow`/`board` 不走同一条仲裁路径，绕过了预留（L4、N(a) 神泉殿 8095）。
4. **缺条件时不会推出计划链。** 模块缺兵、缺船、缺安全路线时只是“不出命令”：岛上缺 3.2 战力却不会去借
   大陆任务的闲兵或者造第二艘船（N(e) 蓝宝 17991）；首航送去的是施法者，清营前排为零（L5）；扩张拿到的是
   正在换代的召唤物（L6）；骑射骚扰时没有可用的反制兵种，也不会去训练（E08）。
5. **世界事实和任务状态混在一起。** “delivered/complete/已买船”被当成“岛现在安全”；本土 intel 的零 intrusion
   被当成全图安全（N(d) 碎海两座岛厅）。

## 2. 设计原则

- **世界事实与任务状态分开。** 每次 think 先算局势，任务状态只记“我承诺了什么”，不代替事实。
- **一个分配器看到全部占用。** 单位、船、金币、生产队列、工人都在同一张分配表里：防守/任务 claim、甲板上的人、
  ferry crew、施工成员、治疗中的人，都是同一种“占用记录”，只是种类和可抢占性不同。
- **占用与命令分开。** 在岗不需要新命令的兵照样占着；有新的局部命令也不会自动释放原任务。
- **抢占必须带交接。** 一个目标拿走另一个目标的资源，要满足“收益超过对方损失加切换成本”，并给被抢的一方
  发事件（暂停 / 缩小 / 失败并说明原因），不能让对方误判成战斗磨损。
- **缺条件时产生子目标，不产生沉默。** 子目标带资源需求、预计时长和替代做法（借兵 / 训练 / 造船 / 换接驳点 /
  放弃），一起进入比较。
- **执行结果回流。** 实际装载、卸载、营地伤亡、厅奠基/完工/被拆、守军到岗、航行停滞，都会改变目标的效用和可行性。
- **规则不看地图 ID。** 岛屿和大陆的区别只来自陆块/海域连通性、到达时间和运输时延。

## 3. 四层结构

```
局势评估 Situation ──► 目标生成与效用 Objectives ──► 分配 Allocator ──► HTN 分解 Methods ──► 执行器 Executors
        ▲                                                                                        │
        └──────────────────────── 执行反馈（进展、失败、到岗、损失）─────────────────────────────┘
```

### 3.1 局势评估（每次 think，可增量）

按**陆块**（地面连通块）和**海域**（水面连通块）组织，不分“本土/岛屿”两套：

- 己方资产：每个陆块上的矿厅、矿、塔、生产建筑、工人，以及它们的价值（剩余矿量 × 采矿速度，按时间折现）。
- 威胁：每个资产在时间窗内的来袭者及到达时间。复用 `land-arrivals` 的实际路线估算（#542/#550 已在用），
  并扩展到所有陆块，不只看 `readV6Intel` 选出的那一块。
- 兵力：每个单位的位置（陆块/甲板/船舱）、健康、角色、当前占用、到每个候选目标的 ETA；跨陆块的 ETA
  包含“等船 + 装载 + 航行 + 卸载”。
- 运力：每个海域的运输船、战舰、船厂、在途任务和预计空闲时间。
- 机会：对方正在施工的矿厅、离开本土的主力、守备薄弱的分矿、无人控制的中立矿/路口。
- 经济：现金、收入预测、已承诺给各目标的预算。

### 3.2 目标生成与效用

候选目标是类型化的，每类都写清效果、价值来源和失败条件：

| 目标 | 效果 | 价值主要来自 |
| --- | --- | --- |
| 守住据点 DefendSite(厅) | 该厅及矿工在威胁窗口内不被拆、不被杀 | 风险资产价值 × 丢失概率，按到达时间加权 |
| 夺回/重建 RecoverSite | 丢失的矿点重新有己方矿厅 | 矿值 − 当地威胁 |
| 陆地扩张 ExpandLand(矿) | 矿点有完工矿厅，且留守交接成立 | 矿值、时间折现、清营成本 |
| 夺岛 ConquerIsland(矿) | 同上，跨海 | 同上，再加运力与航时成本 |
| 增援前线 ReinforceFront(陆块) | 某陆块的我方兵力达到目标 | 该陆块上目标的缺口 |
| 进攻 AttackSite(敌厅) | 敌厅被摧毁 | 敌方收入损失 + 机会（在建、空虚） |
| 争夺路口 ContestRoute | 占住通往敌矿的路口 | 压制对方扩张、提前预警 |
| 驱赶骚扰 CounterHarass(敌单位) | 骚扰者被杀或离开 | 工人和采矿损失速度 |
| 撤离 Evacuate(据点) | 工人和可撤资产安全离开 | 救回的价值，用于"守不住"时 |

效用 = 期望收益 − 资源成本（兵力 × 时间、金币、运力），乘以成功概率（局部兵力比、我方 ETA 与敌方 ETA 的比较）。
有两个必须有的稳定机制：
- **坚持加分**：已经在执行的目标有额外加分，并且要连续若干次 think 都被别的目标明显超过才换。这是对
  L1、E04、碎海 A-B-A 来回切换的直接修复。
- **最短驻留**：刚到岗的留守或回防，在约定时间内不被普通目标抢走，除非出现更高等级的紧急事件。

侵略性来自这里：只要还有空闲兵力，进攻、扩张、争路口这些目标就有正的效用，空闲兵力一定会被分出去，
而不是等某个模块的触发条件刚好成立。

### 3.3 分配器（冲突裁决的唯一入口）

分配器把资源分给目标，输出一张持久的分配表：目标 → 单位、船、预算、预计到达、阶段。

- **贪心 + 边际效用**：按“给这个目标再加一份资源能增加多少效用”排序分配，直到资源用完或效用不再为正。
- **抢占规则**：从目标 A 拿走资源给 B，要求 B 的边际收益 > A 的边际损失 + 切换成本（路程回吐、任务重启）。
  抢占后给 A 发事件：A 自己决定是缩小（保留剩余兵继续）、暂停（保存进度等待归还）还是失败（说明原因）。
  "兵被借走"永远不再记成战斗磨损。
- **救命中断不经过分配**：工人撤离、躲炮弹、濒死治疗这些局部动作可以随时打断，但会在分配表里留下“空缺”：
  这个兵仍属于原目标，但当前不可用，分配器在下一次 think 看到空缺并补位（修 E03、L3）。
- **safety 中断必须产出 blocked 报价**：输入带上被打断时实际执行的父行动 ID、仍占用的工人和未支付预算，
  以及缺失前置与证据：例如要清的营地成员集合、需要压制的敌塔 ID、实际 steering 路线上被挡的路段或落点。
  由分配器比较续行、改派或生成清障子目标；不能只留一个占位，让经济不再派工、护送却看不见任务。
  父行动失效或被新战略/玩家改令替换时，同一输入立即解除占位与预算。[工人续行实验](worker-continuation-evaluation.zh.md)
  说明了这一前置：有工人和预算不等于可安全到达，不能在旧执行器之间再补一层手工交接。
- **单位状态分三种**：已分配、在路上、已到岗。目标的有效兵力只算已到岗的，加上按 ETA 折算的在路上的兵力，
  同一份兵力不重复兑现（修 L3、L6）。
- **在途任务也要重新评估**：已经出航的运输船、正在装船的部队都在分配表里，本土出现更高优先级的威胁时，
  分配器可以让它们返航或停装，代价按已投入的航程计算（修 E01、N(d) 环海）。

### 3.4 HTN 分解

每类目标有若干**方法**，每个方法有前置条件。条件不满足时生成**子目标**，子目标也进入分配和预算。

以夺岛为例：
- 方法 1，直接夺取：前置 = 该海域有空闲运输船、装船点有足够的清营兵力、滩头安全。
- 方法 2，逐批建立滩头：前置 = 滩头安全、首批兵力能自保。先登一批，后续批次按缺口补兵。
- 子目标：
  - 缺运输船 → 获取运力(海域)：有船厂就造船，并预留预算；没船厂就先造船厂。
  - 缺兵力 → 集结兵力(N, 装船点)：从其他目标借兵（交给分配器比较），或者训练（预留预算、占生产队列）。
  - 滩头不安全 → 清理滩头，或者换一个登陆点。
  - 清营、运工人、落矿厅、留守交接（沿用已经完成的岛屿任务链）。

守住据点的方法：就近小队 → 主力回防到矿口 → 塔下等待 → **跨海增援**（从别的陆块运兵，ETA 包含航行时间）→
**撤离并放弃**（守不住时救回工人，停止继续投入，修 E02）。

陆地扩张、进攻、争夺路口、驱赶骚扰也按同样方式写方法和子目标。缺反制兵种时产生“训练反制兵种”子目标（修 E08）；
需要持续兵力的清营不能用正在换代的召唤物凑数（修 L6）。

**预算账本**：每个子目标的金币预留都记在账本里，写明归属哪个目标、什么时候释放；目标失败或被放弃时一起释放。
这一步替代了现在散落在经济模块里的多处 reserve 和优先级前移（L 第 7 节）。

### 3.5 执行器

现有模块改造成执行器：输入是“目标 + 分到的单位/船/预算”，输出是“命令 + 进展事件 + 失败原因”。
执行器不再自己从全军里挑兵，只在分到的集合里做战术选择。命令仲裁统一：所有命令类型（包括 `follow`、`board`）
走同一条过滤路径（修 L4、N(a) 神泉殿）。

## 4. 岛屿与大陆为什么不会再冲突

不靠“岛屿优先”或“本土优先”这样的规则，而是靠同一套机制：
- 所有据点，不管在哪个陆块，都以同样的方式生成“守住据点”目标，用同样的方式计算风险和效用。
- 跨陆块的兵力调动是方法里的一个选项，它的成本里包含航行时间和运力占用。
- 在途的运输任务每次 think 都参与重新评估，本土出事时可以收回。
- 两个夺岛任务、夺岛和扩张，抢的是同一张分配表里的资源，由分配器统一比较（修 E06、N(e)）。

## 5. 计划链与可视化

每次 think 输出一份计划链，作为 #557 `AiPlanTrace` 的正式数据源：目标列表（效用分解：收益、成本、成功概率、
坚持加分）、选中的方法、未满足的前置条件、生成的子目标、分配（谁、到岗状态、ETA）、抢占记录（谁从谁那里拿了什么、为什么）、
预算账本。可视化里的“受阻原因”“为什么换目标”直接读这份数据，不再显示“—”。

## 5.1 死亡归因：每一次单位死亡都要说得清

主人的要求：任何一次单位死亡都要有归因，在执行什么行动时死的，是不是异常死亡。死亡账本是这一层最重要的
自检工具，也是判断目标层好坏的主要证据。

每次己方单位（包括工人、召唤物、船）死亡，记录：
- **谁、在哪、什么时候**：单位、种类、造价、所在陆块/甲板/船舱、死亡 tick。
- **被谁打死**：击杀者、击杀者种类与归属（敌方军队 / 野怪 / 塔 / 船 / 范围伤害），以及死前一段时间内承受的
  伤害来源构成。
- **当时在为哪个目标服务**：分配表里的目标与方法、阶段、到岗状态（已分配 / 在路上 / 已到岗 / 救命中断中），
  当前订单与下达这个订单的执行器；还没有分配表时，用现有的 claim、任务记忆和订单推断，并标明是推断。
- **死前的处境**：血量轨迹、是否在撤退或治疗、局部兵力比、是否超出该目标的范围（缰绳、驻守点）、
  目标当时的效用和是否刚被抢占或切换。

在此基础上分类：
- **正常战损**：在目标接受的交战中死亡，局部兵力比在目标的计划范围内。
- **异常死亡**，需要逐个解释，常见类别：
  - 在路上、跑腿或运输中被打死（购物、招佣兵、送补给、装船等待时）；
  - 闲置时被打死（没有目标、在集结点干等）；
  - 撤退或治疗途中被打死；
  - 被落在岛上或孤立陆块、没有撤离路线时被打死；
  - 刚被切换或借调、正在两个目标之间移动时被打死；
  - 超出目标范围追击时被打死；
  - 被野怪打死但不在清营目标里；
  - 召唤物以外的单位在“兵力磨损”判定后仍然留在交战区被打死。

账本进入计划链和可视化：可视化里每个阵亡标记都能点开看到归因。每局结束输出一份按类别的统计（次数、金额），
并列出所有异常死亡的明细，作为每一步迁移的主要验收数据：异常死亡次数和金额必须下降，不能出现新的异常类别。

## 6. 性能与确定性

- 每次 think 的工作量有上限：局势按事件增量更新；候选目标只保留前 K 个；分配是“目标数 × 候选单位”的贪心，
  用空间索引裁剪；HTN 只在目标或条件变化时重新分解，否则沿用上次的计划。
- 路线和 ETA 复用现有缓存（#546、#550 的做法）。
- 验收线：四军场景和后期海图 think 的 p95 / max 不超过 main 的 110%，同机 ABBA。
- 确定性：所有排序有稳定的次序，不用随机数和墙钟。只用于房间 AI（bootstrap_1）；v8/v9 对手不受影响。

## 7. 迁移顺序

每一步都可以单独合并，都用证据里的真实帧做场景测试（改之前失败、改之后通过），再在 7 张海图 + 4 张陆图上
跑 15 分钟真实对局，按席位给出目标时间线。不跑胜率 bench。

1. **只读的局势 + 目标 + 效用 + 死亡账本。** 只产生计划链和死亡归因，不改行为。死亡账本先基于现有的 claim
   和任务记忆做推断，跑出 11 张图的基线异常死亡统计，作为后面每一步的对照。用三份证据里的事件帧检验排序是否合理，例如
   E01 时“守本土”应高于“第二艘船出航”；N(e) 蓝宝 17991 时应能提出“借四兵 + 一班船”的夺岛方案。
2. **海陆防守与夺岛切片。** 分配器接管守住据点（含岛屿）、夺岛、增援前线、撤离，以及运输船。
   修 E01、E02、E05、E06、N(a)–N(e)。
3. **陆地切片。** 扩张、进攻、争路口、驱赶骚扰、新矿留守迁到分配器下。修 L1–L6、E03、E04、E08。
4. **预算账本和训练子目标。** 统一经济预留，缺兵、缺船、缺反制兵种都能变成训练/建造子目标。
5. **可视化接入**（#557 的后续）：用正式的计划链替换现在拼出来的 trace。

## 8. 怎样判断“有目标感、有侵略性”

不看胜率，看可观测的行为指标（每局、每席位）：
- 空闲兵力秒数（有兵没目标的时间）；
- 目标来回切换次数（A-B-A）；
- 据点受袭到有兵到场的时间，以及“兵在别处时据点被拆”的次数；
- 15 分钟内完成的目标数：扩张、夺岛、拆敌矿；
- 进攻或压制状态的时间占比；
- 抢占次数和它们的理由分布。

## 9. 分工建议
