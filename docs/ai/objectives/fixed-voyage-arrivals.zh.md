# 已分配航次的当前 ETA

`createArrivalQuery(...).fixedVoyageArrival(unit, target, voyage)` 只重新评估传入的物理船和原岸点；不从全军选船，也不重新选择装卸岸。`FixedVoyage` 不依赖分配表类型，传入当前阶段、真实船 ID、海盆、两个水侧点和已验证且带陆块标签的两个陆侧点。

- 人在船上：从该船当前位置计剩余航程、卸载和登陆后的步行。
- 人仍在出发岸且航次为 loading：到装船点的步行与该船进港并行，随后装船、原航段、卸载和步行。
- 人已实际卸在目标陆块：只计余下步行，船已离开或阵亡不再阻止已卸人员前往目标。
- 船、人、陆块或海盆不匹配；人未登船而航次已出发；或航次正在返回：输出 unknown 及结构化原因，不改用另一艘船。

结果仍是共享 `Arrival`，全部时长相对本次快照。调用方每次 think 刷新后可转成绝对 arrivalTick；不能把前一次相对时长当成当前剩余时间。已有实际登船关系优先于候选计划。该查询复用普通 ETA 的建筑感知地面场、海盆场、船速/风报价、确定性公布预算和惰性解释；预算未完成仍为 unknown。它与其他共享 ETA 一样是路线预测，不预测拥堵、战斗或原生船舶微操的完成保证。

真实 E01/E02 回归覆盖错过出航、错船、实际卸载、船当前位置推进、额外可用快船、原船失效、冷暖查询及 JSON fork。普通到达查询的数值与完整解释协议保持原样。
