# 动作暴露与威胁包络的第一级实现

依据 [统一风险模型约定](https://github.com/shuxueshuxue/sketch-rts/pull/589)及 main 的 [规划器 §2.6](https://github.com/shuxueshuxue/sketch-rts/blob/09630dd7/docs/ai/objectives/goal-planner.zh.md#26-执行中被打断统一的风险模型)。本说明供 32 审接口和预算；只提出第一级改造，不修改生产代码或排入当前缓存修复。

第一版只增加一个公共的包络计算和一张按 `UnitKind` 固定的拦截率表。地点安全、登陆安全与路线风险消费同一结果。已有营地战损、整组防御、原生武器与路线服务继续使用，不另外训练战斗模型，不加在线 Beta、区域热度、过期计时器或混合策略。

## 动作暴露声明

建议在 `GoalActionDeclaration` 增加可选的 `exposures`。每个执行器最终都要完整声明；迁移期间“缺声明”是未知，不等于空包络。下面是待 32 审定的 shape，类型名与字段尚未落代码。

```ts
type GoalExposure = Readonly<{
  id: string;                         // 内容版本短引用，不内嵌整条路线
  subjects: readonly GoalEntityReference[];
  carrier?: GoalEntityReference;
  protectors: readonly GoalEntityReference[];
  motion:
    | { kind: 'stationary'; at: Target }
    | { kind: 'route'; mover: 'land' | 'sea'; pathRef: string };
  interval: { from: GoalEventTime; until: GoalEventTime };
  interruption:
    | { kind: 'member-loss'; required: readonly GoalEntityReference[] }
    | { kind: 'capacity-below'; minimum: number }
    | { kind: 'force-below'; minimum: number };
  battleAccountRef?: string;          // 已有同事件战斗报价的版本证明
}>;
```

`GoalEventTime` 沿用声明的 start/finish/offset 口径。`pathRef` 引用共享服务发布的路线与时间标记，不复制几何进 ID、lease 或 event。调度推迟、换路径、换成员/船、武器/升级/HP 变化都要换相应内容版本并重读风险。ETA 粗估与精确值的 basis 要保留；偏差超过 50% 按 §3.1 重新报价。

- 集结/步行：按各成员真实路径和时间声明。共路、共时、同保护条件的组可以合并，不能拿最快成员时刻代替全部到场时刻。
- 调船/运兵/运工：航段以真实 carrier 为可受击物体，乘员作为同一次沉船的损失资产。deck/cabin 与武器能力按原生规则处理；不能把 cabin 工人放在海面上再算一遍陆军拦截。
- 装卸、施工：分别声明岸边等待、卸载后步行、施工驻点。逻辑矿点和实际施工点的硬位置绑定继续保留；安全海滩不代替矿点风险。
- 生产/训练：声明实际会暴露的 producer 或已出生单位；未来 binding 仅用于条件方案。出生前不能给未来船创建实际租约。船厂可能进入哪个海域用 harbor 决策口；精确出生位姿及出口拥堵不变成风险前置。
- hold/defend：声明完整 through 义务和具名保护组。当前报价/执行只读 `min(through, now + Situation.horizon)`，逐 think 滚动。到期前保持 in-progress，不能把一个已报价窗口当整段安全或完结。
- 等钱等无新增暴露的动作可以显式 `exposures: []`；它不免除计划内仍在执行的运输、施工或留守暴露。

声明属于动作层；公共世界读取函数只消费快照、原生能力、路径/到达事实和时间窗。它不读取 allocator、owner memory、任务 lease 或 FactWork。source 负责解析引用、核对授权成员、排队和版本发布；这样世界包络以后可用于战役剧情。事件仍是事实翻转加具名证据。

## 同一个包络怎样判定

对一个暴露片段 A 和一个敌人 e，保留三个结果：有证据可截到、已证明不能截到、计算尚未完成。风险报价的未知不能当 q=0。

1. 核对敌人活着、敌对关系、有效寿命、原生武器/技能能打到该类目标。静态塔用固定射程；中立营地先按原生 alert、有效追击、返营与响应边界限定可达区。场上弹道和持续伤害是已发生/正在传播的世界危险，不能用“敌人可能不来”把它们再打折。
2. 用空间距离和最大合法速度只做**不能赶到**的下界前筛。对整条路段取最短可能距离、最大武器触达，再与该段最晚经过时刻比较；筛掉必须有整段证明。大圆相交不证明可达，路段两端安全也不证明中间安全。
3. 复用同 source 已发布的原生陆路/海域距离场、Arrival 和武器触达事实，求一个合法的攻击位置与见证时刻。`enemyArrivalTick <= ownPassageTick` 才是进入包络的见证。到地点中心的 ETA 早，足以证明能到；中心 ETA 晚，不能排除远程武器早已够到，须读射击位置的到达证明。
4. 对路线内部仍有疑问的区间继续细化，或保留 pending。有限采样点只能给出正见证；没有命中采样点不自动证明区间之外。实现需给出区间下界或覆盖全部原生路径单元，不能偷偷把连续包络改成几个点的距离测试。
5. 粗 ETA 有误差时，用区间比较：敌人最晚到达仍不晚于我方最早经过，可确认为在包络内；敌人最快仍晚于我方最晚经过，可排除；其余只精化可能翻转决策的区间。同海域的时长仍可粗估，不能为了 ETA 重接全量船体 steering。
6. “足以打断”针对声明的结果门槛。杀工人、沉 carrier、把剩余兵力/运力压到需求以下，是不同事件；不能用无武器、打不到目标的敌人压低主力 P。护送和静防必须是本方案真实绑定且及时可达的组。复用现有原生能力/整组战损门槛，不增加固定余量或第二套克制表。

敌人单个打不过护卫、合起来却打得过时，不能逐个删出包络。先收集时间上可会合的真实敌人，再用该整组与实际保护组作一次有界门槛判断；首版不枚举 2^E 个敌方组合。未知的整组判断仍是 pending。已发布的防御报价须匹配整个组、实际 post、同一窗口及全部真实前置。

SiteThreat 的意图只标“当前在打什么”，不撤销敌人改道能力；常数 q 不再额外乘 `redirectProbability`。当前读全图，不需要“看不见后 120 秒过期”。将来有战争迷雾时，再由世界读取层提供最后位置和可达集合；不在这一版加入记忆模型。

公共结果建议包含短 exposure 引用、epoch、支持窗口、每个敌人的路径/见证引用、敌/我到达时刻、可打断门槛结果，以及 pending 依赖。`shore-safe`、`site-safe`、路线暴露和当前保护接口都从这份结果投影。原生连通、真实成员、出生/落岛、武器合法性等仍是硬条件；“有可达敌人”进入概率报价，不再自动要求先消灭所有敌人。具体谓词投影由 32 一次性定义，避免不同 reader 悄悄改变同名世界谓词的含义。

## 概率和损失只记一次

按每种 `UnitKind` 的固定 `qKind`，对一个动作中的具名敌人去重：

`P_A = product(1 - qKind[e.kind])`

同一个敌人碰到同动作的几个路段、同 carrier 上几名乘员，不能重复乘 q。拆成先后动作时，按 §2.6 的动作乘积形成计划 P；这是首版的独立性近似，报告要保留每项因子，不宣称已校准相关性。

一次中断的成本按 `(1-P_A) × (暴露资产损失 + 重推延误价值)` 进入原有 `GoalActionCost`，与收益使用同一 2400 折现时钟。船沉时船体与真实乘员各估值一次；不能把乘员同时当直接受击事件再赔一遍。资产购买仍是现金交换，实际中断后的既付款是沉没成本，重推只计算剩余动作和新增损失。

计划收益只包括该计划新增的目标收益；资产损失和延误项不得再次包含已由 `P × 收益` 扣掉的同一份目标失败收益。若延误已经体现在同一分支的完工折现中，不再加同一份收入损失。机会费仍由 allocator 计一次。

目标营地的到场离散、接战和战损已经由选中且完整报价的清营模型负责，沿用 `plannedCampIds` / `campContact` 的绑定排重：只有同营地、同组、同接触/窗口、已知 P/cost 的证明才能标为 `battleAccountRef`。旁观营地和外敌始终进入包络。未选中的营地、不匹配的报价、仅有一条“准备清营”的声明都不能免责。对于同一海上接战，也只能由旧 native voyage 损失或新包络事件负责一次，不能两者全额相加。

反制仍由普通动作报价：护送改变实际保护组和打断门槛，清除使具名敌人从世界里消失，换路线/时间改变经过时刻，塔和驻兵通过其真实战斗能力影响同一条件报价。第一级不另加地图风险修正或“有塔就随意减 q”的系数。

## 6144 额度和容量上界

令 E 为本 epoch 所有待查危险主体数，含敌方单位、静态火力、营地成员及需要检查的已在途危险；L 为选中/比较方案的原子暴露路段数，驻点窗口也算一段。不同成员的不同路径计入 L；同 carrier 的乘员不把同一航段复制 U 次。不是只数画在 UI 上的几条大折线。

建议逻辑计费上界为：

`W <= E + L + 3*E*L + H + B + V`

- E/L：扫描/校验共享危险索引与暴露声明；世界索引若已准备好，只收实际发生的增量，不能隐藏新建全图扫描。
- 每对最多三个有界步骤：能力/全段下界、读取一个已发布的到达/路径单元、写入去重与见证。若需要更多路径单元，展开为额外 L 或逐项记进 H，不能把任意长循环算成 1。
- H：所有新增原生距离场出队、路径覆盖/区间细化、必要局部几何的真实 work。必须是现有 source 服务；对一个 `(e,段)` 新跑完整寻路再按 1 记账不满足这个上界。
- B：每个暴露的整组能力/门槛报价的真实开销，复用已发布报价则只记查验。若现有 helper 没有有限 work 接口，先加可续算口，不能直接绕过队列。
- V：有界聚合与发布，包括逐个解析我方引用、估值真实乘员和验证保护组；每个被消费的风险因子、依赖验证都按项记，不在最后一个“完成”步骤藏全量遍历。

例如 E=64、L=8 时，索引与成对基础工作最多 1608，尚余 4536 给搜索、其他事实及 H/B/V；不是包络独享这 4536。E=128、L=16 时仅这一基础项就有 6288，必然跨 think，不能声称每帧完整重算。

source 只在既有 `FactWorkQueue` 上注册确定性游标，使用剩余 6144，包络游标每片最多推进 128 work；原生场仍沿已有片规在同一账本续算；零额度不做几何。同 tick 多次报价不重复花额度，完成后按既有 next-think 边界发布。队列/内存压力时保留 pending 和游标，不截断危险列表、遗漏路段、把未看完部分判安全，或提高上限。

路线、组、武器和风险内容只保存一份版本正文；动作/比较引用短 ID。缓存根包括已选方案与正在比较的对手，落选但仍有效的正/反证明按统一有界规则保留。路径/成员/威胁版本或窗口变化就失效；不得混用旧 epoch 的“安全”与新世界。冻结输入 K20 必须复用同版因子并收敛，动态输入则只在有真实依赖变化时重读。具体常驻字节数需要 32 的新缓存计量，本文不给未经测量的内存承诺。

## 常数 q 的离线校准

校准目标是 `P(实际打断 | 已在该动作包络内及给定暴露条件)`，不是全地图敌人的出现率、命中率或清营胜率。第一级只把离线校准结果固化成按 `UnitKind` 的版本表，局内不更新计数。

每条机会记录至少有：实际动作/具名成员与 carrier、真实经过区间、当时可见的敌人及能力、敌/我 ETA 见证、护送/塔条件、敌人是否实际进入接触/发起攻击、动作是否被中断、原生伤害/死亡/运力变化、归属动作与目标。一个敌人连续追同一次动作只算一次机会，不把每 tick 当独立样本。

- 首选冻结真实对局的完整 SDK 命令流与逐 tick 原生观察。无 AI 命令重放需先核每个 owner 快照与终局逐字同轨迹，再提取机会和伤害；这类验证实际使用 SDK/sim，不能标为纯 JSON。
- 只有实际经过、包络完整可核、结果窗完整的无护送机会，才给基础 q 提供正/负样本。没走这条路、等钱、因当前策略避开敌人、录制中断、稀疏帧之间未知经过，都不补成“安全通过”。护送/清除后的样本用于条件检查与反制验证，不与无护送基础机会混估。
- 一个机会有多个敌人但无法归属时，保留集合标签/删失，不把一次失败复制为每个敌人一次成功拦截。由原生 attack/damage/removed 和中断链确定归属；同一 owner 的 item 消耗不能替代实际参战组的消耗证据。
