# 战略观察：局势、海陆防守和夺岛目标

对应 [战略层设计](strategy-layer.zh.md) 的纯观察阶段。入口是 `planAiOwnerCommandEntriesWithTrace`；
普通 planner 先运行一次并返回已接受命令；其临时路由复用范围结束后，观察器在同一次 owner think 读取最终上下文，写入 `AiPlanTrace.strategy`。
分配、抢占、预算和 HTN 子目标都是报价，执行器仍按现有任务运行。
唯一新增的可序列化记忆是 `memory.strategy.observation`：确定性几何公布进度、航次事实版本，以及失矿与目标连续性的最小历史。
场数组不进记忆；previous trace 不再承担恢复这些事实的职责。

另有显式的常开边界 `planAiOwnerCommandEntriesWithDecision` / `buildStrategyDecision`，当前只供观测验收，未接管房间控制。
它返回 `DecisionFacts`：可达状态、ETA、航段、战力、效用、原因 code 和任务 source；数值图不包含 `evidence`、`detail`、`explanation` 属性。
常开入口不创建解释索引或保留投影闭包。调用方明确请求观测时使用 `buildObservedStrategyDecision`，
只有这个入口把解释读取器放在本次评估的旁表中；`projectStrategyTrace` 接受带观测类型的结果并投影完整格式，不重跑策略、路线或效用。
格式化函数定义在模块层，只接收 tick、标量和本次复制的 ID/时间列表，避免 getter 或读取器保留整个 think 的词法上下文。
跨 think 的航次缓存只存数值和完整值记录，不能存调用级读取器；失矿历史在写入可序列化记忆时仍保留原有归因字节。

原始快照索引、单次清营评估和本次中立营查询只在 `withStrategyFrame` 的同步作用域内复用，返回或抛错立即结束其存活期。
跨 think 的单位行和任务成员缓存只保存独立数值、ID 和已确认的地形位置；同一行的血量、位置、寿命、角色、承诺和 ETA 完全相同时才复用。
每份 AI memory 的两种行缓存各最多 2048 个 ID；无任务无 ETA 的地形行另有最多 2048 项，已知陆路 ETA 按相同 ticks 复用最多 4096 个纯数值结果。
容量淘汰只增加计算，不能改变答案；这些表不保存原始 unit、snapshot、调用级 reader 或解释对象。

strategy 的执行接线只覆盖 bootstrap 三个 policy：`v9_archer`、`v9_summoner`、`v9_knight`。
房间默认版本是 `src/shared/rooms.ts` 的 `v9_archer`，房间可选的另外两个版本也在覆盖内。
`v2` 冻结脑、映射到它的旧版本和 `v2-prod` 仍输出原 module-state trace，不经过 `observeBootstrapPlan`，没有这份 strategy。

## 同一份局势

`evaluateSituation` 提供所有陆块、海域、资产和活单位。连通块只取 `terrain.groundWholeAt` 的原标签，
使用 `land:<label>` / `sea:<label>`；资产、单位只在根表保存一份，区域表引用 ID。
甲板和船舱乘客使用支撑船的位置，既不算本土在岗兵，也不会把坐船的工人误记成岛上受威胁的独立工地。

据点包括每座己方矿厅，以及离同陆块己方厅 650 以外的独立资产。厅内工人、塔和矿的价值归到该据点，
避免同一矿口给每名工人重复算一份防守收益。矿的归属需要同陆块、320 范围内的完工厅；
收入是当前采矿订单、工位和维护费率的预测，无主矿的潜在收益不进入现金账。
丢矿历史仅来自观察记忆中上一帧的己方厅真实消失，并关联到仍有矿量的矿点；任务 complete 标签不能代替历史。

威胁复用 `incomingLandArmy` 的入场条件，以 45 秒为默认响应窗。局势层给它提供同一建筑占格、同一地面权重的
目标距离场，原执行器默认调用仍走原生路线。到岗强度与在途强度不重叠；运输中的敌兵只有观察到卸载目的地时
才按实际船和岸点预测；否则明确 unknown，不为每个候选岛编一条假设的敌方登陆航线。岸炮使用 `combatCapability` 的当前工作武器。缺失的距离场意味着未知，不能生成“安全”。

## 有预算的几何与 ETA

岸线按不可变地形在首次观察时一次建好。所有组件标签、岸点和陆块到海域的索引复用同一份，
地形对象替换后重新建立。岸点只要求水陆接触；小岛没有船厂占地，不代表不能登陆。

地面和海域距离场复用 terrain 的加权八邻接流场、建筑边缘目标种子和禁止切角规则。
建筑占格修订会使地面场失效。一次 think 每种 mover 最多推进一个目标场、2048 次队列出队；
完整场才对外可见，进行中的场返回 unknown。每个 owner 的请求顺序、绝对出队计数和公布 tick 在观察记忆中。
共享缓存即使被别的 owner 提前算满，也不能使本席提前公布；冷进程从同一计数重建搜索前缀。
已公布场的证据使用记忆里的公布 tick，不使用进程缓存第一次命中的时间。
每次 think 仍更新全部实体、资产、兵力归属和据点威胁；昂贵 ETA 只为保留任务、受威胁据点及少量粗筛机会计算。
机会按类别交错，避免中立矿挤掉全部进攻机会；候选兵按来源陆块/船选择足够强度前缀。
被裁剪的路线保持未知，不能当成不可达、零援军或已证实的训练缺口。

跨海细算的粗筛常数为 **K=2**：每次 think 先按陆块/海盆是否相接、直线航程下界、据点威胁、保留任务及收益上界选择两组来源—目标候选。
不是按 tick 跳过评估；每次 think 都更新粗事实。未入选且没有有效旧报价的组合是 unknown。
同船同登陆点的乘客共用航行报价，各人只补自己的步行速度和距离。
航次表按来源陆块、目标陆块/岸点、海盆以及物流事实版本保留，版本包含当前船集合的位置/运动极限/船首向、
船厂施工和队列、ferry 及等装船员的位置、风场和建筑占格。输入未变时不重算。
记忆只保存已公布表的键与证据时间，数值表留在加速缓存；冷 fork 可由同一输入重建已公布表。

观察记忆的整个 `strategy` 命名空间有 **64 KiB** 的 UTF-8 JSON 硬上限。
几何仅保存地形/占格版本、每 mover 最多 64 个目标的出队计数和公布 tick；航次版本最多 32 项，历史表最多 256 项。
超限按固定顺序丢弃旧历史报价、失矿历史、资产历史，再丢弃航次键和场进度，并保留 `observation-history-truncated` 提示；
缺失历史保持未知。饱和历史测试验证序列化上限，不靠自然对局恰好很小。
字节检查直接遍历 JSON 记录计算 UTF-8 长度，不为每次检查创建整份 JSON 字符串和编码缓冲；
特殊字符、代理对、非有限数字和省略字段都与实际 JSON 序列化逐字节核对。

当前数值缓存按命中曲线收窄为陆场 24、海场 32，每 mover 最多 8 个待算场；观察记忆仍可记录 64 个公布进度。
每个场只存目标所属原始连通块的包围盒。建筑只删除其中的通路，种子和可达区域不可能越出该包围盒；
仍调用同一份原生流场积分，出队顺序、公布时刻和结果不靠缓存改变。
完成后逐项检查整数代价：所有有限值小于 65535 才无损存成 Uint16，65535 专门表示不可达；超域保留 Int32。
下降缓存记录一个 Int8 方向，和原生 steering 共享同一套下降规则及打破平手的顺序。
五个真实事件帧的 30 个陆/海目标逐格代价哈希和采样平滑路线与 679464e1 的全图 Int32 结果完全一致；长走廊测试覆盖超域回退。
每个地形运行时另保留最多两个可复用搜索工作缓冲；只回收已与完成答案分离的 Int32 工作数组，
不会覆盖调用方仍持有的场或路线。中立营缓存按地形保留一份当前动态事实，逐营核对完整成员记录，
未变化的营复用冻结事实；成员变化只重建对应营，不积累历史帧。

最大图八方河湾为 10240×10240、320×320 格。即使每个连通块都覆盖全图，普通 Uint16 场及下降方向加待算 Int32 的数组上界为
`(3×(24+32)+4×8×2+4×2×2)×102400 = 25395200` 字节（24.22 MiB），其中最后一项是每 mover 两个搜索备用缓冲；
若所有完成场都触发 Int32 回退，数组上界为 35.16 MiB。
这只是当前几何缓存的数组上界，不能当作整房间新增内存已满足 30 MiB。
单进程逐图 maxRSS 的历史试验与最新服务器拓扑验收分开记录，不把整图数组上界当作验收结论。

服务器由 `src/server/index.ts` 创建共享 think 线程池，默认最多 4 线程，房间按 session 轮转到线程上。
每房间 open 消息单独传入 map，`host.ts` 按 session 保留；跨线程消息克隆后的 Terrain 对象各自作缓存键，
相同地图 ID 的不同房间也不会共享距离场。常驻的场、数值行和任务历史按房间累加；
V8 堆扩容造成的瞬时分配峰值按 worker isolate 计，不按房间数重复相乘。

当前内存验收分成两项：11 图完整对局结束后，GC 后每房间 `heapUsed + external` 的增量不超过 30 MiB；
另用真实 `createRoomHost` / `createAiThinkPool` 起 4 个 worker、8 个同时存活房间，
八方河湾、蓝宝、双岸、龟湖各 2 间，每间 1 个空闲人类席位，其余默认房间 AI。
main AA 先列噪声，两版各三次完整 18000 tick，报告服务进程树峰值的中位数、范围和 MAD；
候选整体峰值相对 main 增幅不超过 15%。同一 Node、冻结驱动和源档案运行，不开启 fork 全帧录制。
驱动只把 worker 的 planner 导入重定向到显式 decision 观察边界，原 room host、线程池、session、消息复制和交付校验都保留；
交付 tick 等待 worker 回答，避免主机负载改变命令流。八间房各自的完整 frame 哈希及终局 checksum 必须相同。
GC 诊断另局进行，不拿强制 GC 后的峰值代替服务峰值或 think 性能。

ETA 数值行以共享目标列和紧凑 values 保存；生产查询使用 `unitArrival`，只有完整投影或兼容调用读取 `arrivals` 数组时才创建原格式的条目。
读取旧 JSON 场景仍兼容普通数组。共享 getter 不捕获 evaluator 或 snapshot。
单次 evaluator 已持有这份结果，不再额外按 unit/goal 保存一份答案和直接陆路时间 memo；
跨人共享的装船腿、航行表和公开重复查询 API 仍保留数值复用。
响应名单和其他解释字符串只在明确观察边界生成，返回的读取器只持有已生成的字符串，不保留格式化闭包所处的世界。

receipt 记录并校验录制器绝对路径和 SHA256，另列模拟循环内 maxRSS 与最终校验哈希后的进程 maxRSS。
录制器不保留上一轮完整 strategy；模块变化只读取小型 module-state 历史，战略历史从 memory 恢复。

跨海预测分成：到装船点的步行、等船、装载、航行、卸载、岛内步行。步行与船的准备时间重叠，
不把同一段等待加两遍。已在 ferry 中的兵沿实际 from/to；忙船需要明确借用条件；新船需要船厂施工、
队列、训练、下水及驶到装船点的准备。新船和未来收入均是前置条件，不算现有运力或已预留现金。

船型原型按工厂位置复用，航段报价先按完整计算输入去重，再算风帆速度：

- 命名空间是不可变 Terrain，代表海盆几何版本；几何键是起岸点和终岸点。
- 价格键包括端点、船型、`shipMotionLimits` 的航速/加速度/转向率、当前统一风场的方向和速度。
- 固定岸点段按首段方向起航；实际进港段另带当前船首向，不混用这两种报价。
- 载重、平衡、索具/舵损、船体尺度通过共享运动极限进入键。船的 ID、乘客 ID 本身不改变同一运动模型的结果。
- 端点、运动极限、风场变化重新报价；地形替换同时失效几何和价格。容量上限逐项淘汰，避免整表清空的重建尖峰。
- 缓存一致性测试比较本 think 命中、跨 think 命中和强制重算，并覆盖上述失效输入。

航行几何从同一海域目标场下降并平滑，报价调用共享 hull/wind 模型；没有再逐名士兵跑整段联合寻路。
这些是预测：船体宽度、拥堵、未来风变和战斗仍属于实际执行。各路线报价也没有承诺联合的甲板装载时刻表。

## 目标、方法和旧任务

全线使用 `successProbability × sum(benefit) − sum(cost) + persistenceBonus`。
失败也付出的兵力时间、船体投资放在 cost；只在成功后支付的厅资本放在 benefit 负项。
清营沿用 `creepForce/forceFor`，与全局 field-strength 区分，不把同一数字当成两种战力。

| 目标 | 事实和报价 | 未满足时的计划元素 |
|---|---|---|
| DefendSite | 当前资产风险、在岗兵、来袭 ETA；按每股敌军抵达时间积分拆厅期限 | 就近小队、主力回防、跨海增援三个替代方法；迟于期限的兵不兑现救援 |
| ConquerIsland | 同一陆块上的矿、现有厅/守军、永久清营前排、航程与运力成本 | 借兵/训练、造船厂/取得运输船、实际滩头、送兵、清营、运工人、等收入、落厅、留守交接 |
| ReinforceFront | 据点或夺岛任务的明确缺口 | 指向父目标的收益，不能再凭空创造一份夺矿收益 |
| Evacuate | 濒危据点工人、实际存在的庇护厅和赶得及的路线 | 缺安全落点或运输条件时保持 blocked，不报价虚构救援 |

现有 claim、扩张、进攻、海军、购物和治疗等归属可以重叠，观察器把冲突原样保留。
接受的 `mobileCare/frontRecovery` 命令投影为治疗中断，同时保留原驻守任务；排队下发的命令与当前实际订单分开。
运行时直接消费现有选择结果，不为观察再跑一遍医疗选择器。

`ObjectiveFamily` 是陆地线的显式插口；所有 family 读取同一个 Situation。相同矿的效果标记为替代方案，
ReinforceFront 标记父目标；idleForces 跨 family 按 unitId 去重，只取最佳可行备选。
尚未接入的 family 保留 unknown，不能把“没有报价”解释成闲置最优。

`objectives` 是唯一实体表。只有可行报价出现在 `feasibleObjectiveIds` 并获得 rank；blocked 的 score、rank 都是 null，
另列于 `blockedObjectives`，包含缺失前置、前置满足后的条件潜在效用和每个替代 method 的成本。
几何、敌援或未定义的新兵报价不足时，潜在效用保持 null 并解释缺失事实。替代方法不相加，已计入效用的建厅/工人支出标注引用，避免再扣一次。
历史只为可行报价保留可用于借兵成本的已知分数；blocked 和终态分数保存为 null。

## 验证口径

事件帧检验事实、排序、前置和子目标依赖；另外逐字比较普通 planner 与观察入口的命令、原 policy 记忆和世界。
原 policy 指仅剔除各席位记忆根部的 `strategy` 字段，所有其它字段及嵌套字段均保留。
新增观察记忆单独校验：独立冷进程、其它 owner 预热、逆序目标预热、中途序列化恢复的记忆和 strategy 逐字一致，
并覆盖已公布航次表在冷进程重建后的证据时间。真实连续对局另截取 tick15000 的快照/记忆和之后同一命令流的世界帧，
在新进程中不传 previous trace，比较后续命令、strategy 和观察记忆。
