## 接口与边界

- [`createGoalRegenerate`](../../../src/ai/strategy/goal-regenerate.ts) 显式注册 provider。输入同时给出稳定选择器、全局化 bindings、因果前缀、实际拟议 start 和已发布读取口；不安装环境 resolver。
- [`replayGoalIncumbent`](../../../src/ai/strategy/goal-incumbent-replay.ts) 只重建选中步骤，返回当前小记录、临时完整声明前缀、首个 `repairFrom` 与明确的 known/pending/invalid/requote。临时 `prefix` 不能存进 owner memory。
- `startTick` 和前缀 `dependsOn` 是调用接口的补充；第 1 步的 wire、选择器及 plan/ready/decision 语义身份不变。
- 重放没有 allocator、SDK、预留、付款写入或原生推进口。当前实体必须 own/alive，当前 ready 层必须精确、事实当帧成立且实际引用可解析；未来 output 仍是条件引用。
- host 必须提供真实的当前引用解析、lease 冲突检查和完成安全窗重绑；投影位置/区域由已发布的 `readProjected` 口提供。缺查询保持 pending，起点偏差返回 requote。真实失效保留有效前缀并指出修复位置，修复搜索本身属于第 3 步。

start/offset/finish 的效果按发生时刻重放；排他 demand 按自己的 from/until 区间释放，持续动作的完整 finish/through 不缩短。
现金、单位池及运力逐事件检查；同原生奖励或收入区间不重复入账。世界事实与条件前缀分别读取，当前未观察到的投影效果不能取得 grant。
同一区域的池事实允许原点别名，精确 site/post 与区域身份仍严格匹配。安全窗按实际 finish 重绑；只有时长相对变化超过 50% 才记录软报价变化，不放宽死亡、区域、现金、lease 或过期窗口。

本笔不把已付款/已完成记录重新实现进搜索。正常 authority 接入和基于真实剩余成本的域重建尚待第 3 步；第 1 步付款/绑定迁移审计也不充作本笔新入口已跑真实购建的证明。

## 额度、账本与 CPU

保留原 6144 额度。重建、事实读取和 ledger 输入行/flow 消耗同一 allowance；额度不足明确 pending。纯函数不另开 native queue。
本笔减少重复账本开销：

1. 不同 tick 直接按时间排，同 tick 才建立因果事件图；独立 credit 仍不能跨过自身的 start 借款。
2. 一次临时重放内复用不可变资源键；每次 ledger 调用仍重新核对余额、source 和事件，不缓存过去的现金结果。
3. 同一个前缀的数量事实共享已验证投影；无 flow 步骤复用它，后续有 flow 时仍核完整依赖图。
4. 不同谓词 kind 不进入深层效果匹配。临时键表和投影均随调用结束销毁。
