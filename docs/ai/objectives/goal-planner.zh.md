# 目标导向规划器：动作声明与反推

状态：约定稿，主人已授权开工（2026-10-21）。补充 [战略目标层设计稿](strategy-layer.zh.md) §3.4，取代其中“每类目标手写若干方法”的写法。

## 1. 为什么要补这一份

设计稿定的范式是：局势评估 → 目标 → 满足目标需要的条件 → 满足条件的行为。缺条件时生成子目标，子目标和别的目标抢同一批资源。

实际接进对局的控制路径（#583，`src/ai/strategy/conquest-methods.ts`、`defense-methods.ts`）没有这样做：

- 夺岛的“方法”是一串写死的步骤：运兵 → 清营 → 运工人 → 等钱 → 建厅 → 留守 → 采矿。
- 所有方法返回的 `preconditions` 和 `subgoals` 都是空数组。`types.ts` 里已经定义了 `Precondition`、`Subgoal`，
  以及 `borrow-force / train-force / obtain-transport / build-shipyard / clear-beachhead / wait-income` 等子目标种类，但控制路径一个都没用。
- 缺兵、缺船、缺钱时只会报 `blocked`。前几天补的“集结”，也只是往配方里多塞了一步。

于是“有没有目标感”变成了“配方写得全不全”。每发现一个缺口就要手写一步，这还是 if-else，只是换了位置。
分配器和估值本身没有错，但它们现在服务的是一份写死的配方。

## 2. 范式：事实、动作、规划器

### 2.1 世界事实

规划器只读世界事实，不读任务状态。每个事实都由局势评估（Situation）算出，带状态和证据：
`met / unmet / pending`。`pending` 表示这次思考的计算额度里还没算到，已经排进事实队列，有限几次思考内一定会有结果。

第一批事实词表（只列夺岛和守家切片要用的）：

| 事实 | 含义 |
| --- | --- |
| `force-at(陆块或集结点, 战力, 截止 tick)` | 该处我方已到岗的战力，以及按 ETA 折算的在途战力 |
| `transport-in(海域, 容量)` | 该海域有可用的运输船，或在预计时间内空闲 |
| `shipyard-for(海域)` | 有能下水到该海域的船厂 |
| `production(兵种)` | 有能训练该兵种的建筑及空余队列 |
| `gold(数额, 截止 tick)` | 账本里未被预留的钱，或按收入预测到期能有的钱 |
| `worker-at(陆块)` | 该陆块上有可用工人 |
| `shore-safe(陆块, 登陆点)` | 登陆点附近没有会攻击上岸部队的营地或敌军 |
| `camp-cleared(营地)` | 营地成员全部死亡 |
| `hall-complete(矿点)` | 矿厅完工 |
| `site-safe(据点, 截止 tick)` | 威胁窗口内，据点处我方战力不低于来袭战力 |

事实词表只增不改语义。新增事实要写清怎么从 Situation 算出，以及算不出时怎样变成 `pending`。

### 2.2 动作

每个执行器声明一个或几个动作。动作由五部分组成：前置事实、效果事实、资源需求、时长估计、成本。例如：

| 动作 | 前置 | 效果 | 时长从哪来 |
| --- | --- | --- | --- |
| 集结(集结点, 战力) | 有可调用的兵，或在途补兵 | `force-at(集结点)` | 补兵预测（v2 两步法）+ 到岗 ETA |
| 训练(兵种, 数量) | `production(兵种)`、`gold` | 兵进入可调用兵池 | 生产队列 |
| 建船厂(海域) | `worker-at`、`gold` | `shipyard-for(海域)` | 建造时间 + 工人到岗 |
| 造运输船(海域) | `shipyard-for`、`gold` | `transport-in(海域)` | 生产队列 + 出口 |
| 运兵(集结点 → 陆块) | `force-at(集结点)`、`transport-in`、`shore-safe` | `force-at(陆块)` | 装船 + 航行 + 卸载 |
| 清滩头 / 换登陆点 | `force-at(滩头所在陆块)` | `shore-safe` | 战斗估计 |
| 清营(营地) | `force-at(陆块) ≥ 营地战力 + 余量` | `camp-cleared`，赏金到账 | 战斗估计 |
| 运工人(陆块) | `worker-at(出发陆块)`、`transport-in` | `worker-at(目标陆块)` | 同运兵 |
| 等钱(数额) | 无 | `gold(数额)` | 收入预测 |
| 建矿厅(矿点) | `camp-cleared`、`worker-at`、`gold` | `hall-complete` | 建造时间 |
| 回防(据点) | `force-at(可到达的陆块)` | `site-safe` | 到岗 ETA |
| 撤离(据点) | 有可达的安全落脚点 | 资产撤出 | 撤离 ETA |

动作只说“它需要什么、它让什么成立”，不写“它前面该接哪一步”。顺序由规划器推出来。

**数量资源有进有出。** 钱、可用兵力、运力这类数量，动作可以消耗，也可以产出：训练、建造、买船花钱；
清营按游戏规则拿赏金；采矿带来收入。每个动作的效果里要写明产出多少、在什么时候到账。
赏金就是清营的一个效果，不另写“打野挣钱”的专门逻辑。

### 2.4 数量资源的推算

只看“这个事实成立没有”不够。规划器推计划时，要沿着动作依赖图把数量资源的余额推算一遍：

- 每一步都检查余额。花钱的动作只能排在余额够的时候；产出钱的动作排在前面，后面的动作才能用到这笔钱。
- 先花后挣是允许的。只要整条链每一步余额都不为负，中间把钱花光也没关系。
- 一笔钱只能用一次。两个目标的计划用到同一笔余额时，由账本预留来裁决，不重复计算。
- 同一个缺口有几种补法时（等收入、清某个营拿赏金、少建一样东西），都作为候选，按时间和成本比较。

### 2.5 规划器：从目标效果往回推

每个目标给出要成立的效果事实。规划器做回归搜索（GOAP 式）：

1. 取目标效果里还没成立的事实；
2. 找效果能让它成立的动作，作为候选；
3. 对每个候选，把它的前置事实当成新的待满足条件，递归下去；
4. 已经成立的事实到此为止；`pending` 的事实也到此为止，计划标成“等事实”，不算失败；
5. 同一个条件有多种满足方式时（借兵还是训练，造船还是等船空闲），按成本比较取最便宜的，落选的方案和原因一起保留在计划里。

输出是一张动作依赖图。前置已经全部成立的动作是**就绪动作**，它们向分配器申请资源；其余动作就是**子目标**，
在计划链里看得到，但还不占资源。

搜索有上限：深度、每个目标每次思考展开的节点数，都有固定上限，计入同一次思考的 6144 额度。
排序稳定，不用随机数和墙钟。计划会缓存：路径上的事实没有变化时，下次思考直接沿用；有事实翻转（营地清了、船沉了、兵死了）时，从那一点重推。

### 2.6 执行中被打断：统一的风险模型

对手不会等计划走完。运输船半路被击沉、工人被游击兵截杀、登陆点来了敌人、本土矿厅遭袭，都是同一件事：
动作执行期间，有敌人能赶到并打断它。规划器不为每种干扰写规则，而是给每个动作算一个“不被打断”的概率，进入 §3 的报价。

**动作的暴露。** 每个动作声明它的暴露：哪些我方单位、在什么时间、经过哪些位置（运兵是船和兵走一条航线，
运工是工人走一条路，留守是兵在一个点守一段时间）。

**威胁包络：谁能来。** 敌方单位 $e$ 用真实寻路距离和速度算出赶到暴露路径上每一点 $x$ 的时刻 $t_e(x)$。
只要某一点 $t_e(x) \le t_A(x)$（我方经过该点的时刻），且 $e$ 的战力足以打断这段暴露，$e$ 就在动作 $A$ 的包络 $E_A$ 里。
敌人此刻离得远不代表安全，只要它赶得回来就在包络里。当前 AI 读全图单位；以后有视野时，看不见的敌人按最后位置加上经过时间内能走的距离计算。

**拦截率：会不会来。** 包络里的每个敌人给一个拦截率 $q_e$，于是
$$P(A\ \text{不被打断}) = \prod_{e \in E_A} (1 - q_e),\qquad \text{期望损失} = (1-P)\times(\text{暴露的单位价值} + \text{重推造成的延误})$$
计划的成功概率是各动作的乘积，代替原来的固定余量进入“P × 收益 − 成本”。

**反制是普通动作。** 护送抬高“战力足以打断”的门槛，清除把敌人移出包络，换路线、换时间或等待改变 $t_A(x)$，
建塔、驻兵压低一片区域的拦截率。它们都按成本和其他方案比较，不另写“遇到骚扰怎么办”。
骚扰者本身也可以是目标，追得上、打得过就按普通目标报价。

这个模型直接给出几种行为：敌人退到附近再回来，仍在包络里，再派人就是送死；一个兵的骚扰只进本土两个兵就能处理的包络，
不会压低主力计划的概率；来袭大军进入留守动作的包络，按到达时间比较守家还是夺岛。现有的 `shore-safe`、`site-safe` 和路线暴露
都改由同一个包络计算：是/否留给“做不做得成”的硬条件，概率进入报价。

**从简单开始。** 按“AI 表现 / 模型复杂度”逐级加项，每加一项都要说明哪道题或哪局真实对局因为没有它而失败：

1. 第一级：包络加按单位种类给的常数拦截率（先验，用真实对局校准）。先用它过题 8–10。
2. 第二级：只在第一级被题或对局证明不够时，再加计数。每个区域、每类敌人按“经过 $n$ 次、被截 $k$ 次”更新
   $\hat q=(a+k)/(a+b+n)$。只有不带护送并安全通过才计入 $n$，等待的时间不算，$k$ 和 $n$ 按分钟级半衰期衰减。
3. 更后面才考虑：带种子的随机护送（混合策略），用来对付专门研究我们确定性规则的对手。

**执行中的记账。** 下面几条和风险模型无关，是被打断之后的记账规则：

- 损失由世界事实确认：船沉、兵死、工人死，看快照里单位消失和运力、兵力事实的变化，不靠执行器自报。船上的兵随船损失。
- 已花的钱不再计入：重推只报剩下的链。目标承诺和账本预留按 §3.2 保留，不因一次损失自动释放。
- 执行器报告中断时写明哪个敌方单位、在哪里、什么时刻；这个敌人随后按上面的模型进入相关动作的包络。
- 重推后精确报价净值不大于 0 时明确放弃，记录原因，释放未用预留。暂时缺报价或没有可行路径不等于放弃（§3.2）。
- 被打断造成的死亡在死亡账本里归到当时的动作和目标，标为“被敌方打断”。

## 3. 和分配器、估值的关系

- **分配器不变，只换输入。** 它比较的是各目标计划里的就绪动作：谁拿到哪些兵、船和钱。抢占、交接、推迟损失上限、救命中断留下的空缺，都沿用 #583 已经做好的机制。
- **估值变成动作成本和目标收益。** 计划价值 = 成功概率 × 目标收益 − 各动作成本之和，时间按依赖图的最长路径来算。已经校准好的部分（补兵预测、伤亡模型、续行现金流）直接作为动作的时长和成本使用。
- **不再为某个配方单独打磨估值精度。** 估值只需要能比较不同计划。
- **一个计划一个报价。** 计划净值 = 成功概率 × 目标收益（按关键路径完工时间折现）− 整条链剩余动作的成本。同一计划的就绪动作打包，共用这一份净值，再扣一次这批资源的机会费用；净值不大于 0 的计划不进分配器。跨目标抢同一批资源时，比的是对方计划因此推迟或减员的损失。

### 3.1 精化只为会推翻决策的事实

搜索先用粗估（陆块和海域连通、已有距离场、海岸联系点），只有选中计划里的就绪动作才请求精确事实。
只有会改变“做不做、怎么做”的事实才必须是精确值，例如登陆点安全、营地战力、建址。只影响时间的事实（同一海域内的航行、陆路行军）用粗估时间放行，精确值在后台算，回来后更新计划时间；偏差过大时重新报价并记录偏差。

### 3.2 规划器接管的范围

`strategyControl` 打开时，规划器接管 collector 产出的目标种类（守据点、夺岛、扩张等）：
- 这些种类对应的旧 mission 不再开新任务，由规划器的计划来做；规划器还没覆盖的种类，旧脚本照旧。
- 已经在跑的旧任务，它的进度（装上船的兵、在途的船、已付款的地基）是世界事实，规划器把它当作当前状态接着规划，不算抢占成本。只有计划要把这些单位改派去做别的事时，才按真实的推迟或损失报价。
- 不能让规划器和旧脚本为同一个目标互相竞价：那样规划器要付“抢占在职任务”的上界，计划会被判成亏本，永远不出手。

`strategyControl` 关闭时一切照旧，命令流必须与 main 逐条一致。

## 4. 这样做以后，“缺条件”会自动推出计划链

同一套动作，换不同局势，能推出不同的链，不需要为每种情况写代码：

- 岛上营地要 6 战力，手上只有 2：推出 集结 → 运兵 → 清营 → 运工人 → 建矿厅。
- 这片海没有运输船：在前面接上 造运输船；没有船厂，再接上 建船厂。
- 登陆点旁边有营地：接上 清滩头，或者改用另一个登陆点，看哪个便宜。
- 钱不够建厅：接上 等钱，并在账本里预留。
- 主力在岛上、本土据点被打：守家目标推出 运兵(岛 → 本土) → 回防。这和夺岛用的是同一个“运兵”动作，没有单独的“跨海增援”方法。

这就是验收“范式是否成立”的方法：在证据帧上，不写新代码，只改局势，看能不能推出上面这些不同的链。

## 5. 计划链与可视化

计划链要显示每一层：目标 → 哪个条件没成立 → 推出了哪个动作（落选的方案和原因）→ 谁在执行、走到哪一步 → 结果。
阵前手记的叠加层（#576）改为读这张依赖图，不再只显示分到了哪些兵。

## 6. 迁移

1. **只读规划器。** 定事实词表，给现有执行器写动作声明，实现回归搜索。只输出计划链，不改行为。验收：
   - 所有事实都成立时，推出的链和现在写死的配方相同；
   - 在证据帧上（蓝宝 N(e) 17991、E01、E02、E05、E06），改局势能推出 §4 列的那几种不同的链；
   - 计算额度计入 6144，同样输入在冷、热进程下推出的结果逐字节一致。
2. **夺岛和守家改由规划器控制。** 用规划器的输出替换 `conquestMethodProvider` 和 `defenseMethodProvider`。
   门槛和以前一样：先跑 600 帧六哈希；没有派兵时，191/278 条命令逐条一致；再两图从开局跑满 18000 帧，
   按逐岛时刻表和 baseline 646 对比。
3. **陆地动作。** 扩张、进攻、争路口、驱赶骚扰都写成动作。缺反制兵种时，推出 训练(反制兵种)（修 E08）。
4. **经济动作补齐。** 训练、建造、预留都走规划器加账本，替换经济模块里分散的优先级前移。
