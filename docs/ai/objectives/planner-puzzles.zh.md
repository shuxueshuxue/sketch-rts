# 规划器残局题库（公开部分）

配合 [目标导向规划器](goal-planner.zh.md)。每道题就像象棋残局：局面摆好，看规划器能不能自己推出走法。
题目考的是规划能力，不是某张地图，所以每道题都要用真实规则搭成场景（`*.scene.test.ts`），
不能手写一份假的事实表喂给规划器。

## 题库分两部分

- **公开题**（本文件）：开发时随便用，各条线都可以往里加题。
- **保留题**：只有总指挥知道，不进仓库，不发给任何一条线。规划器冻结后由总指挥搭好场景，只跑一次，
  结果原样报告。用过的保留题转为公开题，同时补一道新的保留题。

公开题和保留题考的是同一类能力，但组合方式不同。所以靠背公开题的答案，过不了保留题。

## 每道题怎么判

1. **计划检查**（冷帧，不推进模拟）：规划器输出的依赖图要满足“必须出现”和“先后顺序”，不能出现“不该出现”。
   不要求和参考答案逐字相同，有几种走法都对的题会写明。
2. **执行检查**（从这一帧开始推进真实模拟）：在时限内达成目标，期间没有违反“不该出现”。
   从2026-10-21 19:34起，必须逐步骤检查归属：题目要求的每一步都要有对应goal动作的实际命令，
   匹配SDK原生应用记录，并观察到该步骤自己的物理效果。gateway接受或一条任意goal命令不能代替整链。
   SDK应用记录来自运行器应用帧之后的onCommand钩子，保留实际owner/scriptId/命令/时刻；不能只拿一条相同参数的原生命令猜归属。
   调船核船到达，运输核真实装船后在目标陆块卸载，清营核指定原生尸体，建厅核该goal命令对应的精确地基完成；
   跨generation续行只按同目标、同实际船与人员关联，不能把旧token改写成新token。
   旧脚本完成的步骤单列“旧代码完成”，该题不能算规划器通过。已有地基按§3.2接手时，也要有goal的真实继续施工命令和后续完成证明。
3. 每道题的每个变体都要过。变体就是改一个数（兵的数量、钱、距离），看计划会不会跟着变。

冷帧使用同一份冻结快照、连续传递同一份owner memory，最多20次think，每次仍遵守6144的服务预算。
从2026-10-21 18:28的约定起，稳定比较最后3次think：选中动作的种类、排列顺序、动作间依赖和每个动作参与的单位集合均相同，才算结构稳定。
动作ID可能编码时间和坐标，比较时以选中图中的动作序号对应身份；事实节点只用于还原它连接的动作依赖。
增删动作、换顺序、换参与单位或依赖变化仍判不稳定。训练/建造对象的种类也属于方案选择。

时间、航时、坐标、报价等数值变化不改变结构稳定结论，但必须逐动作列出末三次的值和变化量。
原因是冻结世界里精确事实仍按think边界分批发布：公开题1 near的488c原片中，第19次才读到新point时间证据，
航时669→719、登陆点纵坐标240→304属于新信息带来的正常重报价，不应单凭这些数值变化判方案不稳定。
已启动的488c/2478e44d一轮保留原完整数值hash判法和原失败结果，在报告中用同一原片并列新结构判法与数值delta；
新的运行判法从下一轮源码开始生效，不重写旧轮或替换正在运行的验收头。

### 工人的真实安全要求

从2026-10-21 23:39起，夺岛题不再要求“清营后才能把工人送上岛”。这条旧顺序只是在代理“别让工人送死”：
d888原片里，工人先落在距矿约996的安全远滩，营地仍在，矿点仍被判不安全。运输和清营可以并行，不能因为不是参考走法就判失败。
新版执行检查改为：

- 未清营地仍在时，工人不能进入它实际可达的警戒范围或活动追击范围，也不能受到营地伤害。
  使用原生警戒、可达性、舱内保护和活动状态；650是原生追击/响应边界，不是idle或返营单位的自动索敌半径。
- 接受goal.build时，原计划必须同时有逻辑矿点和精确施工点的site-safe证明，两条身份及finish窗口均须匹配；
  state必须为met，observedTick为当帧，availableTick不晚于当帧。海滩安全、别的点或远期met不能代替。
- 工人全程不能死亡；逐原生damage/removed事件检查，包括营地残留弹丸、状态和沉船等死亡来源。

正在运行的d888/8bc保留旧顺序断言、原进程退出码和完整轨迹。新版结果另列，不改写旧结果。
该轮未事先记录所有伤害事件，因此以完整原SDK应用流做无AI命令重放：逐个原think和终局的完整snapshot必须一致，
才接受重放中每tick的范围检查及原生伤害/死亡观察；不一致就报告缺证，不能用相邻快照HP相同推断全程无伤。
重放是同一条原轨迹的派生验证，不增加AI对局分母，也不能补造规划器的site-safe事实。

## 公开题

### 1. 船在别处

- **局面：** 大陆上有主基地、工人和足够清营的兵。附近小岛上有矿，矿旁有一营弱野怪。唯一的运输船停在远处另一段海岸。钱够建大厅。
- **目标：** 在岛上的矿建好大厅。
- **必须出现：** 满足装船位置后运兵、清营，安全地运工人并建大厅；运工可与清营并行，建厅须等矿点site-safe。
- **变体：** 运输船就在装船点旁边，计划里不应该再出现“调船”这一步。
- **考的能力：** 运力的位置也是一个前置条件。

### 2. 人口卡住了

- **局面：** 要清的营地需要骑士级别的战力。钱够训练骑士，但人口上限不到骑士要求的档位。
- **目标：** 清掉这个营地。
- **必须出现：** 先造农场，人口到档后再训练骑士。
- **变体：** 改成用步兵凑战力，钱也够、人口也够时，规划器应该比较两种方案的时间和成本，选更快的那个。
- **考的能力：** 看不见的前置条件（人口档位），以及多个方案之间的比较。

### 3. 从零造海军

- **局面：** 大陆上有兵、有工人，没有船厂，也没有船。钱够建船厂、造运输船，再加上建大厅。岛上有矿，矿旁有营地。
- **目标：** 在岛上建好大厅。
- **必须出现：** 建船厂 → 造运输船 → 运兵 → 清营 → 运工人 → 建大厅。
- **先后顺序：** 建大厅要预留的钱，不能被造船提前花掉（账本里要看得到这笔预留）。
- **考的能力：** 4 层以上的前置链，以及钱的预留。

### 4. 守家还是夺岛

- **局面：** 主力在大陆，只够做一件事。侦查到敌军约 90 秒后到达本土一座矿厅。另有一座岛可以夺。
- **目标：** 两个目标同时存在，让规划器和分配器来定。
- **必须出现：** 先守矿厅，守完再去岛上。
- **变体：** 敌军要 6 分钟后才到，而夺岛一个来回只要 3 分钟：这时应该先夺岛，并且在敌军到达前回防。
- **考的能力：** 时间窗口，两个目标抢同一批兵。

### 5. 滩头有人守

- **局面：** 离岛最近的登陆点旁边有一营野怪。另一个登陆点是安全的，但多绕 40 秒航程。
- **目标：** 把兵送上岛去清目标营地。
- **变体 A：** 兵力够顺手清掉滩头的营地：走近的登陆点，先清滩头。
- **变体 B：** 兵力不够清滩头：走远的那个登陆点。
- **考的能力：** 同一个条件（滩头安全）有两种满足方式，按代价选。

### 6. 不划算就不去

- **局面：** 岛上的矿只剩很少的矿量。矿旁的营地很强，清掉大概要死三四个兵。
- **目标：** 有夺岛的选项，同时有别的事可做（比如本土扩张）。
- **必须出现：** 不去夺这座岛，兵去做别的事。
- **不该出现：** 派兵去清这个营地。
- **考的能力：** 收益为负时不行动。侵略性来自“空闲兵力找到有价值的事做”，不是“什么都去打”。

### 7. 守不住就撤

- **局面：** 岛上有一座我方矿厅和几个工人。一支远大于我方全部兵力的敌军正在登岛。附近有一艘运输船。
- **目标：** 尽量减少损失。
- **必须出现：** 运输船去接工人撤离。
- **不该出现：** 把大陆上的兵送上岛去送死。
- **考的能力：** 撤离也是一种计划，“守住”不成立时要能换目标。

## 加题规则

- 一道题只考一两种能力，写清楚“考的能力”。
- 题目用游戏规则描述，不点地图名，也不写单位 ID。
- 参考答案只写必须出现、先后顺序和不该出现，不写具体的 tick 和坐标。
- 新题先在 main 上跑一遍，确认现在的 AI 确实做不对，再收进题库。
