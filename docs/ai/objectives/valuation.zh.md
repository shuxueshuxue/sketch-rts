# 战略估值的共同口径

所有目标用 `P × 收益 − 成本 + 持续奖励`。P 比较同量纲的实际我方、实际对手战力，敌援按真实到达时间评估。出发安全余量只写进方法的兵力需求，不再进 P 或战损分母。清营的整组远程齐射不能拆成逐人战力相加；实际营力不含 `forceFor` 的余量。

`valuationWindow` 以本帧为共同计价起点，视野为任务预计时长加 120 秒持有期，折现尺度为 120 秒。一次效果用 `discountedValue`；矿收入用 `discountedFlow`，积分到视野结束或资源耗尽。比较次优用途时，用请求方的同一份 window 重新报价，不能拿另一个时间窗下的旧 score 直接相减。扩大持有期可能让延迟但持久的矿收入超过一次性战利品，这是明确的经济取舍；相同时间分布的收益支配关系应保持。

船和厅都是资产。`reusableAssetCost` 给出任务后残值（价格乘存活概率）、期望损失和损失的现值。现金准入仍检查完整造价，经济成本只算未来期望损失；旧船已付造价不再收一次。新厅只在成功后建造时，期望资产损失写进负收益项。存活概率必须来自实际风险事实，未知不能假装成 100%。整组机会成本另收一次，不能同时在每条船、每个兵上重复收。

报价分两轮。gross 计算收益、实际战损、资产期望损失，不调用机会成本函数；net 对所用的完整兵船组调用 `resolveValuation`。框架把可行次优目标在有这些资源与失去这些资源时的整组收益相减，并通过 `quoteOpportunityCost` 选择不重复占用相同资源的备选。不再按固定兵价乘时间收费，也不按兵力比例分摊旧目标总分。

明确没有正效用可行次优用途的闲兵，机会成本为 0。已经实际执行的承诺，如果失去这些兵后的损失未知，则 net 报价仍 unknown，不伪造 0。尚未启动的可行备选若缺少减员后报价，可保守以上述备选的全部正效用为上界，必须标出 `conservative-bound`。blocked 报价从不冒充 0 分的可行备选。同一收益的不同方法、支撑目标在进入报价列表前按效果去重；borrow/train 是替代方法，不能相加成本。

只认可核实的拆厅、断矿、施工延迟等收益，不再用敌军战力乘响应时间编造 pressure 收益。旧 ETA 中 `beyond-evaluation-window` 只证明超过旧评价窗；新窗口更长时，没有结构化下界就保留 unknown。

公共接口是纯只读的 `types.ts`、`utility.ts`，不依赖控制实现。`PlanningContext.valuation` 给出 gross/net、共同 window 和整组机会成本回调；`unavailableUnitIds` 用于给同一候选重报价，不能暗中拿别的目标的兵补满。Objective/MethodQuoteFacts 的 valuation 元数据保留所用资源与窗口。只有完整 net 报价可用于正式分配；gross 不是已扣除机会成本的承诺收益。

## 原生生产通道的机会成本

`ProductionUse` 显式记录 buildingId、lane、相对当前 think 的半开占用区间 `[fromTicks, throughTicks)`。training 对应原生 `building.queue`，research 对应 `researchQueue`，两者在同一 tick 独立推进；同一建筑不自动意味着互斥。只将同建筑、同通道、时间重叠的生产作为次优方案资源冲突，现金仍由共用预算竞争。

两轮 oracle 支持只有生产资源的请求。重报原方法时保持同一单位组，并将请求占用区间作为 `unavailableProduction` 传入，报价方必须按实际队列接续/延后结果重算。没有已核实替代训练用途时不收固定队列时间费；已有真实承诺但无法重报时保留 unknown。既付原生队列不得取消或重复收费，其等待时间仍计入真实完工 ETA。
