# 目标搜索实现：当前计划与可续算游标

状态：实现约定，待评审；本文件不宣称生产已按此实现。依据 [规划器 §3.1](goal-planner.zh.md#31-保留当前计划按需精化挑战方案)，先合文档，再分块改代码。
风险报价继续遵守 [§2.6](goal-planner.zh.md#26-执行中被打断统一的风险模型)，不会在这次搜索改造中另加风险模型。

## 1. 常驻什么

每个目标的搜索 memory 只有两个逻辑条目：

| 条目 | 保存内容 | 不保存什么 |
| --- | --- | --- |
| `incumbent` | 当前选中步骤的 provider、grounding key、bindings、相对时刻、已确认数值与预测 basis，以及重放所需的依赖关系 | 完整声明副本、整张事实图、替代方案集合 |
| `cursor` | 可续算 DFS 的栈、下一候选位置、当前前缀、正在精化的唯一候选、依赖版本和有限计算游标 | 所有已经枚举的声明、常驻对手、否决报价表、第二份搜索图 |

正在精化的候选属于 cursor，不是第三份常驻计划。原生计算继续留在已有 geometry、field、route、voyage risk 服务中；
不因删掉报价 memo 而重做已有的原生查询，不另开寻路器或计算额度。
发布缓存命中仍有读取、重建和数值聚合的 CPU 成本；“不用重新推进原生查询”不等于“整次 provider 调用没有成本”。

已授权动作的 intent、generation、lease、issued command、付款、输出绑定、训练 job、世界收口事件属于 authority。
它们不塞进上述两条搜索记录，也不因搜索记录被回收而失效。
collector 本轮不再产出目标，也不撤销已经承诺但尚未完成的目标。

### 1.1 稳定身份

grounding key 是域选择器：明确哪组单位或哪个池、哪条生产关系、哪个逻辑目标和哪个接触选项。
它不能递归嵌入完整事实或动作声明，不用截断 hash 判等，不以遍历顺序生成语义身份。
可以用小型结构化选择器和计划内本地步骤引用；引用只指向 producer 步骤及输出槽，不把 producer 的正文再抄进去。
修复未改变的步骤时沿用其引用；跨 JSON 和冷进程恢复后，同一选择器仍指同一物理方案。

已有实体绑定必须是当前真实 owner/alive 的实体。未来 output、binding 和 pool-member 是条件引用，不能借原型获得 entityId、SDK 权限或 lease。
授权时仍由正常分配口把引用解析成实际对象，并保存与原步骤的对应关系。
比较和切换统计用 provider、grounding、实际 bindings 及依赖拓扑，不用临时版本号或绝对 tick。

## 2. 每次思考的顺序

### 2.1 先重建当前计划

provider 重建需要当前快照、已发布事实、选择器、实际 bindings 和确定性的因果前缀。
不能只拿 snapshot 加一个 key 调用后，默认未来位置已经出现在世界里。
例如四兵仍在本土时，前缀的运兵效果可以为后续集结提供一个条件来源，但不是“世界观察到四兵已经上岛”。
重建函数不发 SDK、不创建 authority，不私自发布新世界事实；缺少事实时返回明确的 pending/请求，由原 source 统一排队。
相同输入和已发布事实必须生成相同声明；CPU 时间另行实测。

重放时分别处理：

- 效果在 start、offset 或 finish 生效；依赖按真实生效时刻连接。
- 排他资源到 finish 才释放，不能因为某个效果已在 start 生效，就提前把同组单位再借给另一个动作。
- 数量资源按事件检查，每个前缀余额非负；同一营地赏金、同一收入区间和同一笔现金只计一次。
- 安全窗按实际排程重新绑定；同 finish 的动作按依赖边拓扑排序，无依赖的动作按稳定语义键排序，不能用编号反转因果。
- 已完成的世界效果、已付款资产和在执行中的真实动作，从 authority 与世界证据接入，既付款不再报成未来成本。

单位死亡、陆块错误、安全窗过期、现金不足、lease 冲突属于硬失效。立即停止把相应的未授权后缀当作 ready，从首个失效步骤修复；
有效前缀仍保留。正在执行的动作是否中断、交接或撤离，仍走正常 allocator/executor 规则，不由搜索直接删任务。

δ 只控制软报价变化的重估，不能豁免上述检查。报价重建后按当前数值估值，不借 δ 把旧值当作新证明。
同一海域 ETA 等只影响时间的预测允许粗估；真实位置或后台结果到达后，相对时长偏差超过 50% 就重新报价并记录影响。
其他软阈值若要引入，必须先写明单位、固定值及证据，不能把未定义的 δ 藏进实现。

### 2.2 续算 DFS，寻找挑战方案

DFS 沿未成立效果回归 achiever，并确定性地推进游标，不在第一次找到一条完整路径后永久结束搜索。
有 incumbent 时继续找能改善它的方案；没有时先找因果完整、净值为正且有合法首层的方案。
一个候选未完成、事实 pending 或额度耗尽，不得顶掉仍有效的 incumbent。

cursor 的依赖包括两类：

1. 已考虑分支所依赖的事实和发布版本；
2. 决定候选集合的版本，例如池成员、生产能力、可用船和新发布的接触选项。

新船出生可能产生更好的路线，即使 incumbent 自己的前置没有变化，也要使相关的已穷尽游标重新开放。
只重启受变化影响的部分，不以全局 refinement revision 或所有敌人的完整状态强制重启全部目标。
每个被否决候选由 DFS 移向下一个候选；不另存它的报价副本。

### 2.3 每目标最多推进一个挑战方案的精化

每个目标每次思考最多选择并推进一个挑战方案。一个方案可能跨 think 等待原生事实；额度不够就保存当前游标，不能为了“一次完成”多开预算。
所有目标先注册再共享原有 6144 work；原生场、搜索、风险及其他事实竞争同一额度，原发布边界不变。

**完整指因果图闭合，ready 指有可执行首层。** 当前可以 grant 的层必须通过精确的决策事实、实际对象绑定与资源检查。
未来后缀仍可有带前提的预测：尚未出生的船不能提供真实航线证明，尚未完成的厂不能提供真实生产者证明。
因此不要求整条未来链所有动作都精确且现在 ready，也不为了补齐这种证明而卡住第一步建船厂。

未来船的下水点、同海域航程与 ETA 继续粗估；船出生后读真实船，再按 50% 规则重报价。
船厂乘船型的可进入海域集合是决策事实；实际海域选择、需要的 rally 条件与未来预测必须有明确绑定。
不把精确下水姿态、当前出口拥堵或完整 steering 排序接成开工前必须等完的证明。

### 2.4 比较后决定是否替换

先重建双方当前可得到的报价；已有发布结果可以重建的挑战者，不能故意拿更乐观的粗价和 incumbent 的精价比较。
双方用同一个世界版本、同一收益折现时钟和同一未来预测口径。
未来后缀中的未知必须显式标注，不得冒称完整精确世界证明。

挑战者必须因果完整、当前 grant 层精确且 ready，并且当前比较价值高出有效 incumbent 超过 ε，才替换。
打平保留 incumbent。没有 incumbent 时也要通过同样的合法首层检查；空图或独立的无关 ready 原子不是完整目标计划。
ε 的单位是效用金，固定值与比较差额写入收据，调参须与搜索结构改动分开说明。

“无计划”与“有计划但已硬失效”分开报告。pending、额度耗尽、游标尚未完成不等于不可行，也不等于放弃。
只有明确达成、失败或放弃并记录原因，才走目标生命周期的对应处理；净值判定先剔除沉没成本，不能把旧购买再算一次。

## 3. 分支定界的正确上界

粗估默认只是搜索优先级。只有能证明覆盖该分支全部合法精化结果的整计划效用上界 `U_upper`，才可剪枝：
`U_upper <= U_incumbent + ε` 时，该分支没有足够替换优势。
尚未证明上界时不剪；有安全但较松的上界时可以用松上界。

上界要同时覆盖成功概率、目标达成时刻、各成本的发生时刻和资源排程。
只断言“精确时长不短于粗估、名义成本不低于粗估”不够：一条并行支路把总完工固定在 t1000，另一条支路的 100 金损失按 finish 折现，
其 finish 从粗估 t1 变成精确 t500 时，目标收益时刻不变，而该成本现值降低，精确净值反而更高。

因此运行时比较的是同一分支、同一输入下 `U_exact <= U_upper`，保留上界来源、依赖及违例原值。
违例使该上界证明失效并停止据此剪枝，不能截断数值、换个名称或只写日志后继续剪。
这条断言只能检查实际精化过的分支，不能证明已经剪掉的支路没有好方案；安全性仍需来自上界推导及小规模完整枚举对照。
带未来预测的条件方案不冒称这里的 `U_exact`。接纳比较仍计算包含未来后缀的整计划预测价值，双方使用同一预测口径，
标明各段 basis 和剩余不确定性；不能只比较眼前动作成本，也不能把预测值当作可证明的上界。

## 4. authority 与一次性迁移

搜索的 incumbent/cursor 与已授权执行之间有稳定对应，但生命周期分开。
以下记录不以 incumbent 是否还存在为回收条件：

- 原始 accepted/issued 命令、generation、实际单位与 lease；
- 同一世界资产的 spendId、实际 native 付款、paidGold、原 building output binding；
- 运输的真实 loaded/landed IDs、营地清除、同地基完工的 world 收口；
- 正式 hold grant、原组、当前滚动保护检查和完整 through 义务。

更换计划不能重新付一笔已经核销的钱，不能把购建预算转给 wait-income 或 repair，也不能把物理靠近当作正式留守完成。
目标的预留和承诺继续由正常 authority 规则处理。搜索暂时没有新结果时，现有付款和世界收口仍运行。

旧 memory 由版本入口一次性迁移。明确把原声明、output、spend、命令和实际绑定对应到新选择器，不能靠字符串子串猜实体或只改一边的引用。
无需沿用的旧搜索 memo/cursor 可以丢弃后重搜；authority 和已验证的世界/付款记录不能一起丢弃。
若旧搜索数据要被读取，其解码只发生在迁移边界；正常路径不再写 DAG/deflate，也不靠压缩满足常驻门槛。
无法证明同义的旧报价转为需要重建，不能升级为 met，更不能让未来原型获得真实执行权。
跨 JSON、冷进程恢复、重复观察后仍须无二次付款、无重复出生或施工命令。

## 5. 删除清单与替代物

以下是搜索层的删除目标，不是本 PR 已完成的代码变化：

| 删除机制 | 替代方式 | 必须保留的边界 |
| --- | --- | --- |
| `GoalRefinementDenial` 及相关分支 | 发布缓存重建报价；DFS 游标前进到下一候选 | 不拿旧粗价直接替换已确认方案 |
| `preferredExactIndex`、`maxAlternativeQuotes`、报价专用 `capacities` | 每目标 incumbent，加一个正在推进的挑战方案 | 通用 bounded-cache、原生缓存限额不删不加大 |
| `quoteRevision` 内全局 `refinements.revision`、8-pass 重入 | 每目标依赖失效与一次确定性重放/比较 | 同一 think 的全部工作仍共用 6144 |
| `cacheSourceRevision` 全局发布指纹 | cursor 的事实与候选集合依赖版本 | 无关目标变化不重启本目标，新挑战者出现能重开搜索 |
| 常驻对手、完整 alternatives、`requotes` 多份图 | 当次诊断与唯一当前 cursor | 失败原因和原始证据可导出，诊断不反过来成为常驻根 |
| planner 的定义表、惰性 declaration reconstruction、通用 planning restore | 稳定小选择器、纯 regenerate、一次性格式迁移 | authority 的版本引用和原生发布缓存引用不能一并删除 |
| 正常搜索路径的 `cache-payload` DAG/deflate | 直接常驻小记录 | 不通过压缩、截断事实或提高上限过门槛 |

原生缓存的计算方式与额度保持。引用保留范围改由 incumbent、活跃 cursor 和仍在执行的真实动作给出，移除落选方案的根，
但不删正在等待发布的必要事实。只删 planner 对手表而不更新这些引用根，仍可能把废弃几何长期 pin 住。

## 6. 验收与实施顺序

三条功能门槛：

1. **决策收敛。** 原 13 输入保留，跨实际 owner/JSON 续行，在固定 K20 内比较选中步骤与 ready 的语义身份。
   无相关新事实发布时，尾窗 N 次必须相同；N 在运行前固定并写入收据。
   不再要求内部 refinement revision 的某个数值或 republish 次数为零。稳定空计划只说明没变化，不说明解题。
2. **解题。** 题 1 两变体和题 3 原冷帧在 K20 内得到因果完整、非空 ready 计划，原 checker 和实际分配证据保持。
   首次完整、首次 ready 分别出现在第几次 think，逐次记录为指标，不改成“第 1 次必须 ready”的代理断言。
   题 3 的冷入口若尚未导出正常 allocator/ledger 的实际分配，必须单列为观察投影合同缺口；补齐后按原 checker 重跑，
   不手填 allocation，也不用计划资本预估代替真实预留。
3. **真实对局。** control-on 对局逐席位报告每游戏分钟计划切换、无计划、硬失效、修复与首次出手延迟。
   切换按 provider、grounding、实际 bindings/依赖拓扑计数，滚动 tick 和编号更新不计。
   报切换原因及相关事实；没有行动却切换少，不算表现改善。阈值用冻结对照评审，不凭空规定一个次数。

原有安全与资源合同仍是硬门槛：6144、严格导航、原生 next-think 发布、逐前缀现金/单位/运力、实际 SDK 应用、原步骤归属、
唯一 native 付款 ACK/原 building binding、运输 world 收口、正式 hold 与完整 through。
8400 内的阶段 hold 不外推为 12015 等完整义务已完成。

常驻体积继续逐帧量实际 wire：planner、定义/迁移数据、authority，以及 planner 导致的 observation 增量都计入。
97f 两真实地图八席位的 24 个高目标数原帧，整席位上限仍为 128KiB；题目动态上限仍为 256KiB。
同帧 control-off 的共享 observation 单列，control-on 增加的部分计入 planner；若用 fresh-zero 全计入作保守界，必须明确标注，不能称为同帧增量。
同时报告峰值、余量和逐次四项曲线；曲线还在持续增长时，不能因某帧刚好没越线就判通过。
题 1 动态仍核 near t1500 前实际 board；far t1500 前正式调船、到同 pickup 距离下降、到港后 10 次 owner think 内实际 board。
另实测冷/热 provider 重建与每次 think 的 CPU 时间、重建次数、原生缓存命中/新增 work，随固定输入和源码保存。
命中查询的 work 为零不证明重建 CPU 为零；性能读数不以新的墙钟时点断言替代上述行为与额度合同。

实施按以下顺序，每一块单独提交和过闸，不把一份新框架叠进旧框架长期双跑：

1. 固定稳定选择器、incumbent/cursor 格式、纯重放接口和 authority 迁移；先锁 JSON、付款/绑定和未来引用边界。
2. 建立当前计划重建与从失效步骤修复，删除通用惰性声明恢复；验证 start/finish、排他释放、逐事件资源及持续动作。
3. 接续算挑战搜索和已证明的整计划上界，替换首完整路径即结束的行为；删除常驻对手/否决表。
4. 用每目标依赖与单次比较替代全局 revision、8-pass、`requotes`；更新原生缓存引用根，移除多余定义/压缩路径。
5. 固定搜索候选后，冷分配观察投影和 harbor 分开提交、各过适用门槛；接口缺证保持未通过，不伪造投影。
   由 26 用齐备的固定头按原 checker 复验题 1/3 冷 K20，再按指定范围核真实对局与执行。

文档先合，代码才推进。每个中间提交报告已删除与尚存的机制、通过的闸和仍失败的输入，不把阶段通过合成整体验收。
dee4 与 v9 的原输入、失败、局次和停止记录保留，不用新判法或新实现回写旧结果。
