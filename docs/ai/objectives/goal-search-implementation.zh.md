# 只读回归搜索实现边界

`planGoals(GoalPlannerInput)` 只产生声明式依赖图，不下原生命令、不分配单位、不预留金币。控制默认值不变。

搜索先从所求效果回归，向所有 provider 查询 achiever，并展开其前置。数量事实会收集所有正贡献者，包括不能单独填满缺口的赏金、收入和训练。随后在这些相关声明里搜索可行组合，用同一个资源投影器验证每个支出前缀。动作声明里没有前后顺序；依赖来自事实的生产者和互斥资源。

每个事实展开、组合可行性检查计一个逻辑工作单位，任务进入调用方提供的 `FactWorkQueue`；所有目标先注册，再按共享队列轮转。零额度不展开，序列化前沿在后续 think 继续。深度、展开数、保留方案数由输入限制；缓存总量限 256 KiB，超限明确标 `truncated`，丢掉缓存不会让缺失事实变成真。冷暖缓存不参与决策排序。

事实 revision/state 与声明版本不变时复用已完成的图；时间只重新定位计划的绝对时刻。未完成搜索保留前沿，事实翻转后重新回归。缓存记录选中和落选路径所读的事实，落选动作的完整声明保留在 alternatives。多笔数量贡献通过 `chosenActionIds` 保留，旧单值字段只供旧消费端兼容。

`readProjectedFact` 由共同世界事实源负责，用显式 output 引用、移动后的真实成员和原生整组评估检查未来事实。规划器不把 camp-force 线性相加，也不把 pool/post 当两份兵；没有这些共同物理事实时，不能把纯算法契约测试说成海军或陆地验收。

当前通用契约测试覆盖：无序动作的依赖回归，两笔部分赏金共同填缺口，先花后挣且不透支，费用替代比较，零预算及 JSON 前沿续行，revision 缓存失效、pending 保留、future output 绑定。它们没有替代公开题的真实 source/完整动作 grounding、命令适配器或执行检查。
