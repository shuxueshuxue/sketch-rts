# 陆地目标的只读报价

本轮对应战略层设计的第 1 步。`generateLandObjectives`、`decomposeLandObjective`、`landIdleForces` 只消费统一的 `Situation` 和借用的世界/任务上下文，输出候选、效用、前置条件及替代子图；不发命令、不写任务、claim 或预算。当前执行器的先后顺序不变，v8/v9 对手不接入这些报价。

## 金额、条件与方法

全局参数来自 `strategy/utility.ts`：评价窗 120 秒，据点默认威胁窗 45 秒，1 点 field-strength 对应 100 金；成本为兵力强度乘占用时间。效用统一为 `p × 收益 − 已承诺成本 + 坚持加分`。成功后才付的矿厅费用作为负收益；已经奠基的矿厅不重复收费。概率使用 `a²/(a²+r²)`，拒绝非有限输入；未知的应援路线保留 unknown，不把缺记录当作零。共享 evaluator 明确证明超出整个评价窗的物理下界，可从当前响应窗排除。

| 目标 | 收益 | 必须单列的前置/效果 |
| --- | --- | --- |
| ExpandLand / RecoverSite | 折现后的矿收入，扣尚未支付的矿厅费用 | 清营力量、实际可达工人、400 金与驻防交接；同矿共用 mining-established 效果，失地必须有 previous Situation 的实体消失证据 |
| AttackSite | 当前目标资产、断矿收入、迫使应援军回防的压制价值，以及在建/主力外出的时机价值 | 实际目标被摧毁才达成效果；施工窗口要用实际工人数与剩余工时核对，不能把选中过 attack 算完成 |
| ContestRoute | evaluator 给出的真实前压点及其压制报价 | ETA 键是 opportunity.id，不能拿敌厅中心冒充路口；占用整个评价窗，不把驻守算成一 tick |
| CounterHarass | 受威胁厅、工人与采矿收入的风险价值 | 生成于真实 SiteThreat 中的骑射手或正在攻击工人的陆兵；有追上/射程压制与两轮有效伤害的能力要求；和 DefendSite 共用 site-safe 效果 |

报价只挑够用的候选队伍，每类最多四个目标，稳定排序并保留正在执行的身份。旧任务的兵、甲板成员和有条件的跨海路线不是空闲兵。目标的 sinceTick 与最短驻留沿实际任务承诺起点，不从首次观测再续一段驻留；同一效果重启任务时更新承诺起点。借调需要交接；有上一帧目标报价时，按被借战力份额列出原目标的机会损失；原报价未知时明确写明未知，不能视为已获授权。治疗、撤退等局部控制保留原任务身份，同时不兑现为可用战力。

应援军用统一 ETA 在“我方抵达 + 预计交战时间”内的可达成员计数，最多覆盖 120 秒；不以据点默认的 45 秒截掉远征途中可能赶到的敌人。营地沿用 `creepForce/forceFor` 的量纲。召唤物按抵达后的剩余寿命占预计工作时间的份额折算一次；常驻施法者的 ranged 注解不等于前排，现有召唤物也不能独立兑现后续护送/留守。对营地使用战斗评分加权的寿命系数，未虚构施法者在场后的重召。

缺兵保留“借兵”或“训练”两种替代方法，不把两者同时当必做项；缺工人、钱、运力分别保留 deliver-workers、wait-income、obtain-transport。子图中的建厅依赖清营/清除占矿敌厅及工人和预算，驻防交接依赖实际矿厅。运输、训练的预算/队列落实属于后续统一分配和预算迁移，本轮的 demand 是报价，不是预留。

闲置另列 `idleForces`，不伪造 HoldReserve 目标。每兵只记一次：既有驻守、在途、医疗承诺的单位不算可调空闲；有真实可达的正效用备选时，闲置效用为放弃它的负收益；没有这样的备选，保留原因和 null，不虚造机会成本。collector 对全部 family 的报价统一去重和排序，陆地函数不自行抢占。

## L1–L6 的真实帧

原始世界来自 [陆地契约证据包](land-contract.evidence.json)，均为执行 owner think **之前**的完整快照。测试夹具同时保存来源 SHA256、evaluator 提交和统一 Situation；没有在测试里另写 ETA 或威胁算法。原始模拟版本是 883f57c5，Situation 首版 1020b5f7 加 6ef40ec7、89cf51c3。

| 事件 / tick | 核验结果 |
| --- | --- |
| L1 / 7560 | ravager 1039/1044/1058 的 DefendSite 承诺保留，不进入闲置池；其他目标借兵必须列出交接 |
| L2 / 9015 | archer 1334/1515/1537 同时保留 attack 与 expansion 来源；hold 订单不抹掉原进攻身份，报价将借调交接单列，尚未改变旧执行器的磨损撤回判定 |
| L3 / 14025 | chieftain 3872 保留远方驻守，同时记录 mobileCare.claimsUnits；不兑现为清营/进攻可用兵 |
| L4 / 16875 | contractArcher 1923 保留 mineGuard、当前 mobileCare 选择和 follow 医疗订单证据；不当作闲置 |
| L5 / 16980、17985 | 在途/已登陆 caster 仍归 ConquerIsland；不重复生成同矿陆地扩张，也不把 caster 算成清营前排 |
| L6 / 8265 | spirit 1903/1953 在到达前过期，其他 spirit 的寿命折算后仍不能单独满足常驻前排前置；生成借兵/训练子目标，保留资金和驻防缺口 |

L3 的执行器归因取自原始逐 think 记录：14010 和 14025 是 **mobileCare** 的 accepted move，14040 才是 expansionGarrison 的返回命令。它不是 postRecoveryAssignments 当前选中的患者；不能仅凭血线或避战 move 猜执行器。

## 验证与边界

七帧的完整输入 JSON 在观察前后相同；重复观察结果相同。每帧在旧 planner 前加上陆地观察，输出命令、完整任务 memory 与世界快照的 SHA256 均和未观察版本相同。

初版完整 src：7794/7795 通过，唯一失败在 A100 的 think-worker 子线程解析 `./host`，是已知 Node/tsx 环境问题；这四项在 juma 单独全部通过（6.16 秒，测试本体 1.33 秒）。后续新增的场景/模型测试另行通过，具体数量及最终检查见 PR 验收记录。

性能使用同机 ABBA，分别记录四军场景和后期海图的每次 think。为单独量陆地模块，两组先在计时区外取得同一份 Situation，再比较旧 planner 与“陆地报价/分解/闲置 + 旧 planner”；这项数据不代表 evaluator 免费，框架的总耗时由共享局势 PR 另列。原始逐 think 数据和命令哈希放 A100 证据包。

本轮报价中的交战时长、风险、压制价值都是注明来源的估计，不是模拟反事实。当前共享输入仅提供已有前压点；没有真实几何的新增路口不拿敌厅位置代替。缺生产/运输前置的 blocked 目标可以保留价值和需求，但不会假造未来兵的 ETA、成功承诺或执行成功。终态、分配、抢占和预算承诺仍由后续阶段建立。
