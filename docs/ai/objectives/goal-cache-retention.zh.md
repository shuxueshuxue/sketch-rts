# 规划缓存的保留集与席位常驻量

每个目标保留选中计划、每个比较点最好的一个已精确报价对手，以及继续确定性搜索的游标。其他候选重新生成。事实、动作选择和声明配方通过随 memory 保存的递增版本号引用；没有截断哈希，也不对新搜索缓存做压缩。

只有 ready、已授权或正在执行的动作需要完整声明。其余动作保存 provider、grounding key、依赖事实版本和报价数值。重建必须重新经过同一个 provider、绑定和安全时窗，并核对依赖及报价。过期声明保留单位、船与落点的选择身份，但没有执行所需的报价、资源需求或输出。

精确报价输掉比较后，保留否决记录及依赖版本。依赖不变时按原精确值比较；依赖变化才允许重新挑战。粗估挑战者仍须先精化，不能直接换掉精确在选方案；近似平价时保留现方案。定义表按实际常驻根回收，版本计数不回退。搜索的原 256KiB 额度包含其全部可达定义，不能通过把正文移到表外规避额度。

缓存中没有可直接沿用的世界观察。读取选中记录必须提供当前事实 reader，图边和资源事件由声明、日程和开账余额重建。公开 trace 是独立的完整值；已丢弃的 trace 候选不再成为席位定义表的常驻根。
