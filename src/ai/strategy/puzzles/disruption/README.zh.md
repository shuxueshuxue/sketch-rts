# 原生干扰候选场景

这里只运行未改动的 main 行为基线，不把物理结果当成正式规划器验收。所有敌人保持在原快照中；当前原生环境没有战争迷雾。

## 题9：快骑游击（#590）

两名原生 raider（速度82）反复袭击去远矿的工人。我方初始只有四名 footman（62），现成兵营还可训练 lancer（68）。AI没有禁用任何生产、研究或其他选择；整局记录真实兵种、速度和完成的生产建筑，若出现更快的可用兵就单独报告条件变化。

开跑前固定的敌方规则：

- 首次有活工人进入唯一路段中段带时，只以该工人为 attack 目标。
- 每个原生 tick 观察我方武装单位；任一武装单位进入骑兵的原生正常警戒范围，就立即提交 move，撤回同一固定撤退点。警戒复用 unitAutoAcquireRadius 的 idle 范围、strikeReach 和原生可达条件；这里是普通玩家单位230，不是中立营地150或650。
- 工人被原生击杀后也撤退。两名存活骑兵都到撤退点、且警戒解除后，只接受另一个工人在此之后新从本土跨入路段的事件，再返场。已经在途的工人不能重触发。
- 至少三次循环，除非我方先以真实战斗清除袭击者。控制器不补工人、不重生敌人、不移动或删除实体。

敌方每 tick 观察，我方仍每15 tick正常思考；两边命令都经过原SDK三 tick延迟。脚本不主动攻击武装单位；原生自动反击、碰撞、远程弹丸和堵路均保留，因此我方若仍能清掉骑兵，应照实记为清除。

撤退点、路线、两骑兵的属性和数量与初次快骑诊断相同，不根据 main 结果调参。验收要求是工人总死亡最多一人、下一工人出发前有正面保护、并在480秒内建成目标厅。速度快不能直接证明不可被拦截或击杀。旧 stay、hit-run、小袭 main 成功结果保持回归题，旧原片与新变体分别封存。
